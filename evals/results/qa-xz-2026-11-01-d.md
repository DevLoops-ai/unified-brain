## The change

Three edits in `codebase_qa_service.py`, all in the chain judgement
(`_jev_expand` / `_judge`, `_jev_verdict_names`):

1. **Verdict question asked clean.** The chain instruction is back to
   "Does this `code` help answer the `question`?". The derived-copy
   sentence of change 3 is removed from it.
2. **Derived copies as their own question.** The same Jev call now
   carries a third question, `derived` (yes/no), next to the verdict and
   the names: "Is this `code` a derived copy of text that exists
   elsewhere in the repository in its original form — a translation or
   localisation catalog, a mirrored or generated file — AND the
   `question` is not about that copy itself (its translations, how it is
   generated, what differs in it)? Answer no when the `question` asks
   about such copies." A body with `derived` above 0.5 is a sure reject
   whatever the verdict said. Same call, same cost; the verdict wording
   no longer carries the rule, and a question *about* translations keeps
   its `.po` bodies. The conditional clause was added during the
   session; Q4 ran about a minute after it was proposed and the log does
   not record which wording it had — on nine questions none of which is
   about translations the clause cannot have changed a value. The
   seed-scoring and hit-triage sentences from change 3 are unchanged
   (they still have no such clause; see notes).
3. **Names pool: the name a body was reached through is no longer
   offered.** In wide mode every place of that name is already in
   `seen`, so following it again finds nothing; but Jev gave it 0.73 on
   `license-check.sh` (first run of the session) and `_picked` drops
   names under half the top share, so a dead option was crowding out
   real ones. Wide mode only; in the fast probe's narrow mode re-following
   a name takes the next unclaimed place and is left as it was.
4. **`reached_because` carries the link line.** The matching line of the
   body with one line around it (`_link(c)`, already computed for the
   chain string) is now also in the state Jev judges with: "it mentions
   `xzgrep_expected_output` …; line: `^tests/xzgrep_expected_output$ |
   ^tests/files/[^/]+\.(lz|lzma|xz)$'`". Unmeasured on its own: it was
   applied in the first run of the session together with (3), and the
   verdict on `license-check.sh` did not move (0.76 before, 0.76 after).
   See notes.

The log line gained `derived=` after the verdict probabilities.
