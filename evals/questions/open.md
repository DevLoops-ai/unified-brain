## Q6 — Subscriptions, cross-file (PublishRequests, lifetime, Republish) — 8 points

> How does the server handle PublishRequests: where are they queued per session, how does a subscription pick one up to send a notification, what do keepAliveCount and lifetimeCount control, what happens when a subscription runs out of publish requests or its lifetime expires, how are sent notifications kept for Republish, and when does the server return BADTOOMANYPUBLISHREQUESTS?

Reference points (`src/server/ua_services_subscription.c`, `src/server/ua_subscription.c`, `src/server/ua_session.c/.h`):

- **Queue** (1): the per-session queue holds *responses*, not requests — `UA_PublishResponseEntry` (`responseToken`, `maxTime` from the TimeoutHint, `response`) in `session->responseQueue` / `responseQueueSize`; `UA_Session_queuePublishReq()` (tail, or head when putting one back) and `UA_Session_dequeuePublishReq()` (oldest first).
- **Service_Publish** (2): empty `session->subscriptions` → `BADNOSUBSCRIPTION`; `UA_Session_ensurePublishQueueSpace()` (in `ua_subscription.c`, not `ua_session.c`): while `responseQueueSize >= config.maxPublishReqPerSession` (default 512; 0 = no limit) the **oldest** queued entries are answered with `BADTOOMANYPUBLISHREQUESTS` and the new request is still queued; acknowledgements: unknown subscription → `BADSUBSCRIPTIONIDINVALID`, otherwise `UA_Subscription_removeRetransmissionMessage()` → `BADSEQUENCENUMBERUNKNOWN` if not in the queue (per-ack results, not the service result); then every subscription with `late == true` is served immediately via `UA_Subscription_publish()` (round-robin within priority); returns `false` = answered later.
- **UA_Subscription_publish** (2): runs from `sampleAndPublishCallback` (publish timer) and from Service_Publish; dequeues entries, answering expired ones (`maxTime < now`) with `BADTIMEOUT`; found a request → `Subscription_resetLifetime()` (`currentLifetimeCount = 0`); none → `++currentLifetimeCount`, and when `> lifeTimeCount` logs "End of subscription lifetime" and sets `statusChange = BADTIMEOUT` → `sendStatusChangeDelete()` deletes the subscription (a StatusChangeNotification only goes out if a request happens to be queued); keepalive: with no notifications `++currentKeepAliveCount`, request put back until `>= maxKeepAliveCount`, then an empty response; sequence number advances only when notifications were sent (keepalives reuse it, 0 is skipped); `late` is a boolean on the subscription, not a state.
- **Revised counts** (1): `maxKeepAliveCount` bounded by `config.keepAliveCountLimits`, `lifeTimeCount` by `config.lifeTimeCountLimits` and then forced to at least `3 * maxKeepAliveCount`. `publishingEnabled=false` maps to `UA_SUBSCRIPTIONSTATE_ENABLED_NOPUBLISH` — keepalives still go out and the lifetime still counts.
- **Retransmission** (1.5): `UA_NotificationMessageEntry` in `sub->retransmissionQueue`, added only when `config.enableRetransmissionQueue` and notifications > 0 (keepalives never stored), before sending so the new number is in `availableSequenceNumbers`; two limits — hard-coded `UA_MAX_RETRANSMISSIONQUEUESIZE` 256 per subscription and `config.maxRetransmissionQueueSize` per session (`session->totalRetransmissionQueueSize`, 0 = unlimited); `discardedMessageCount++` under diagnostics. `Service_Republish`: unknown sub → `BADSUBSCRIPTIONIDINVALID`; resets the lifetime; not found → `BADMESSAGENOTAVAILABLE`; otherwise copies the message and leaves it in the queue.
- **Bonus / deep** (0.5): `removeOldestRetransmissionMessageFromSub()` takes `TAILQ_LAST` of a queue filled with `TAILQ_INSERT_TAIL` — it drops the **newest** message, not the oldest, despite its name.

Traps: the BADTOOMANYPUBLISHREQUESTS code lives in `ua_subscription.c` under a `UA_Session_` name; config fields are in `include/open62541/server.h`, defaults in `plugins/ua_config_default.c`; `ua_server_async.c` has no publish code; there is no LATE/KEEPALIVE state; the field is spelled `lifeTimeCount` but the counter `currentLifetimeCount`.

## Q7 — MonitoredItems, data-change pipeline — 8 points

> For a data-change MonitoredItem, how does the server sample a value, decide whether it counts as a change (including the deadband filter and the trigger setting), put the notification in the item's queue, and what exactly happens when that queue is full — which notification is discarded, how the client is told about the overflow, and how does this differ for an item with queue size 1?

Reference points (`src/server/ua_subscription_datachange.c`, `src/server/ua_subscription.c`, `src/server/ua_services_monitoreditem.c`):

- **Sampling** (1.5): `UA_MonitoredItem_sample()` reads with `read_async()` (`ua_server_async.c`), at most `UA_MONITOREDITEM_ASYNC_MAX` (8) reads in flight else `BADTOOMANYOPERATIONS`; completion → `processMonitoredItemAsyncRead()` → `UA_MonitoredItem_processSampledValue()`. `UA_MonitoredItem_registerSampling()` picks one of: `CYCLIC` (`addRepeatedCallback(UA_MonitoredItem_lockAndSample)`, `UA_TIMERPOLICY_CURRENTTIME`), `PUBLISH` (interval == publishingInterval → sampled inside `sampleAndPublishCallback`, no own timer), `EVENT` (interval 0 on a non-external value source → sampled on write by `triggerImmediateDataChange()` in `ua_services_attribute.c`, synchronous `Operation_ReadWithNode`). External/callback sources with interval 0 get the interval clamped to `samplingIntervalLimits`.
- **Change detection** (2): `detectValueChange()` against `mon->lastValue` — status change always counts; trigger default `STATUSVALUE` (from the `UA_DataChangeFilter` if set); `STATUS` → no further check; `hasValue` differs → change; absolute deadband on a numeric type → `detectVariantDeadband()` result returned **directly** (so with `STATUSVALUETIMESTAMP` + deadband the timestamp is never compared); `STATUSVALUETIMESTAMP` compares only the **source** timestamp; else `UA_equal` on the Variant. `detectScalarDeadBand()`: the 10 integer/float types, strictly `diff > deadband`; arrays — any one element over the deadband counts, length/type change always counts. **Percent deadband is never evaluated at sample time**: `setAbsoluteFromPercentageDeadband()` reads `EURange` at create/modify, computes `(pct/100)*(high-low)` and rewrites the filter to `ABSOLUTE` (not recomputed if EURange changes). `lastValue` is the last value that **produced a notification**, not the last sample; initialised to status `~0` so the first sample passes.
- **Enqueue** (1): `UA_MonitoredItem_createDataChangeNotification()` → `UA_Notification_new()` → `UA_Notification_enqueueAndTrigger()`: subscription queue first (`UA_Notification_enqueueSub`, if REPORTING or triggered SAMPLING), then `UA_Notification_enqueueMon()` → `TAILQ_INSERT_TAIL`, `++mon->queueSize`, then `UA_MonitoredItem_ensureQueueSpace()`. Max is `mon->parameters.queueSize`; current count is `mon->queueSize` (two fields called queueSize); `parameters.discardOldest` comes from the request unchanged.
- **Overflow** (2.5): `UA_MonitoredItem_ensureQueueSpace()`: `discardOldest` → remove `TAILQ_FIRST`; otherwise remove the **second newest** (`TAILQ_PREV(TAILQ_LAST)`) so the newest sample is always kept; the next notification takes the removed one's place in `sub->notificationQueue` (no starvation); SemanticsChanged bit is moved to the next; `monitoringQueueOverflowCount++` under diagnostics. Client is told via `setOverflowInfoBits()` — only if a removed notification was reported — setting `status |= UA_STATUSCODE_INFOTYPE_DATAVALUE | UA_STATUSCODE_INFOBITS_OVERFLOW` on `TAILQ_FIRST` (oldest remaining) for discardOldest, on `TAILQ_LAST` (the new one) otherwise.
- **Queue size 1** (1): both modes remove the old one and keep the new; `setOverflowInfoBits()` returns immediately for `queueSize == 1` — **no overflow bit**; when Modify shrinks the queue to 1, `UA_MonitoredItem_removeOverflowInfoBits()` clears the bit on the remaining notification. Clamping in `checkAdjustMonitoredItemParams()`: 0 → 1, else `config.queueSizeLimits` (default 1–100); `maxNotificationsPerPublish` is not involved.

Traps: no `sampleCallback`/`maxQueueSize` (a stale comment still mentions `mon->maxQueueSize`); the interval-0 path is in `ua_services_attribute.c`; `EVENT` sampling type also covers data-change items; sampling uses `read_async`, not `readWithSession`.

## Q8 — AddNodes instantiation — 10 points

> When an AddNodes request creates an Object or Variable node from a type, trace what the server does after the node is inserted into the nodestore: how it checks the type definition and the reference to the parent, how it copies the mandatory children of the type (and of the type's supertypes) onto the new instance, how it decides which children to copy and which to skip, how variable types constrain the instance's value and data type, in which order constructors run, and what is rolled back when a step fails.

Reference points (`src/server/ua_services_nodemanagement.c` unless noted):

- **Phases** (1.5): `Service_AddNodes` (`maxNodesPerNodeManagement` → `BADTOOMANYOPERATIONS`) → `Operation_addNode` (begin/endModelChange) → `Operation_addNode_inner` → `Operation_addNode_begin` (`checkSetBrowseName`, `addNode_raw`: access control, namespace check, `UA_NODESTORE_NEW/INSERT`; then `addNode_prepare` = `addNode_addRefs` + `callEarlyConstructors`) → `addNode_finish`. Lowercase names; no `AddNode_raw`.
- **Parent and type checks** (2): `checkParentReference()`: parent not found → `BADPARENTNODEIDINVALID`; reference type missing/not a ReferenceType → `BADREFERENCETYPEIDINVALID`; abstract reference → `BADREFERENCENOTALLOWED`; type nodes need HasSubtype to a same-class parent; instances need a hierarchical reference (`isNodeInTree_singleRef`) else `BADREFERENCETYPEIDINVALID` (not BADREFERENCENOTALLOWED); unattached Method governed by `config.allowUnattachedMethods`. `addNode_addRefs()`: null type → `baseDataVariableType`/`baseObjectType`; type not found or wrong NodeClass → `BADTYPEDEFINITIONINVALID`; abstract VariableType/ObjectType allowed only if the parent is under BaseDataVariableType/BaseObjectType (`isNodeInTree`); then adds the inverse parent reference and forward HasTypeDefinition.
- **Variable type constraints** (2): in `addNode_finish` — `useVariableTypeAttributes()`: no value → copy the VariableType's value (if `compatibleVariableTypeValue`), *before* copying DataType (setting DataType triggers a type check) and ArrayDimensions; a failed value write is only logged. Then `typeCheckVariableNode()`: `compatibleDataTypes`, `compatibleValueRankArrayDimensions`, `compatibleValueRanks`, `compatibleArrayDimensions` (all in `ua_services_attribute.c`) → `BADTYPEMISMATCH`; incompatible internal value re-written through `writeAttribute` so the write path can adjust it; empty value with a concrete DataType governed by `config.allowEmptyVariables` (ABORT → `BADTYPEMISMATCH`, DEFAULT → `setDefaultValue()`); external source failing `compatibleValue` → `BADINTERNALERROR`.
- **Children** (2.5): `addTypeChildren()` → `getTypeAndInterfaceHierarchy()` (`ua_server_utils.c`: leaf, then supertypes via inverse HasSubtype, then HasInterface — most-derived first, so a supertype's same-named child is then "existing") → `copyAllChildren()` (Browse Aggregates) → `copyChild()`: `findChildByBrowsename()` — existing child kept, its missing members deep-copied; `isMandatoryChild()` looks only for HasModellingRule → Mandatory; everything else (Optional, placeholders, no rule) is created only if `config.nodeLifecycle->createOptionalChild` says so; Methods are not copied unless `config.copyMethodsOnInstances` — a reference to the type's Method is added instead; `copyChildNode()`: `UA_Node_copy`, context/constructed reset, value source forced INTERNAL, references stripped except HasInterface/Method HasProperty/(conditionally) HasModellingRule, then `addNode_addRefs` → `callEarlyConstructors` → `copyAllChildren(declaration→child)` → `addNode_finish(child)`; depth guard `UA_MAX_NODE_INSTANTIATION_DEPTH` 64 → `BADTYPEDEFINITIONINVALID`. Objects also get `addInterfaceChildren()` (HasInterface reference added).
- **Constructors** (1): early phase in `callEarlyConstructors()` (global `earlyConstructor`, then the type's); main phase `recursiveCallConstructors()` only if `!head.constructed`: **children first**, then global `config.nodeLifecycle->constructor`, then the type's `lifecycle->constructor`, then `setConstructedNodeContext` sets `head.constructed = true`.
- **Rollback** (1): before insert `UA_NODESTORE_DELETE`; after insert `addNode_prepare`, `addNode_finish` and `copyChildNode` all call `deleteNode(server, id, true)` with model-change events suppressed → `buildDeleteNodeSet`/`autoDeleteChildren` removes already-added children (kept only if they have another hierarchical parent outside the set); `deconstructNodeSet()` runs type then global destructors for every node in the set **without checking `head.constructed`**; a failed type constructor already ran the global destructor, so destructors can run twice.

Traps: `isNodeInTree` lives in `ua_services_view.c`, not `ua_server_utils.c` (depth limit `UA_MAX_TREE_RECURSE` 50, returns "not in tree" silently); the public comment on `UA_Server_addNode_begin` in `server.h` says `_begin` does the type checking — the code does it in `addNode_finish`; `reftypes_skipped` in `copyChildNode` is actually the set of references *kept*; `ua_server_modelchange.c` holds only the events.
