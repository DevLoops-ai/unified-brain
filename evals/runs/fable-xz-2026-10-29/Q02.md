## Summary

Sandboxing in xz is **a command-line-tool feature only** (`xz`, `xzdec`, `lzmadec`). liblzma contains no sandboxing code: a recursive grep for `sandbox|pledge|capsicum|landlock` in `src/liblzma` returns nothing. Three OS mechanisms are supported, selected at build time, mutually exclusive:

| Mechanism | Platform | Build macro | Runtime API |
|---|---|---|---|
| Capsicum | FreeBSD (>= 10.2 per comments) | `HAVE_CAP_RIGHTS_LIMIT` | `cap_enter()`, `cap_rights_limit()` |
| pledge(2) | OpenBSD (>= 5.9 per comments) | `HAVE_PLEDGE` | `pledge()` |
| Landlock | Linux (>= 5.13 per CMake comment) | `HAVE_LINUX_LANDLOCK` | `landlock_create_ruleset`/`landlock_restrict_self` via `syscall()`, plus `prctl(PR_SET_NO_NEW_PRIVS)` |

Version numbers come from comments in `src/xzdec/xzdec.c` (`sandbox_enter`), `src/xz/sandbox.c` (`sandbox_enable_strict_if_allowed`, Capsicum branch), and `CMakeLists.txt` lines 1745-1747. Windows, macOS, etc. have no sandbox: on those builds `ENABLE_SANDBOX` is undefined and `sandbox.c` compiles to a dummy typedef (`src/xz/sandbox.c` line 15-18).

## Build-time selection

**Autotools** (`configure.ac`, "Sandboxing" section, lines 547-573 and 1149-1216): `--enable-sandbox=auto|no|capsicum|pledge|landlock`, default `auto`. Detection order is Capsicum (`AC_CHECK_FUNCS([cap_rights_limit])`), then pledge (`AC_CHECK_FUNCS([pledge])`), then Landlock via an `AC_LINK_IFELSE` test that compiles a program referencing `SYS_landlock_create_ruleset`, `SYS_landlock_restrict_self`, `LANDLOCK_CREATE_RULESET_VERSION` and `prctl(PR_SET_NO_NEW_PRIVS,...)` (a link test is used because some systems ship `linux/landlock.h` without the syscall numbers). Landlock sets `AC_DEFINE([HAVE_LINUX_LANDLOCK])`; the other two get `HAVE_*` from `AC_CHECK_FUNCS`. If Landlock is found and `CFLAGS` contains `-fsanitize=`, configure errors out (lines 1194-1196). Sandboxing is forced off when both `--disable-xz` and `--disable-xzdec` are given (line 559-562). An explicitly requested method that isn't found is a hard error (line 1214). Macros reach the code through `config.h`, included from `src/common/sysdefs.h` line 23.

**CMake** (`CMakeLists.txt` lines 1740-1841): `XZ_SANDBOX` cache variable with the same five values; same detection order (`check_symbol_exists(cap_rights_limit sys/capsicum.h ...)`, `check_symbol_exists(pledge unistd.h ...)`, `check_c_source_compiles` for Landlock). The chosen macro is stored in `SANDBOX_COMPILE_DEFINITION` and applied to both the `xz` target (line 2048-2050) and the `xzdec`/`lzmadec` targets (line 1890-1893). Same `-fsanitize` fatal error for Landlock (lines 1828-1834).

CI disables it for the sanitizer and valgrind jobs (`.github/workflows/ci.yml` lines 80-99, via `build-aux/ci_build.bash -d sandbox`, which passes `--enable-sandbox=no`, `ci_build.bash` line 210).

## xz: three-stage enforcement

Interface: `src/xz/sandbox.h`. It defines `ENABLE_SANDBOX` when any of the three `HAVE_*` macros is set (lines 12-15) and declares four functions. Implementation: `src/xz/sandbox.c`.

**Stage 1 - `sandbox_init()`**, called from `main()` in `src/xz/main.c` line 169, right after `tuklib_progname_init()` and `io_init()` and *before* `tuklib_gettext_init()` (so a failure message here is untranslated; the comment at main.c 165-168 notes this).
- pledge: `pledge("stdio rpath wpath cpath fattr", "")` (sandbox.c 74).
- Landlock: `prctl(PR_SET_NO_NEW_PRIVS, 1, ...)` with return value ignored for old kernels (214), probe kernel ABI with `landlock_create_ruleset(NULL, 0, LANDLOCK_CREATE_RULESET_VERSION)` and clamp to `LANDLOCK_ABI_MAX` (3 or 4 depending on whether the header defines `LANDLOCK_ACCESS_NET_BIND_TCP`, lines 129-133), then `enable_landlock(required_rights)` keeping only `WRITE_FILE | READ_FILE | READ_DIR | REMOVE_FILE | MAKE_REG` (234-241). `READ_DIR` is kept only so that a directory argument gives "Is a directory" rather than "Permission denied" (comment 228-233). Truncate isn't needed because files are created `O_EXCL` without `O_TRUNC` (comment 224-226).
- Capsicum: no-op (289).

**Stage 2 - `sandbox_enable_read_only()`**, called from `main()` (main.c 252) only if `to_stdout_only` is true, i.e. `--stdout`/`--test`/`--list` was used, or `--files`/`--files0` wasn't used and every filename argument is `"-"` (main.c 235-249).
- pledge: `pledge("stdio rpath", "")` (89).
- Landlock: `enable_landlock(READ_FILE | READ_DIR)` (251-254).
- Capsicum: no-op (297).

**Stage 3 - strict sandbox.** `sandbox_allow_strict()` (sandbox.c 28-33) just sets `strict_sandbox_allowed = true`; `main()` calls it when `to_stdout_only && args.files_name == NULL && args.arg_count == 1` (main.c 258-259), i.e. exactly one input going to stdout. Then `io_open_src()` in `src/xz/file_io.c` (lines 723-727) calls `sandbox_enable_strict_if_allowed(pair.src_fd, user_abort_pipe[0], user_abort_pipe[1])` after the source file is successfully opened. That function first calls `prepare_for_strict_sandbox()` (sandbox.c 40-57), which returns false if not allowed, and otherwise pre-loads things that would otherwise require opening files later: `snprintf(NULL, 0, "%s%s", _(dummy_str), strerror(EINVAL))` to pull in gettext/libc locale files and `tuklib_mbstr_width()` to pull in iconv data. Then:
- pledge: `pledge("stdio", "")` (105).
- Landlock: `enable_landlock(0)` - every FS right the ABI knows is restricted, plus `LANDLOCK_ACCESS_NET_BIND_TCP | CONNECT_TCP` when ABI >= 4 (172-176, 272). No `landlock_add_rule` is ever called; the ruleset is applied with an empty allow list (comment 184-186, call 196).
- Capsicum (the only place Capsicum does anything in xz): `cap_enter()`, then `cap_rights_limit()` on `src_fd` (`CAP_EVENT|FCNTL|LOOKUP|READ|SEEK`), stdin cleared to no rights if it isn't the source, stdout (`CAP_EVENT|FCNTL|FSTAT|LOOKUP|WRITE|SEEK`), stderr (`CAP_WRITE`), the user-abort pipe read end (`CAP_EVENT`) and write end (`CAP_WRITE`) (312-339). If any call fails with `ENOSYS` (kernel without capability mode, or emulator) xz silently continues unsandboxed (349-350); any other failure is `message_fatal(_("Failed to enable the sandbox"))`.

Failure policy: in every branch except Capsicum-ENOSYS, a failing sandbox call is fatal (`message_fatal`), not a silent downgrade. Landlock on a kernel without Landlock is the one "soft" case: `landlock_abi <= 0` makes `enable_landlock()` return early (149-150) because the ABI probe returned an error.

The Landlock `handled_access_fs` mask is built as `~required_rights & ((1ULL << (12 + my_min(3, landlock_abi))) - 1)`, relying on the fixed bit layout (bit 0 EXECUTE through bit 12 MAKE_SYM in v1, bit 13 REFER in v2, bit 14 TRUNCATE in v3) so no per-flag `#ifdef`s are needed (comment 152-168).

## xzdec / lzmadec

`src/xzdec/xzdec.c` (shared by `lzmadec`, `src/xzdec/Makefile.am` line 34-35) has its own standalone copy, not using `sandbox.c`. It defines `ENABLE_SANDBOX` itself (lines 38-41).
- `main()`: on pledge, immediately `pledge("stdio rpath", "")` (401); on Landlock, `prctl(PR_SET_NO_NEW_PRIVS, 1, ...)` (416). Nothing early for Capsicum.
- `sandbox_enter(int src_fd)` (303-387) is called with `STDIN_FILENO` when no filenames are given (439), or with `fileno(src_file)` **only for the last filename** (`optind == argc - 1`, line 467-468), because after it the process can't open more files. Capsicum: `cap_enter()`, `src_fd` -> `CAP_READ`, stdin cleared if not the source, stdout/stderr -> `CAP_WRITE`. pledge: `pledge("stdio", "")`. Landlock: same ABI probe/clamp and full-mask ruleset as xz's `enable_landlock(0)`, skipped if the probe returns <= 0. Errors: Capsicum ENOSYS is tolerated (381-382); everything else prints "Failed to enable the sandbox" and `exit(EXIT_FAILURE)`. There is no `prepare_for_strict_sandbox()` equivalent here (xzdec doesn't use gettext).

## Documented behaviour
