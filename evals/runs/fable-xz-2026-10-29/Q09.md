# Multi-Stream .xz decoding in the threaded decoder: from last Block to next Stream

All citations are to the checkout at commit 45d08abc. Line numbers are from this checkout.

## 0. What the xz CLI actually sets up

`coder_init()` in `src/xz/coder.c` (lines 866–965): for `.xz` input with `MYTHREAD_ENABLED`, it always uses `lzma_stream_decoder_mt()`, with

- `flags |= LZMA_CONCATENATED` unless `--single-stream` (`opt_single_stream`, lines 876–879); with `--single-stream`, `allow_trailing_input = true` instead.
- `flags |= LZMA_TELL_UNSUPPORTED_CHECK` (or `LZMA_IGNORE_CHECK` with `--ignore-check`). `LZMA_FAIL_FAST` is **not** set by xz.
- `memlimit_stop = hardware_memlimit_get(MODE_DECOMPRESS)` (hard limit; `UINT64_MAX` if user set none — `hardware.c:174–186`).
- `memlimit_threading = threads == 1 ? 0 : hardware_memlimit_mtdec_get()` (soft limit; default `total_ram/4`, `hardware.c:322`, capped by the hard limit at `hardware.c:215` and again in `stream_decoder_mt_init` lines 1982–1985).
- Default thread count is automatic (`hardware_init()` calls `hardware_threads_set(0)`, `hardware.c:338`).

The driver loop is `coder_normal()` (`coder.c:1128–1350`): `action = LZMA_FINISH` once `pair->src_eof`; any `ret != LZMA_OK` other than `LZMA_UNSUPPORTED_CHECK` stops, flushes pending output (`coder_write_output`), prints `message_strm(ret)` (`message.c:790`: `LZMA_DATA_ERROR` → "Compressed data is corrupt", `LZMA_BUF_ERROR` → "Unexpected end of input", `LZMA_MEMLIMIT_ERROR` → "Memory usage limit reached", `LZMA_FORMAT_ERROR` → "File format not recognized"). `LZMA_STREAM_END` is success; with `allow_trailing_input` it calls `io_fix_src_pos` and stops without examining the rest of the file (lines 1282–1287).

Between the coder and the CLI sits `lzma_code()` (`common.c:197–370`): `LZMA_OK` with zero in/out progress twice in a row becomes `LZMA_BUF_ERROR` (lines 311–324); `LZMA_TIMED_OUT` is converted to `LZMA_OK` (326–329); `LZMA_STREAM_END` puts the stream in `ISEQ_END`; fatal errors go to `ISEQ_ERROR`.

## 1. Happy path: last Block of Stream 1 → first Block of Stream 2

State machine: `struct lzma_stream_coder::sequence` in `src/liblzma/common/stream_decoder_mt.c:139–153`, driven by `stream_decode_mt()` (line 968).

### 1a. Finishing the last Block (threaded mode)

In threaded mode the main thread does **not** decode. In `SEQ_BLOCK_THR_RUN` (lines 1515–1574) it copies Compressed Data + Block Padding + Check into `thr->in` (size `comp_blk_size()` = `vli_ceil4(compressed_size) + lzma_check_size(check)`, line 932). The moment `in_filled == in_size` it sets `coder->thr = NULL` and goes to `SEQ_BLOCK_HEADER` (lines 1569–1573), *while the worker may still be decoding*.

The worker (`worker_decoder`, line 370) runs `lzma_block_decoder_init`'s coder (`block_decoder.c::block_decode`):
- `SEQ_CODE`: raw filter chain; input/output capped at `compressed_limit`/`uncompressed_limit` (which are the Block Header sizes in threaded mode, since both are required to be present — `is_direct_mode_needed()` line 944). On `LZMA_STREAM_END` it verifies `is_size_valid()` for both sizes (lines 137–141) → `LZMA_DATA_ERROR` on mismatch. It also fails if sizes are met but the filter didn't end, etc. (lines 98–123).
- `SEQ_PADDING`: Block Padding must be zero bytes (165–166).
- `SEQ_CHECK`: copies the Check into `block->raw_check`, compares against the running `lzma_check_state` unless `ignore_check` or unsupported check type (lines 179–196) → `LZMA_DATA_ERROR`.

The worker stores the result in `outbuf->finish_ret` and marks `outbuf->finished = true` (lines 501–505), sets `coder->thread_error` if it was an error (509–511), and calls `worker_stop()` which moves `mem_in_use → mem_cached` and pushes itself onto `threads_free` (352–366).

**Key point**: Check validation of the final Block is done by a worker; the main thread learns of it only when `read_output_and_wait()` → `lzma_outq_read()` (`outqueue.c:230–270`) reaches the end of that outbuf and returns its `finish_ret`.

### 1b. Index detection

`SEQ_BLOCK_HEADER` → `decode_block_header()` (line 879). If the first byte is `INDEX_INDICATOR` (0x00, `index.h:30`) it returns the internal `LZMA_INDEX_DETECTED` (`common.h:172`), and `stream_decode_mt` sets `SEQ_INDEX_WAIT_OUTPUT` (lines 1182–1185). Note the byte is **not consumed**; `lzma_index_hash_decode` re-checks it (`index_hash.c:192`).

### 1c. `SEQ_INDEX_WAIT_OUTPUT` (lines 1644–1654)

Calls `read_output_and_wait(..., input_is_possible=NULL, waiting_allowed=true)` and returns `LZMA_OK` until `lzma_outq_is_empty()`. This is the synchronization barrier: **all worker results, including the last Block's Check verdict, must have been drained before the Index is parsed.** Any worker error surfaces here as the `finish_ret` of the failing outbuf (after all output preceding it has been delivered, since `fail_fast` is off in xz), `read_output_and_wait` breaks with `ret != LZMA_OK`, calls `threads_stop()` (872–873), and the error propagates via `return_if_error`.

### 1d. `SEQ_INDEX_DECODE` (lines 1658–1675) — the cross-stage consistency check

Calls `lzma_index_hash_decode()` (`index_hash.c:172`). The state connecting Blocks to the Index is `coder->index_hash` (`lzma_index_hash`, `index_hash.c:36–68`), holding two `lzma_index_hash_info` accumulators: `blocks` (what was decoded) and `records` (what the Index claims). Each has `blocks_size` (sum of `vli_ceil4(unpadded)`), `uncompressed_size`, `count`, `index_list_size` (sum of VLI encoded lengths), and a `LZMA_CHECK_BEST` hash over the `(unpadded, uncompressed)` pairs (SHA-256 if built, else CRC64, else CRC32 — `check.h:67–73`).

Where `blocks` is filled differs by mode:
- **Threaded mode**: `lzma_index_hash_append()` is called in `SEQ_BLOCK_INIT` *before* decoding, from Block Header sizes (lines 1292–1298). This is sound only because `block_decode` rejects any Block whose actual sizes differ from the header (`is_size_valid`) — the comment at 1292–1294 says exactly this.
- **Direct mode**: appended after `LZMA_STREAM_END` from the Block decoder (`SEQ_BLOCK_DIRECT_RUN`, lines 1633–1638), with the sizes the Block decoder wrote back into `block_options` (`block_decoder.c:145–146`).
- Single-threaded `lzma_stream_decoder`: same as direct (`stream_decoder.c:270–273`).

`lzma_index_hash_decode` then walks: Index Indicator (`SEQ_BLOCK`), `Number of Records` must equal `blocks.count` (205–206), each `Unpadded Size` must be in `[UNPADDED_SIZE_MIN=5, UNPADDED_SIZE_MAX]` (232–235), after each record the running `records.*` sums must not exceed `blocks.*` (250–256), Index Padding must be zero (`SEQ_PADDING`, 275–278), then exact equality of the three sums (284–290) **and** equality of the two hashes (293–298), then CRC32 of everything consumed (`SEQ_CRC32`, 308–322). Returns `LZMA_STREAM_END` only after all four CRC bytes match.

### 1e. `SEQ_STREAM_FOOTER` (lines 1679–1717)

Buffers 12 bytes, then `lzma_stream_footer_decode()` (`stream_flags_decoder.c:61–87`): Footer Magic `59 5A` → else `LZMA_FORMAT_ERROR` (converted to `LZMA_DATA_ERROR` at 1699–1700); CRC32 over Backward Size + Stream Flags → else `LZMA_DATA_ERROR`; reserved bits → `LZMA_OPTIONS_ERROR`; `backward_size = (stored+1)*4`. Then two **independent structural checks**:
- `lzma_index_hash_size(index_hash) != footer_flags.backward_size` → `LZMA_DATA_ERROR` (1704–1706). `lzma_index_hash_size` computes from `->blocks` (`index_hash.c:112–120`), i.e. from Block-derived state, not from bytes read in the Index.
- `lzma_stream_flags_compare(&coder->stream_flags, &footer_flags)` (`stream_flags_common.c:19–46`): check type must equal the Stream Header's → `LZMA_DATA_ERROR`.

Then `if (!coder->concatenated) return LZMA_STREAM_END;` (1713–1714), else `SEQ_STREAM_PADDING`.

### 1f. `SEQ_STREAM_PADDING` (lines 1721–1759)

Consumes zero bytes, tracking `coder->pos = (pos+1) & 3`. On input exhaustion: `LZMA_RUN` → `LZMA_OK` (more input may come); `LZMA_FINISH` → `LZMA_STREAM_END` if `pos == 0`, else `LZMA_DATA_ERROR`. On a nonzero byte: if `pos != 0` → consume that byte and `LZMA_DATA_ERROR` (1751–1755); if `pos == 0` → `stream_decoder_reset()` (951–965: re-init `index_hash`, `sequence = SEQ_STREAM_HEADER`, `pos = 0`) and loop.

### 1g. `SEQ_STREAM_HEADER` for Stream 2 (lines 1034–1080)

Buffers 12 bytes; `lzma_stream_header_decode()` (`stream_flags_decoder.c:29–58`): magic → `LZMA_FORMAT_ERROR`, which is remapped to `LZMA_DATA_ERROR` because `first_stream` is now false (1050–1052, 1057); CRC32 → `LZMA_DATA_ERROR`; reserved bits → `LZMA_OPTIONS_ERROR`. Copies `check` into `block_options.check`, goes to `SEQ_BLOCK_HEADER`, possibly returning `LZMA_UNSUPPORTED_CHECK` first (xz prints it as a warning and continues, `coder.c:1270, 1326`).

### 1h. Back into Block decoding

`SEQ_BLOCK_HEADER` → `lzma_block_header_decode()` (`block_header_decoder.c`: CRC32, flags, sizes, filter flags, zero padding) → `lzma_raw_decoder_memusage()` → `SEQ_BLOCK_INIT` → `SEQ_BLOCK_THR_INIT` (or direct) as in §3. Threads from Stream 1 are **not** torn down between Streams (`threads_end` is only called in `stream_decoder_mt_init`, `SEQ_BLOCK_DIRECT_INIT`, and `_end`); only `index_hash` is reset. The API doc confirms "Concatenated Streams are processed one Stream at a time; no inter-Stream parallelization" (`container.h:757–758`).

Important ordering detail for the Footer: CRC is verified *before* Backward Size and Stream Flags, so an attacker who recomputes the CRC gets past the CRC step and is caught by the structural checks; an attacker who doesn't recompute is caught by the CRC. Both yield `LZMA_DATA_ERROR`, so the CLI cannot distinguish them.

### Concatenated vs. single-Stream mode

- **`LZMA_CONCATENATED` (xz default)**: `LZMA_STREAM_END` is only returned from `SEQ_STREAM_PADDING` when input is exhausted with `LZMA_FINISH` and `pos == 0` (`container.h:682–684` documents that `LZMA_FINISH` is required). Everything after the Footer is examined. Trailing garbage that is not zero-padding and not a valid Stream Header → `LZMA_DATA_ERROR`.
- **`--single-stream` (no `LZMA_CONCATENATED`)**: `SEQ_STREAM_FOOTER` returns `LZMA_STREAM_END` immediately (1713–1714). Stream Padding and anything after it are **never read**; the attacker's modifications there are invisible. `coder_normal` sees `allow_trailing_input` and succeeds (`coder.c:1283–1287`). Note the init-time probe in `coder_init` tolerates `LZMA_STREAM_END` for this mode (`coder.c:1008–1016`).

## 3. Connection to threading and memory limits

### 3a. What must wait for workers

- Only the **Index/Footer/Padding/next-Header** validation depends on worker results, and only via the barrier `SEQ_INDEX_WAIT_OUTPUT` (queue must be empty). Block Header parsing of later Blocks in the *same* Stream does not wait (the main thread races ahead, bounded by `threads_max`, output-queue slots, and `memlimit_threading` in `read_output_and_wait` lines 751–763).
- What survives from Blocks to Index verification: only `coder->index_hash->blocks` (sums, count, encoded list size, hash). Per-Block sizes are *not* retained — hence the spec's "constant memory" implementation hint (`xz-file-format.txt:699–704`). Because threaded mode appends from the header *before* decoding, correctness of the Index check also depends on the worker's `is_size_valid` + Check rejections being surfaced before `SEQ_INDEX_DECODE`, which the barrier guarantees.
- Worker errors (bad Check, size mismatch, corrupt LZMA2) arrive as `outbuf->finish_ret`. Without `LZMA_FAIL_FAST` (xz's case), `read_output_and_wait` sets `pending_error` as a flag (735) and keeps delivering output; the real code is returned only when the failing outbuf reaches the head (comment 720–728). With `LZMA_FAIL_FAST`, `thread_error` is returned immediately (715–717). `container.h:693–712` documents this difference and that output volume/error code can vary run to run with fail-fast.

### 3b. Next Block valid but memory exceeds what's available

Computed in `SEQ_BLOCK_INIT` (lines 1221–1306) from the Block Header only, before any data is decoded:

1. **Hard limit** — `mem_next_filters > memlimit_stop` (1228): flush all pending output first (`read_output_and_wait`, `waiting_allowed=true`), return `LZMA_OK` while the queue is non-empty, then `LZMA_MEMLIMIT_ERROR` (1233–1240). The sequence stays at `SEQ_BLOCK_INIT`, so after `lzma_memlimit_set()` raises the limit (`stream_decoder_mt_memconfig`, 1820–1864) decoding can resume — this is what `test_memlimit.c::test_memlimit_stream_decoder_mt` (lines 60–95) verifies. `lzma_code` treats `LZMA_MEMLIMIT_ERROR` as non-fatal (`common.c:356–360`), but xz does not retry: `coder_normal` prints "Memory usage limit reached" plus `message_mem_needed(lzma_memusage())` and stops (`coder.c:1334–1342`). Note `memlimit_stop` only gates the **filter chain** memory, not the in/out buffers.

2. **Soft limit (threading)** — three escalating outcomes, none of which is an error:
   - `mem_next_block = mem_next_filters + comp_blk_size + lzma_outq_outbuf_memusage(uncompressed_size)` (1260–1278). If `mem_next_block > memlimit_threading` **by itself** (1282–1285), or sizes are unknown/too large (`is_direct_mode_needed`, 1248–1253), or the sum overflows (1267–1274) → `SEQ_BLOCK_DIRECT_INIT`: drain the queue, `lzma_outq_clear_cache`, `threads_end()` (frees all worker threads and resets `mem_in_use/mem_cached`), init `coder->block_decoder` in the main thread, `mem_direct_mode = mem_next_filters` (1576–1616). Decoding continues single-threaded, possibly far above `memlimit_threading` — exactly as `container.h:205–210, 219–220` promises ("memlimit_threading will never make lzma_code() return LZMA_MEMLIMIT_ERROR"). Later Blocks can switch back to threaded mode (1287–1290 frees the direct decoder).
   - If `mem_next_block ≤ memlimit_threading` but currently-running threads plus the output queue make `memlimit_threading - mem_in_use - outq.mem_in_use < mem_next_block` (`read_output_and_wait` 751–755), `block_can_start` stays false and `SEQ_BLOCK_THR_INIT` **waits** (1327–1348), copying output to the caller meanwhile and returning `LZMA_OK` when the output buffer is full. This merely delays scheduling; concurrency drops.
   - If it can start but cached memory would push over the limit, `SEQ_BLOCK_THR_INIT` frees outq cache and cached worker Block decoders first (1385–1424).

So: *cannot be scheduled concurrently right now* = wait in `SEQ_BLOCK_THR_INIT`; *can never fit under the soft limit even alone* = direct mode; *filter chain exceeds the hard limit* = `LZMA_MEMLIMIT_ERROR` after flushing output.

### 3c. Interaction with Stream completion

- Direct-mode Blocks append to `index_hash` *after* decoding (1635–1638), threaded Blocks *before*; both feed the same `blocks` accumulator, so a Stream mixing both modes is verified identically at `SEQ_INDEX_DECODE`.
- A `LZMA_MEMLIMIT_ERROR` on Block N of Stream 2 leaves `index_hash` with N-1 records; if the application raises the limit and continues, the Index check still works. In xz it's terminal.
- `threads_stop()` after any fatal error (872–873) stops workers but does not free them; `lzma_end` → `stream_decoder_mt_end` → `threads_end` does (1795–1809).
- Between Streams nothing memory-related is reset; worker threads and cached decoders carry over, and `mem_cached` can be reclaimed by Stream 2's `SEQ_BLOCK_THR_INIT`.

## 4. Mode/platform differences that change the path

- **`--single-stream`**: Footer → `LZMA_STREAM_END`; padding and later Streams never parsed (§2).
- **`-T1` / `--threads=1`**: `memlimit_threading = 0` → `my_max(1, 0) = 1` (1982), so every Block takes `SEQ_BLOCK_DIRECT_INIT`; behavior matches `lzma_stream_decoder()` (`container.h:760–761`), and Index appends happen post-decode. The sequence of validations (Index → Footer → Padding → Header) is identical; only who decodes and when `index_hash` is fed differs.
- **Build without `MYTHREAD_ENABLED`**: xz uses `lzma_stream_decoder()` (`coder.c:960–963`, `stream_decoder.c`), same checks, no `SEQ_INDEX_WAIT_OUTPUT` barrier needed.
- **Blocks without size fields in the header** (e.g. produced by single-threaded `xz -T1`): `is_direct_mode_needed` forces direct mode for that Block even with many threads.
- **`FUZZING_BUILD_MODE_UNSAFE_FOR_PRODUCTION`**: CRC32 mismatches in Stream Header, Stream Footer, Block Header and Index are ignored (`stream_flags_decoder.c:42–45, 73–76`, `block_header_decoder.c:58–60`, `index_hash.c:315–317`); only the structural checks remain.
- **`LZMA_CHECK_BEST`** depends on `HAVE_CHECK_SHA256`/`HAVE_CHECK_CRC64` (`check.h:67–73`); with neither, the Index record hash is CRC32, weakening (but not removing) the per-record cross-check — the sums and count checks are unaffected.
- **`LZMA_FAIL_FAST`** (not used by xz): worker errors and truncation are reported immediately as `LZMA_DATA_ERROR` (1159–1165, 1516–1528) rather than after all preceding output.
- **32-bit builds**: `memlimit_mt_default` capped at 1400 MiB (`hardware.c:323–333`); `is_direct_mode_needed` uses `SIZE_MAX/3` so more Blocks fall to direct mode.
