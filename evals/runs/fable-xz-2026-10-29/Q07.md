## Where deletion happens

There is exactly one code path that removes the input file: `io_close_src()` in `src/xz/file_io.c` (lines 739–774), called only from `io_close()` (file_io.c:1029–1074). The deletion line is:

```c
if (success && !opt_keep_original)
	io_unlink(pair->src_name, &pair->src_st);
```

guarded by `pair->src_fd != STDIN_FILENO && pair->src_fd != -1` (file_io.c:754). The file is closed before unlinking (file_io.c:767; comment explains the EBUSY/CIFS reason and that xz ≤ 5.2.2 did the reverse).

`io_unlink()` (file_io.c:231–285) does the actual `unlink()`, but only after re-checking identity (see "Last-moment check" below).

## Conditions required for deletion (all must hold)

**1. The source is a named, on-disk file, not stdin.** `io_close_src` skips stdin (file_io.c:754). For stdin, `io_open_src_real` sets `src_fd = STDIN_FILENO` without stat (file_io.c:453–454).

**2. `opt_keep_original` is false.** It becomes true from:
- `-k`/`--keep` (args.c:423–424).
- `--stdout`/`-c` (args.c:383–384), or being invoked as `xzcat`/`lzcat` which sets `opt_stdout` (args.c:773–781); or `--test`/`-t` (args.c:436–437). All of these are collapsed in `args_parse()` by: `if (opt_stdout || opt_mode == MODE_TEST) { opt_keep_original = true; opt_stdout = true; }` (args.c:819–825, comment: "Never remove the source file when the destination is not on disk").
- Options from `XZ_DEFAULTS`/`XZ_OPT` are parsed too (args.c:791–792), so `-k` in those env vars also prevents deletion.

Consequence: passthru mode (`coder_passthru`, coder.c:1357) returns `true` on success, but it is only reachable with `--decompress --stdout --force` (coder.c:928–933), so `opt_keep_original` is always true there and nothing is deleted.

**3. `success` is true when `io_close(pair, success)` is called.** Callers:
- `coder_run()` (coder.c:1380–1454): `success` starts `false` (coder.c:1391) and becomes true only from the return of `coder_normal()` (coder.c:1442).
- `list_file()` in list.c:1344 always passes `false` — `--list` never deletes.

`coder_normal()` (coder.c:1128–1350) sets `success = true` in exactly two places:
- coder.c:1285: `lzma_code()` returned `LZMA_STREAM_END` and `allow_trailing_input` is true (`--single-stream`, coder.c:876–877, or `.lz` input, coder.c:975).
- coder.c:1310: `LZMA_STREAM_END` with `strm.avail_in == 0` after a 1-byte probe read confirmed `src_eof` (coder.c:1294–1312). If there is trailing garbage, `ret` is set to `LZMA_DATA_ERROR` and `success` stays false (coder.c:1315).

Note that a non-fatal warning does not block deletion: `LZMA_UNSUPPORTED_CHECK` sets `stop = false` (coder.c:1270), emits only `message_warning`, and coding continues to `LZMA_STREAM_END` → `success = true`.

**4. Nothing in `io_close()` flips `success` back to false.** Within `io_close()` (file_io.c:1029–1074):
- Sparse-file finalisation: if the final `lseek()` or 1-byte `io_write_buf()` fails, `success = false` (file_io.c:1041–1051).
- `io_close_dest(pair, success)` returning true sets `success = false` (file_io.c:1063–1064, comment: "If it fails, we must not remove the source file!"). `io_close_dest` fails if restoring stdout flags fails (file_io.c:989–999) or if `close(dest_fd)` fails (file_io.c:1006–1015) — in the latter case the *destination* is unlinked as junk instead.
- Note: `io_copy_attrs()` is `void` (file_io.c:293) and only emits warnings on `fchown`/`fchmod`/timestamp failure (file_io.c:305–340); its failures do **not** prevent deleting the source.

## Checks that prevent reaching deletion at all (file never opened / never coded)

These happen earlier, so `io_close` is called with `success == false` or never with an open src:

**In `io_open_src_real()` (file_io.c:450–686):**
- Empty filename → skipped (`io_open_src`, file_io.c:692–694).
- Symlink: `follow_symlinks = opt_stdout || opt_force || opt_keep_original` (file_io.c:488–489); without those, `O_NOFOLLOW` is used (file_io.c:508–510) or an `lstat` fallback (file_io.c:515–527), and a symlink is skipped with "Is a symbolic link, skipping" (file_io.c:584–586).
- Directory → skipped (file_io.c:613–617).
- Not a regular file when `reg_files_only = !opt_stdout` → skipped (file_io.c:494, 619–623).
- When `reg_files_only && !opt_force && !opt_keep_original` (file_io.c:626): setuid/setgid bit → skip (627–641); sticky bit → skip (643–648); `st_nlink > 1` (hard links) → skip (650–655). Note `--force` *or* `--keep` bypasses these three checks; with `--keep` that is safe because nothing gets deleted anyway.

**In `coder_run()` / `coder_init()`:**
- First read error (`io_read` returns `SIZE_MAX`, coder.c:1403) → no coding.
- `coder_init()` returning `CODER_INIT_ERROR` or `user_abort` already set (coder.c:1412) → no coding.
- `--test`: destination not opened, but `opt_keep_original` is already true anyway (coder.c:1413–1415).

**In `io_open_dest_real()` (file_io.c:778–964), any failure → `success` remains false:**
- `suffix_get_dest_name()` returns NULL (file_io.c:808–810): unknown suffix when decompressing (suffix.c:164–167), or file already has a compressed suffix / custom suffix when compressing (suffix.c:239–258).
- `--force` tries to `unlink()` an existing destination first (file_io.c:837); without `--force`, `open()` uses `O_CREAT | O_EXCL` (file_io.c:845–846) so an existing destination fails with EEXIST and nothing proceeds.
- DJGPP only: refuses if dest would be the same dev/inode as source (file_io.c:824–832).

**During coding (`coder_normal`):**
- `user_abort` (set by the signal handler, signals.c:40–42) exits the `while (!user_abort)` loop (coder.c:1192) with `success == false`.
- Any `io_read` failure (coder.c:1205–1206, 1301–1302) or `coder_write_output`/`io_write` failure (coder.c:1230–1231, 1241–1242, 1278–1279) breaks out with `success == false`.
- Any fatal `lzma_ret` other than `LZMA_STREAM_END` / `LZMA_UNSUPPORTED_CHECK` (coder.c:1266–1343) → error message, `success == false`. In those failure cases `io_close_dest` deletes the partially written destination (file_io.c:1019–1020).

## Last-moment check inside `io_unlink()` (file_io.c:231–285)

Before `unlink()`, on non-DOS systems xz re-stats the path and compares `st_dev` and `st_ino` to the values recorded by `fstat()` at open time (`pair->src_st`, file_io.c:609). If stat fails or dev/ino differ, it prints "File seems to have been moved, not removing" and does not delete (file_io.c:252–275). Details:
- Uses `lstat()` normally, `stat()` when `--force` was given (file_io.c:249–250). The comment notes the consequence: with `--force`, if `foo` is renamed to `bar` and a symlink `foo -> bar` is created, xz will follow it and still remove `foo` (the symlink) (file_io.c:240–248).
- On VMS only `st_ino` (an array) is compared via `memcmp` (file_io.c:253–257); on DOS-like systems the check is skipped entirely because `st_ino` is meaningless (file_io.c:233–236).
- A TOCTOU race between the stat and `unlink()` remains and is acknowledged (file_io.c:278–279).
- If `unlink()` itself fails, only a warning is printed (file_io.c:280–282).

Signals with handlers are blocked for the whole `io_close()` sequence (`signals_block()` at file_io.c:1054, unblocked at 1071), so a Ctrl-C cannot land between closing the destination and unlinking the source.
