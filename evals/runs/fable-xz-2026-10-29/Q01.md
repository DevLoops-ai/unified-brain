# Answer

## Answer

The `.note.GNU-stack` section is emitted in exactly two places in the tree, both hand-written 32-bit x86 assembly files, and only when two layers of conditions are satisfied: (1) the build system decides to compile those `.S` files at all, and (2) the preprocessor guard inside the files is true for the target.

### 1. Where it is emitted

- `src/liblzma/check/crc32_x86.S`, line 306-308 (end of file, after `lzma_crc32_generic`):
  ```c
  #if defined(__ELF__) && (defined(__FreeBSD__) || defined(__linux__))
  	.section	.note.GNU-stack,"",@progbits
  #endif
  ```
- `src/liblzma/check/crc64_x86.S`, line 289-291 (identical guard, after `lzma_crc64_generic`).

The comment directly above both says it "is needed to support non-executable stack" and that `__FreeBSD__`/`__linux__` are used because the author does not know a way to detect GNU assembler. The directive is at top level of the file, not nested inside any other `#if` (verified by listing the preprocessor structure of `crc32_x86.S`), so its only in-file condition is that guard.

No other file in the checkout mentions `GNU-stack`, `noexecstack`, `execstack` or `GNU_STACK` (grep over the whole tree excluding `.git`). In particular there is no linker flag such as `-Wl,-z,noexecstack` anywhere; the C objects get the note from the compiler as usual, and these two files are the only hand-written assembly that would otherwise lack it.

### 2. In-file condition (preprocessor)

The section is emitted only if **both**:
- `__ELF__` is defined (ELF object format), **and**
- `__FreeBSD__` or `__linux__` is defined.

So even if the `.S` files are compiled on other ELF systems (NetBSD, OpenBSD, GNU/Hurd, Solaris...), no `.note.GNU-stack` is written. On Mach-O (`__APPLE__`), PE (`_WIN32`, `__CYGWIN__`) and DJGPP (`__MSDOS__`) it is likewise not emitted; the surrounding `#elif` blocks (lines 289-299 in crc32_x86.S) show those targets are intentionally handled separately.

### 3. Build-system condition: when are the `.S` files compiled?

**Autotools** (`configure.ac`, "Assembler optimizations" block, lines 342-374):
- `--enable-assembler` defaults to `yes`. With `yes`, it is resolved to `x86` only when `$host_os` matches `linux* | *bsd* | mingw* | cygwin | msys | *djgpp*` **and** `$host_cpu` matches `i?86`; otherwise it becomes `no`. The comment notes Darwin is deliberately excluded (universal binaries) and Solaris x86 is untested.
- `--enable-assembler=x86` forces it; `--disable-assembler` turns it off; any other value is an `AC_MSG_ERROR`.
- Result: `AC_DEFINE([HAVE_CRC_X86_ASM])` and `AM_CONDITIONAL(COND_ASM_X86, ...)`.
- `src/liblzma/check/Makefile.inc` adds `check/crc32_x86.S` only under `if COND_ASM_X86` **inside the `else` branch of `if COND_SMALL`** (i.e. not when `--enable-small`), and adds `check/crc64_x86.S` only under `COND_CHECK_CRC64` and `!COND_SMALL` and `COND_ASM_X86`.

**CMake** (`CMakeLists.txt`):
- Lines 232-256: only `if(NOT MSVC)`. Default of `XZ_ASM_I386` is `check_symbol_exists("__i386__" ...)` when `MINGW OR CYGWIN OR CMAKE_SYSTEM_NAME MATCHES "^FreeBSD$|^GNU$|^Linux$|^MirBSD$|^NetBSD$|^OpenBSD$"`, otherwise `OFF`. The user can override with `-DXZ_ASM_I386=ON/OFF`. When on, `enable_language(ASM)` is called.
- Lines 711-740: `crc32_x86.S` is added (and `HAVE_CRC_X86_ASM` defined) only `if(XZ_ASM_I386)` within the `else()` of `if(XZ_SMALL)`; `crc64_x86.S` only when `"crc64" IN_LIST XZ_CHECKS`, not `XZ_SMALL`, and `XZ_ASM_I386`.

### 4. Combined condition

`.note.GNU-stack` appears in the liblzma build output iff:

1. Target is 32-bit x86 (`i?86` host CPU in autotools; `__i386__` defined, or `XZ_ASM_I386=ON` forced, in CMake), and
2. Assembler optimizations are enabled (autotools: default on for linux/*bsd/mingw/cygwin/msys/djgpp, `--enable-assembler=x86` elsewhere, not `--disable-assembler`; CMake: `XZ_ASM_I386`, not MSVC), and
3. Not a small build (`--enable-small` / `XZ_SMALL` selects `crc32_small.c`/`crc64_small.c` and never the `.S` files), and
4. The target defines `__ELF__` and (`__FreeBSD__` or `__linux__`).

`crc64_x86.S` additionally requires CRC64 to be in the enabled checks (`COND_CHECK_CRC64` / `"crc64" IN_LIST XZ_CHECKS`), but since `crc32_x86.S` carries the same directive and CRC32 is always built, the note's presence is not dependent on CRC64.
