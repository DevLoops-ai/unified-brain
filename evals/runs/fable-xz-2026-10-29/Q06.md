# Answer

**Scope of the answer:** all code is in `src/liblzma/common/stream_decoder_mt.c` unless stated otherwise; checkout commit 45d08abc.

## Two limits, not one

The multithreaded decoder takes two limits from `lzma_mt` (`src/liblzma/api/lzma/container.h`, lines 225 and 236) and stores them in `struct lzma_stream_coder`:

- `memlimit_threading` — "Memory usage that will not be exceeded in multi-threaded mode. Single-threaded mode can exceed this even by a large amount." (struct comment, lines 229-231)
- `memlimit_stop` — "Memory usage limit that should never be exceeded. LZMA_MEMLIMIT_ERROR will be returned if decoding isn't possible even in single-threaded mode without exceeding this limit." (lines 233-236)

In `stream_decoder_mt_init()` (lines 1982-1985) both are clamped to at least 1 and `memlimit_threading` is clamped down to `memlimit_stop` if it was larger. The xz CLI fills them in `src/xz/coder.c` lines 943-957: `memlimit_stop = hardware_memlimit_get(MODE_DECOMPRESS)`, `memlimit_threading = hardware_memlimit_mtdec_get()`, or 0 when `threads == 1` to force single-threaded mode.

## Memory accounting

The coder tracks (struct fields, lines 238-264):
- `mem_direct_mode` — memory of the single-threaded Block decoder (0 in threaded mode).
- `mem_in_use` — filters + input buffers of running worker threads (mutex-protected).
- `mem_cached` — filter memory of idle threads kept for reuse.
- `outq.mem_in_use` / `outq.mem_allocated` — output buffers in use / allocated including cache (`src/liblzma/common/outqueue.c`: `lzma_outq_get_buf()` line 213 adds to `mem_in_use`, `move_head_to_cache()` line 60 subtracts, `lzma_outq_prealloc_buf()` line 175 adds to `mem_allocated`, `free_one_cached_buffer()` line 75 subtracts).
- `mem_next_filters`, `mem_next_in`, `mem_next_block` — the estimate for the Block about to start.

Per-buffer cost is `sizeof(lzma_outbuf) + buf_size` (`lzma_outq_outbuf_memusage()`, `src/liblzma/common/outqueue.h` lines 251-256).

When a worker finishes or is stopped, `worker_stop()` (lines 351-367) does `mem_in_use -= in_size`, `mem_in_use -= mem_filters`, `mem_cached += mem_filters`, and pushes the thread on `threads_free`. When a cached thread is picked up again, `get_thread()` (lines 626-637) subtracts its `mem_filters` from `mem_cached`; the caller adds the actual new usage to `mem_in_use` (line 1441-1442).

## Enforcement path per Block (in `stream_decode_mt()`)

**1. `SEQ_BLOCK_HEADER` (lines 1205-1214):** after decoding the Block Header, `mem_next_filters = lzma_raw_decoder_memusage(coder->filters)`. `UINT64_MAX` (unknown filter ID) gives `LZMA_OPTIONS_ERROR`.

**2. `SEQ_BLOCK_INIT`, hard limit first (lines 1221-1241):**
```c
if (coder->mem_next_filters > coder->memlimit_stop) {
```
If the filter chain alone needs more than `memlimit_stop`, the decoder first flushes already-decoded output via `read_output_and_wait()`; while `outq` is non-empty it returns `LZMA_OK` so the application drains it, and only then returns **`LZMA_MEMLIMIT_ERROR`**. The comment (lines 1225-1227) states this check is deliberately first in `SEQ_BLOCK_INIT` so decoding can be *restarted* after the application raises the limit with `lzma_memlimit_set()`. Note this check uses only the filter memory, not buffers — buffers are only needed in threaded mode.

**3. `SEQ_BLOCK_INIT`, decide threaded vs direct mode (lines 1243-1285):**
- If `compressed_size` or `uncompressed_size` is `LZMA_VLI_UNKNOWN` or `> SIZE_MAX / 3` (`is_direct_mode_needed()`, lines 944-948) → `SEQ_BLOCK_DIRECT_INIT`.
- Otherwise `mem_next_in = comp_blk_size()` (compressed size rounded up to 4 + check size, lines 932-937), `mem_buffers = mem_next_in + lzma_outq_outbuf_memusage(uncompressed_size)`, and `mem_next_block = mem_next_filters + mem_buffers` (overflow → direct mode, lines 1267-1274).
- **If `mem_next_block > memlimit_threading` → `SEQ_BLOCK_DIRECT_INIT`** (lines 1282-1285). This is the "a block would exceed the available memory" case for threading: the decoder does not fail, it falls back to single-threaded direct mode for that Block.

**4. `SEQ_BLOCK_THR_INIT`, wait for memory to drop (lines 1310-1348):** `read_output_and_wait()` is called with `input_is_possible` set. Inside it (lines 751-763) the Block may start only when:
```c
coder->memlimit_threading - coder->mem_in_use - coder->outq.mem_in_use >= coder->mem_next_block
&& lzma_outq_has_buf(&coder->outq)
&& (coder->threads_initialized < coder->threads_max || coder->threads_free != NULL)
```
Until that holds, the main thread copies finished output to the caller and blocks on the condition variable (subject to the timeout / `waiting_allowed` logic); running workers finishing reduces `mem_in_use` and `outq.mem_in_use`. This is how the thread count is effectively reduced by memory: new Blocks simply are not started while the running ones would push usage over `memlimit_threading`. If the caller's output buffer is full and the queue is non-empty, it returns `LZMA_OK` (lines 1339-1348).

**5. `SEQ_BLOCK_THR_INIT`, evict caches to stay under the limit (lines 1362-1443):** `mem_max = memlimit_threading - mem_next_block`.
- If `mem_in_use + mem_cached + outq.mem_allocated > mem_max`, cached output buffers are freed with `lzma_outq_clear_cache2()` (keeps one buffer if it already has the right size; `outqueue.c` lines 92-108).
- If there is a free thread and `mem_in_use + mem_cached + outq.mem_in_use > mem_max`, cached Block decoders of idle threads are freed (`lzma_next_end()` on each, `mem_filters = 0`), skipping the first cached thread if its memory is ≤ what this Block needs so it can be reused (lines 1406-1424).
- Then `mem_cached -= mem_freed; mem_in_use += mem_next_in + mem_next_filters` under the mutex, the output buffer is preallocated (`lzma_outq_prealloc_buf()`), a thread is obtained, and `thr->mem_filters = mem_next_filters`. Allocation failures (`LZMA_MEM_ERROR` from prealloc/`lzma_alloc` of the input buffer) stop the threads and return the error (lines 1446-1459, 1484-1490).

**6. `SEQ_BLOCK_DIRECT_INIT` / `SEQ_BLOCK_DIRECT_RUN` (lines 1576-1642):** the fallback. It waits until `outq` is empty (all threaded output delivered), frees the output cache (`lzma_outq_clear_cache()`), tears down all worker threads with `threads_end()`, initializes `coder->block_decoder` single-threaded, and records `mem_direct_mode = mem_next_filters` so `lzma_memusage()` reports it. In this mode `memlimit_threading` is not consulted at all — the API doc says it "may be exceeded even by a large amount" (`container.h` lines 205-209). Only `memlimit_stop` (checked in step 2) bounds it. After the Block finishes it goes back to `SEQ_BLOCK_HEADER`, and the next Block may re-enter threaded mode (step 3 frees the direct decoder: `lzma_next_end(&coder->block_decoder)`, `mem_direct_mode = 0`, lines 1289-1290).

## `lzma_memlimit_get/set` behaviour

`stream_decoder_mt_memconfig()` (lines 1820-1864): reports `memusage = mem_direct_mode + mem_in_use + mem_cached + outq.mem_allocated` (at least `LZMA_MEMUSAGE_BASE`), gets/sets **only `memlimit_stop`**; `memlimit_threading` cannot be changed after init (comment lines 1824-1825). A new limit lower than current usage (including cache) is rejected with `LZMA_MEMLIMIT_ERROR`. Raising it after an `LZMA_MEMLIMIT_ERROR` lets `lzma_code()` resume because `SEQ_BLOCK_INIT` re-runs the check.

## Summary of outcomes when a Block "would exceed" memory

| Condition | Result |
|---|---|
| `mem_next_filters > memlimit_stop` | Flush pending output, then `LZMA_MEMLIMIT_ERROR`; resumable after `lzma_memlimit_set()` |
| `mem_next_block` (filters + in buf + out buf) `> memlimit_threading`, or sizes unknown/huge | Single-threaded direct mode for that Block; `memlimit_threading` ignored |
| Block fits in `memlimit_threading` but running threads currently use too much | Main thread waits in `read_output_and_wait()` until workers free memory (fewer effective threads); caches evicted as needed |
| Actual `malloc` fails | `LZMA_MEM_ERROR`, threads stopped |
