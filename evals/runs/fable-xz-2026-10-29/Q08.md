# Answer

## Setup: what "Index" means in the code and what stays fixed

The Index as decoded by liblzma (index_decoder.c `index_decode`, index_hash.c `lzma_index_hash_decode`) is: Index Indicator byte `0x00` (`INDEX_INDICATOR`, index.h) → Number of Records (VLI) → List of Records, each (Unpadded Size VLI, Uncompressed Size VLI) → Index Padding (0–3 zero bytes) → CRC32 over everything before it.

"Blocks unchanged" pins three things the Index is compared against:
- each Block's Unpadded Size as actually consumed (`lzma_block_unpadded_size(&coder->block_options)` after the Block decoder has written the final `compressed_size`/`uncompressed_size` into `coder->block`, block_decoder.c `block_decode` lines 137–146),
- each Block's Uncompressed Size as actually produced,
- the Block count and the order.

Those are fed into the hash with `lzma_index_hash_append` (stream_decoder.c `stream_decode` SEQ_BLOCK_RUN line 270; stream_decoder_mt.c lines 1295 and 1635). Note that in the MT threaded path the append happens *before* decoding, using the Block Header's sizes, and the Block decoder then verifies those header sizes against reality (block_decoder.c `is_size_valid`); either way, the hash input equals the true Block sizes or decoding fails first.

There are two independent consumers of the Index, with different check sets:

- **Forward path** (`xz -d`, `lzma_stream_decoder`, `lzma_stream_decoder_mt`): `lzma_index_hash_decode` with Block data available. Strongest.
- **Backward path** (`xz --list`, `lzma_file_info_decoder`, `lzma_index_decoder`/`lzma_index_buffer_decode`): `index_decode` with no Block data. Weaker; relies on geometry and the Footer.

## Forward path: checks in the order they fire

Everything below is in `lzma_index_hash_decode` (index_hash.c) unless noted, called from stream_decoder.c SEQ_INDEX (line 288) and stream_decoder_mt.c SEQ_INDEX_DECODE (line 1668).

**F1. Index located and Indicator byte.** The stream decoder only enters SEQ_INDEX when the byte at the current position is `0x00` (stream_decoder.c line 167). Any other value is treated as a Block Header: `lzma_block_header_size_decode` then `lzma_block_header_decode`, whose CRC32 check (block_header_decoder.c line 57–59) fails on garbage. Inside the hash decoder SEQ_BLOCK re-checks `in[..] == INDEX_INDICATOR` (line 192).

**F2. VLI well-formedness** (`lzma_vli_decode`, vli_decoder.c). Two rejections: more than `LZMA_VLI_BYTES_MAX` bytes, and a non-minimal encoding (a terminating `0x00` byte after the first byte, lines 57–58). So re-encoding the same number with extra continuation bytes is a `LZMA_DATA_ERROR` on its own, before any sum check.

**F3. Record count == Blocks decoded** (SEQ_COUNT, line 205). `remaining != blocks.count` → `LZMA_DATA_ERROR`. Forward-only; the standalone Index decoder has no equivalent.

**F4. Per-Record Unpadded Size range** (line 232): must be in `[UNPADDED_SIZE_MIN=5, UNPADDED_SIZE_MAX=LZMA_VLI_MAX&~3]` (index.h). Uncompressed Size is only bounded by the VLI decoder.

**F5. Running-sum upper bounds** (lines 250–256), after each Record: `records.blocks_size` (Σ `vli_ceil4(unpadded)`), `records.uncompressed_size` (Σ uncompressed), and `records.index_list_size` (Σ VLI byte lengths, `hash_append` lines 128–131) must not exceed the Block-side totals. Early-abort check only; equality is tested later.

**F6. Index Padding** (SEQ_PADDING_INIT/SEQ_PADDING, lines 267–278). Padding length is `(4 - index_size_unpadded(records.count, records.index_list_size)) & 3` — computed from the *Index as read*, not from the Blocks — and each padding byte must be `0x00`.

**F7. Exact equality of the three totals** (lines 284–290): `blocks_size`, `uncompressed_size`, `index_list_size` Blocks-side vs Records-side.

**F8. Record-sequence hash** (lines 293–298). Each (unpadded, uncompressed) pair is hashed in order with `LZMA_CHECK_BEST` (`hash_append` lines 134–136) and the two digests are `memcmp`'d. `LZMA_CHECK_BEST` is SHA-256 if `HAVE_CHECK_SHA256`, else CRC64, else CRC32 (check.h lines 66–73). This is the check that catches any redistribution of sizes among Records that preserves all three sums.

**F9. Index CRC32** (lines 301–320): CRC32 over Indicator…Padding compared byte-by-byte to the stored field (disabled only under `FUZZING_BUILD_MODE_UNSAFE_FOR_PRODUCTION`). Note the ordering: in the forward path the CRC is verified *after* F7/F8, so a content change with a fixed-up CRC fails at F7/F8, and a content change without a CRC fix-up also fails at F7/F8 first (or F3–F6 earlier), never at F9.

**F10. Stream Footer** (stream_decoder.c lines 313–328; mt lines 1696–1711):
- `lzma_stream_footer_decode` (stream_flags_decoder.c): footer magic `YZ`, CRC32 over Backward Size + Stream Flags.
- `lzma_index_hash_size(index_hash) != footer_flags.backward_size` → `LZMA_DATA_ERROR`. `lzma_index_hash_size` is deliberately computed from `->blocks` (index_hash.c lines 115–119), i.e. the Backward Size is compared to what the Index *should* be given the Blocks, not to what was read.
- `lzma_stream_flags_compare` header vs footer (stream_flags_common.c): check type must match; Backward Size is compared only when known on both sides, which it is not for a header (`backward_size = LZMA_VLI_UNKNOWN`, stream_flags_decoder.c), so this does not re-check the Index size.

## Backward path: checks in the order they fire

`lzma_file_info_decoder` (file_info.c `file_info_decode`), used by `xz --list` (list.c line 364).

**B1. Footer** (SEQ_FOOTER, lines 378–392): `lzma_stream_footer_decode` (magic + CRC32), then `file_target_pos >= backward_size + LZMA_STREAM_HEADER_SIZE` or `LZMA_DATA_ERROR`. Stream Padding before it must be a multiple of 4 (line 337).

**B2. Index decode** with `lzma_index_decoder_init` (index_decoder.c `index_decode`): Indicator (line 82), memlimit vs `lzma_index_memusage(1, count)` (line 100), VLI well-formedness (F2), Unpadded range (line 131), then `lzma_index_append` (index.c lines 640–681) which rejects: uncompressed sum > `LZMA_VLI_MAX`, unpadded sum > `UNPADDED_SIZE_MAX`, projected file size > `LZMA_VLI_MAX` (`index_file_size`), projected Index size > `LZMA_BACKWARD_SIZE_MAX`. Then Index Padding zeros (lines 154–163) and CRC32 (lines 169–188). **No Block-derived cross-check exists here**; CRC32 is the only integrity check and it is attacker-recomputable.

**B3. Index length == Backward Size** (file_info.c lines 475–496): the decoder is fed at most `backward_size` bytes; if it wants more with `index_remaining == 0` → `LZMA_DATA_ERROR`; if it returns `LZMA_STREAM_END` with `index_remaining != 0` → `LZMA_DATA_ERROR`. So the Index byte length must equal the Footer's Backward Size exactly.

**B4. Geometry: Stream Header must sit where the Index says** (lines 509–535, 581–606). `seek_amount = lzma_index_total_size(this_index) + LZMA_STREAM_HEADER_SIZE`, where `total_size` is Σ `vli_ceil4(unpadded)`. If `file_target_pos < seek_amount` → `LZMA_DATA_ERROR`. If it lands at offset 0 the cached first header is reused; otherwise `lzma_stream_header_decode` is run at that offset (magic + CRC32, `hide_format_error` turns magic mismatch into `LZMA_DATA_ERROR`), and `lzma_stream_flags_compare` must match the footer's check type (line 605). If it did not land at 0, the loop continues treating the bytes before as an earlier Stream (lines 662–663), which must itself parse.

**B5. `xz --list -vv` / `--robot -vv` only** (list.c `parse_details` → `parse_block_header`, lines 439–602; called only at `V_DEBUG`, lines 886/907 and 1087): for every Record, reads at `iter->block.compressed_file_offset` (derived from the cumulative Index sums) and requires: first byte `!= 0`; `header_size <= total_size - check_size`; `lzma_block_header_decode` succeeds (header CRC32, block_header_decoder.c line 57); `lzma_block_compressed_size(&block, iter->block.unpadded_size)` succeeds (block_util.c: `unpadded_size > header_size + check_size`, and if the header stores Compressed Size it must equal `unpadded_size - header_size - check_size`); and if the header stores Uncompressed Size it must equal the Record's (list.c lines 516–519). `parse_check_value` only reads and prints the Check bytes; it does not verify them.

Plain `xz -l` and `xz -lv` do none of B5 — they trust the Index after B1–B4.

## Modifications that survive one check but fail a later one

Each item assumes the attacker also recomputes the Index CRC32 (F9/B2 CRC) — if they do not, F9/B2 catch it, but in the forward path F3–F8 fire first anyway.

1. **Change one Record's Uncompressed Size (count, Unpadded, VLI byte length unchanged).** Passes F1–F4 and F6. Fails F5 if the new value pushes the running sum above the Block total, otherwise fails F7 (uncompressed sum). Backward: passes B1–B4 entirely (uncompressed sizes do not affect geometry). Fails B5 only if that Block's header carries an Uncompressed Size field (list.c lines 516–519); if the header has no size fields, `xz --list -vv` reports the lie as fact.

2. **Move Uncompressed Size between two Records keeping the sum (e.g. +N on Record 1, −N on Record 2).** Passes F1–F7 (all three totals unchanged if VLI byte lengths are kept, which requires staying within the same 7-bit-group range). Fails F8 (hash of the ordered pairs). This is the case F8 exists for. Backward: passes B1–B4; B5 catches it only if the affected headers carry Uncompressed Size.

3. **Swap two Records whose VLI encodings have equal total byte length.** Same as (2): all three sums identical, Index Padding and Backward Size unchanged, fails F8. Backward: Σ `ceil4(unpadded)` is unchanged so B4 passes; B5 fails at the first Block whose header-stored Compressed Size disagrees with `unpadded_size - header_size - check_size` (block_util.c `lzma_block_compressed_size`), or whose header CRC32 fails because the computed offset is now inside a different Block's payload.

4. **Change one Unpadded Size by a non-multiple of 4 within the same 4-byte bucket** (e.g. 101 → 103). `vli_ceil4` is equal, so `blocks_size` is unchanged and F5/F7 pass; F8 fails. Backward: B4 passes (total_size unchanged), B5 fails via `lzma_block_compressed_size` if the header stores Compressed Size; if it does not, it passes everything in the backward path. Unpadded Size is not re-derivable without the header's Compressed Size field.

5. **Change a size so the VLI gets a different byte length but pad Index Padding to compensate** (e.g. a size crosses 127→128, growing a VLI by 1 byte, and the attacker removes one padding zero so Index total length is unchanged). Passes F3–F5; F6 passes only if the attacker set the padding length to match the *new* `index_list_size` (which is how F6 is computed); F7 fails on `index_list_size`. Backward: B3 passes (byte length unchanged), B4 fails (if Unpadded changed) or passes (if Uncompressed changed), B5 as above.

6. **Change a size so the VLI byte length changes and the Index's total 4-byte-rounded length changes, with Footer left untouched.** Forward: fails F7 on `index_list_size` (F6 passes if padding is self-consistent). Backward: fails B3 (`index_remaining != 0` or decoder wants more) because Backward Size no longer matches. If the attacker also rewrites Backward Size *and* the Footer CRC32, B3 passes; forward then still fails F7, and additionally F10 (`lzma_index_hash_size` from Blocks ≠ new Backward Size).

7. **Add or remove a Record (count changed).** Forward: fails F3 immediately. Backward: B2 accepts any count within memlimit; B3 fails unless Backward Size + Footer CRC are rewritten; if they are, B4 fails unless the new Σ `ceil4(unpadded)` still equals the real Blocks total — e.g. splitting one Record of Unpadded 2·k into two Records of Unpadded k each, both ≥ 5, keeps `total_size` and passes B4. Then `xz -l`/`-lv` report the fake Block list; B5 fails at the second half because its computed offset points into the middle of the real Block (no valid header CRC there), or because the first half's header-stored Compressed Size disagrees.

8. **Re-encode a VLI non-minimally (same value, extra bytes).** Fails F2 (`lzma_vli_decode`) in both paths before any sum check. Not survivable.

9. **Flip a bit in the Index CRC32 field only.** Forward: passes F1–F8 (content unchanged), fails F9. Backward: fails B2 CRC. Nothing downstream — this is the only modification where the CRC32 is the detecting check.

10. **Modification that passes every check in every path.** From the code read: a change to a Record's Uncompressed Size where (a) the sum over all Records is restored by an opposite change in another Record, (b) all VLI byte lengths are preserved, and (c) the forward decoder is never run, and (d) the affected Blocks' headers do not store Uncompressed Size — passes B1–B5. It is detected the moment anything decompresses the file (F8). I found no check in the backward/`--list` path that detects it; `parse_check_value` does not verify Check values and nothing in file_info.c or list.c decodes Block payloads.

## Summary of independence

| Check | Source of truth | Forward | Backward | `--list -vv` |
|---|---|---|---|---|
| F2 VLI minimality | encoding rule | yes | yes | yes |
| F3 count | Blocks | yes | no | no |
| F7 three sums | Blocks | yes | no | no |
| F8 ordered-pair hash | Blocks | yes | no | no |
| F9/B2 CRC32 | Index itself | yes (last) | yes (only integrity check) | yes |
| F10/B3 Backward Size | Blocks (fwd) / Index byte length (bwd) | yes | yes | yes |
| B4 header-at-offset | Σ ceil4(Unpadded) vs file | no | yes | yes |
| B5 per-Block header | Block Headers' optional size fields | no | no | yes |

The forward path's F7+F8 make Index forgery against an unchanged Block set infeasible up to a hash collision in `LZMA_CHECK_BEST`. The backward path has no Block-derived check at all except geometry (B4), so `xz --list` without `-vv` is fooled by any Index whose `Σ vli_ceil4(Unpadded)` and byte length are right and whose CRC32 was recomputed.
