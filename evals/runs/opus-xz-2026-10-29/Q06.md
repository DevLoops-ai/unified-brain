# Answer

The threaded decoder in `src/liblzma/common/stream_decoder_mt.c` uses two separate limits. A Block that does not fit the soft limit is decoded single-threaded. A Block that does not fit the hard limit stops decoding with `LZMA_MEMLIMIT_ERROR`.

## The two limits

- **`memlimit_threading`** (soft). The struct comment says threaded mode will not go over it, but single-threaded mode can, "even by a large amount" (`struct lzma_stream_coder`). The public docs say it never makes `lzma_code()` return `LZMA_MEMLIMIT_ERROR`; it only reduces the number of threads (`src/liblzma/api/lzma/container.h`, `lzma_mt.memlimit_threading`).
- **`memlimit_stop`** (hard). This is the limit that "should never be exceeded". `LZMA_MEMLIMIT_ERROR` is returned if decoding is not possible even single-threaded (`struct lzma_stream_coder`; `container.h`, `lzma_mt.memlimit_stop`).

`stream_decoder_mt_init()` sets both to at least 1. If `memlimit_threading > memlimit_stop`, it lowers `memlimit_threading` to `memlimit_stop`.

## What the decoder counts (all protected by `coder->mutex`)

- `mem_in_use`: filter-chain memory plus the input buffer of each running worker.
- `mem_cached`: filter memory held by idle worker threads that are kept for reuse.
- `outq.mem_in_use` and `outq.mem_allocated`: output-queue buffers.
- `mem_direct_mode`: the single-threaded decoder (0 when threaded).

When a worker finishes, `worker_stop()` subtracts `in_size` and `mem_filters` from `mem_in_use` and adds `mem_filters` to `mem_cached`. When an idle thread is picked again, `get_thread()` subtracts its `mem_filters` from `mem_cached`.

## Per-Block checks in `stream_decode_mt()`

**1. Block Header state (end of the `SEQ_BLOCK_HEADER` case).** `mem_next_filters = lzma_raw_decoder_memusage(filters)`. If this returns `UINT64_MAX` (unknown filter ID), the result is `LZMA_OPTIONS_ERROR`.

**2. `SEQ_BLOCK_INIT`: hard-limit check.** This is deliberately the first thing in the state:
- If `mem_next_filters > memlimit_stop`, the decoder first calls `read_output_and_wait(..., NULL, true, ...)` to flush pending output.
- If the output queue is still not empty, it returns `LZMA_OK`.
- Once the queue is empty, it returns `LZMA_MEMLIMIT_ERROR`.

So the caller gets all output decoded before the failing Block. Because the check comes first, the caller can raise the limit with `lzma_memlimit_set()` and continue; the comment at that spot says this is the reason for its position.

Note that this hard check compares only the filter-chain memory. It does not include the threaded-mode buffers.

**3. `SEQ_BLOCK_INIT`: deciding threaded vs. direct mode.** The decoder switches to single-threaded mode (`SEQ_BLOCK_DIRECT_INIT`) in three cases:
- The Block Header does not give the compressed or uncompressed size, or a size is greater than `SIZE_MAX / 3`. This is checked by `is_direct_mode_needed()`.
- The total would overflow: `UINT64_MAX - mem_buffers < mem_next_filters`.
- **The Block alone needs more than the soft limit:** `mem_next_block > memlimit_threading`.

Here `mem_next_block = mem_next_filters + comp_blk_size() + lzma_outq_outbuf_memusage(uncompressed_size)`. `comp_blk_size()` is the compressed size rounded up to a multiple of 4, plus the check size. In other words, the whole compressed Block and the whole uncompressed output buffer are counted.

Otherwise the decoder frees any existing direct-mode decoder, sets `mem_direct_mode = 0`, and moves to `SEQ_BLOCK_THR_INIT`.

**4. `SEQ_BLOCK_THR_INIT`: waiting until the Block fits.** It calls `read_output_and_wait(..., &block_can_start, true, ...)`. That function sets `*input_is_possible = true` only when all of these hold:
```c
coder->memlimit_threading - coder->mem_in_use - coder->outq.mem_in_use
        >= coder->mem_next_block
&& lzma_outq_has_buf(&coder->outq)
&& (threads_initialized < threads_max || threads_free != NULL)
```
Until then it keeps copying decoded data to the caller (which frees memory) and blocks on the condition variable, subject to the timeout.

If the caller's output buffer fills before the Block can start, the decoder returns `LZMA_OK` (see the asserts after the call). This wait is how the thread count is reduced in practice: a new Block simply does not start until enough running Blocks have finished.

**5. Freeing cached memory before starting.** The decoder computes `mem_max = memlimit_threading - mem_next_block`. Then:
- If `mem_in_use + mem_cached + outq.mem_allocated > mem_max`, it calls `lzma_outq_clear_cache2()`. This keeps at most one cached output buffer, and only if its size matches this Block.
- If there are idle threads and `mem_in_use + mem_cached + outq.mem_in_use > mem_max`, it frees the cached Block decoders of idle threads with `lzma_next_end()` and subtracts what it freed from `mem_cached`. The first idle thread is kept if its `mem_filters <= mem_next_filters`, so `get_thread()` can reuse its memory.

The comments say both checks assume the worst case.

**6. Reserving and allocating.** Under the mutex, `mem_in_use += mem_next_in + mem_next_filters`. The decoder then:
- preallocates the output buffer (`lzma_outq_prealloc_buf`),
- picks a thread (`get_thread`),
- stores `thr->mem_filters = mem_next_filters`,
- initializes the Block decoder,
- allocates `thr->in` with size `mem_next_in`.

If the preallocation or `get_thread()` fails, it calls `threads_stop()` and returns the error. If the input buffer allocation fails, it calls `threads_stop()` and returns `LZMA_MEM_ERROR`. If Block decoder initialization fails, the error goes through `pending_error` and `SEQ_ERROR`.

## What happens when a Block would exceed the memory

| Situation | Result |
|---|---|
| Fits under `memlimit_threading` now | Decoded by a worker thread right away |
| Fits under `memlimit_threading`, but other running Blocks use too much | Waits in `read_output_and_wait()` (output keeps flowing), then caches are trimmed (step 5) and the Block starts |
| Alone exceeds `memlimit_threading`, or has no sizes in its header | Single-threaded mode (`SEQ_BLOCK_DIRECT_INIT`), described below |
| `mem_next_filters > memlimit_stop` | All earlier output is flushed, then `LZMA_MEMLIMIT_ERROR` (can be resumed after raising the limit) |

**Single-threaded mode in detail (`SEQ_BLOCK_DIRECT_INIT`):**
1. It waits until the output queue is empty.
2. It calls `lzma_outq_clear_cache()` and `threads_end()`, so all worker threads and the thread array are destroyed.
3. It calls `lzma_block_decoder_init()` on `coder->block_decoder`.
4. It sets `mem_direct_mode = mem_next_filters`, so the usage is visible to memconfig.

`SEQ_BLOCK_DIRECT_RUN` then decodes the Block in the caller's thread, streaming. No full input or output buffer is needed, so the soft limit can be passed here, as the docs allow. For a later Block that fits, step 3 frees the direct decoder and threaded mode resumes.

## Getting and setting the limit at runtime (`stream_decoder_mt_memconfig()`)

- It reports memory usage as `mem_direct_mode + mem_in_use + mem_cached + outq.mem_allocated`, never less than `LZMA_MEMUSAGE_BASE`. Cached memory is deliberately included.
- It gets and sets **only `memlimit_stop`**. The comment says `memlimit_threading` cannot be changed after initialization.
- A new limit below current usage (cached memory included) is rejected with `LZMA_MEMLIMIT_ERROR`. Cached memory is not freed to make room.
