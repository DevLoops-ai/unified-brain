# Answer

Sandboxing exists only in the two command-line tools: `xz` and `xzdec` (`lzmadec` is built from the same `xzdec.c`). The library liblzma has no sandboxing code. Exactly one of three OS mechanisms is chosen when the project is built: **Capsicum on FreeBSD, pledge(2) on OpenBSD, Landlock on Linux**. Every other platform (Windows, macOS and so on) runs without a sandbox, because no code path exists for it.

## 1. How the method is chosen at build time

**Autotools, `configure.ac`:**
- The option is `--enable-sandbox=auto|no|capsicum|pledge|landlock` (lines 551–573). The default is `auto`. It is forced to `no` when both `xz` and `xzdec` are disabled.
- The probes run in this order (lines 1161–1206): `AC_CHECK_FUNCS([cap_rights_limit])` → `AC_CHECK_FUNCS([pledge])` → a Landlock link test.
- Each probe only runs while `$enable_sandbox` is still `auto` or names that method. A successful probe sets `enable_sandbox=found`, so in `auto` mode only the first match is used.
- The Landlock test checks for `PR_SET_NO_NEW_PRIVS`, `SYS_landlock_create_ruleset`, `SYS_landlock_restrict_self` and `LANDLOCK_CREATE_RULESET_VERSION`. A comment explains why: some systems have the header but not the syscalls. On success it defines `HAVE_LINUX_LANDLOCK`.
- If Landlock is found and `CFLAGS` contains `-fsanitize=`, configure stops with an error. The comment at lines 1151–1160 says Landlock is the only one of the three methods that does not work with sanitizers.
- If a method was requested explicitly and not found, configure fails: `"$enable_sandbox support not found"` (lines 1208–1216).

**CMake, `CMakeLists.txt`:**
- The option is the cache variable `XZ_SANDBOX` (lines 1740–1757). The comments give minimum versions: Capsicum needs FreeBSD ≥ 10.2, pledge needs OpenBSD ≥ 5.9, Landlock needs Linux ≥ 5.13.
- The probes run in the same order, each guarded by `NOT SANDBOX_FOUND` (lines 1772–1836).
- The single result goes into `SANDBOX_COMPILE_DEFINITION`. It is added to the `xzdec`/`lzmadec` targets (lines 1890–1892) and to the `xz` target (lines 2048–2049).
- If a requested method is not found, CMake reports `SEND_ERROR` (lines 1838–1840).

**Compile-time switch in the sources:** `ENABLE_SANDBOX` is defined when any of `HAVE_PLEDGE`, `HAVE_LINUX_LANDLOCK` or `HAVE_CAP_RIGHTS_LIMIT` is defined. This happens in `src/xz/sandbox.h` (lines 12–15) and `src/xzdec/xzdec.c` (lines 38–41).

## 2. `xz`: three stages (`src/xz/sandbox.c`, `main.c`, `file_io.c`)

The interface is in `sandbox.h`: `sandbox_init()`, `sandbox_enable_read_only()`, `sandbox_allow_strict()` and `sandbox_enable_strict_if_allowed(src_fd, pipe_event_fd, pipe_write_fd)`. `sandbox.c` has one `#if defined(HAVE_PLEDGE) / #elif HAVE_LINUX_LANDLOCK / #elif HAVE_CAP_RIGHTS_LIMIT` chain. Note that this order (pledge first) differs from the probe order (Capsicum first), but only one macro is ever defined, so this has no effect.

**Where each stage is called:**
1. **Stage 1, always on.** `main()` calls `sandbox_init()` right after `tuklib_progname_init()` and `io_init()`, before gettext is set up (`main.c` lines 158–170).
2. **Stage 2, read-only.** After argument parsing and `signals_init()`, `main()` computes `to_stdout_only` (`main.c` lines 225–261). It is true if any of these holds:
   - `--stdout` was used,
   - `MODE_LIST` (`--list`) is active,
   - `--files`/`--files0` was not used and every filename argument is `"-"`.
   If true, `main()` calls `sandbox_enable_read_only()`. If, in addition, `args.files_name == NULL && args.arg_count == 1`, it calls `sandbox_allow_strict()`. That function only sets the static flag `strict_sandbox_allowed`.
3. **Stage 3, strict.** `io_open_src()` (`file_io.c` lines 723–727) calls `sandbox_enable_strict_if_allowed(pair.src_fd, user_abort_pipe[0], user_abort_pipe[1])` after the input file is opened successfully. Before tightening, `prepare_for_strict_sandbox()` returns false unless the flag is set. It then tries to preload files that would otherwise be opened later: it calls `_()` and `strerror()` through `snprintf(NULL, 0, ...)` to load locale/NLS data, and `tuklib_mbstr_width()` to load iconv data.

**What each backend does at each stage:**

| Stage | pledge (OpenBSD) | Landlock (Linux) | Capsicum (FreeBSD) |
|---|---|---|---|
| `sandbox_init` | `pledge("stdio rpath wpath cpath fattr", "")` | `prctl(PR_SET_NO_NEW_PRIVS)` (return value ignored), reads the kernel ABI version, then `enable_landlock(WRITE_FILE\|READ_FILE\|READ_DIR\|REMOVE_FILE\|MAKE_REG)` | does nothing |
| `sandbox_enable_read_only` | `pledge("stdio rpath", "")` | `enable_landlock(READ_FILE\|READ_DIR)` | does nothing |
| `sandbox_enable_strict_if_allowed` | `pledge("stdio", "")` | `enable_landlock(0)`, which restricts everything the ABI supports | `cap_enter()`, then `cap_rights_limit` on each descriptor (see below) |

**Landlock details (`enable_landlock()` and `sandbox_init()`):**
- `LANDLOCK_ABI_MAX` is 4 if the installed header defines `LANDLOCK_ACCESS_NET_BIND_TCP`, otherwise 3. The kernel's ABI version is capped at that value.
- `handled_access_fs = ~required_rights & ((1ULL << (12 + min(3, abi))) - 1)`. In words: every filesystem right the ABI knows about is restricted, except the ones passed in as required.
- On ABI ≥ 4, `handled_access_net` also restricts TCP bind and connect.
- No `landlock_add_rule` calls are made. The code relies on all needed files already being open. A NOTE in the source admits the preload trick may not be enough, in which case a rule allowing reads from `/usr` or the install prefix might be needed.
- Truncate rights are not needed because output files are created with `O_EXCL` and without `O_TRUNC`.
- `READ_DIR` is kept at stage 1 so that passing a directory gives "Is a directory, skipping" instead of "Permission denied". Commit `de4337fd` changed this.
- If the ABI version is ≤ 0 (kernel without Landlock), `enable_landlock()` simply returns and the program runs unsandboxed.

**Capsicum details (`sandbox_enable_strict_if_allowed()`):** after `cap_enter()`, each descriptor keeps only these rights:
- source fd: `EVENT|FCNTL|LOOKUP|READ|SEEK`
- stdin, when it is not the source: all rights removed
- stdout: `EVENT|FCNTL|FSTAT|LOOKUP|WRITE|SEEK`
- stderr: `WRITE`
- the two ends of the abort pipe (`user_abort_pipe`): `EVENT` on `[0]`, `WRITE` on `[1]`

**Failure behaviour:** any backend failure calls `message_fatal("Failed to enable the sandbox")`. The one exception is Capsicum failing with `errno == ENOSYS` (kernel or emulator without capability mode): `xz` then continues silently without a sandbox.

## 3. `xzdec`/`lzmadec`: simpler, inline (`src/xzdec/xzdec.c`)

- **At startup, in `main()`:**
  - OpenBSD: `pledge("stdio rpath", "")`, so files can still be opened (lines 394–405).
  - Linux: only `prctl(PR_SET_NO_NEW_PRIVS)` (lines 407–417). No Landlock ruleset is applied yet.
  - FreeBSD: nothing.
- **Strict stage, `sandbox_enter(src_fd)` (lines 302–388):**
  - Capsicum: `cap_enter()`; source fd gets `CAP_READ`; stdin is cleared if it is not the source; stdout and stderr get `CAP_WRITE`.
  - pledge: `pledge("stdio", "")`.
  - Landlock: a ruleset restricting every filesystem right the ABI supports (plus TCP bind/connect on ABI ≥ 4), then `landlock_restrict_self`. As in `xz`, this is skipped when the ABI version is ≤ 0.
  - If `ENABLE_SANDBOX` is defined but no method matches, the build stops with `#error`.
- **When the strict stage is entered:** when there are no file arguments, it is entered before decoding stdin (lines 436–441). Otherwise it is entered only for the **last** file on the command line (`optind == argc - 1`, lines 461–469). Earlier files are decoded with only the startup protection.
- **Failure behaviour:** `my_errorf("Failed to enable the sandbox")` followed by `exit(EXIT_FAILURE)`. As in `xz`, Capsicum `ENOSYS` is tolerated.

## 4. Things worth knowing

- **Capsicum in `xz` is all-or-nothing.** On FreeBSD, `xz` has no early or read-only stage. The sandbox exists only in the strict single-file-to-stdout case. pledge and Landlock restrict the process from startup.
- **The strict stage in `xz` needs all of these:** output only to stdout (`--stdout`, `--test`, `--list`, or all inputs are `"-"`), exactly one argument, and no `--files`/`--files0`. `INSTALL` (around line 593) describes this as the common case, for example GNU tar piping `.tar.xz` files.
- **`INSTALL` is shorter than the code.** It says the sandbox is used "when (de)compressing exactly one file to standard output". It does not mention the always-on `sandbox_init()` stage or the multi-file read-only stage that `xz` now applies under pledge and Landlock.
