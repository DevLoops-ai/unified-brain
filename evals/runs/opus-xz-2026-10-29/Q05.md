# Answer

After a Stream Footer checks out, the decoder skips `0x00` bytes and counts them modulo 4. The first non-zero byte is taken to be the start of another Stream. There is no separate test for garbage: garbage is whatever then fails Stream Header decoding. This only happens when `LZMA_CONCATENATED` is set.

## 1. The concatenated path exists only with `LZMA_CONCATENATED`

- **Flag off:** `stream_decode()` (`src/liblzma/common/stream_decoder.c`, case `SEQ_STREAM_FOOTER`) returns `LZMA_STREAM_END` right after the footer is validated (`if (!coder->concatenated) return LZMA_STREAM_END;`). liblzma does not look at any bytes after the footer; they stay unread in `avail_in`.
- **Flag on:** the state moves to `SEQ_STREAM_PADDING`.
- **API rule:** with the flag set, `lzma_code()` returns `LZMA_STREAM_END` only when the action is `LZMA_FINISH` (doc comment for `LZMA_CONCATENATED`, `src/liblzma/api/lzma/container.h`).

Before that state is reached, the footer checks in `SEQ_STREAM_FOOTER` can already fail:
- Footer magic mismatch: `lzma_stream_footer_decode()` returns `LZMA_FORMAT_ERROR`, which is turned into `LZMA_DATA_ERROR`.
- Footer CRC32 mismatch: `LZMA_DATA_ERROR`.
- Reserved bits set in the footer flags: `LZMA_OPTIONS_ERROR`.
- Index size different from Backward Size: `LZMA_DATA_ERROR`.
- Header and footer Stream Flags differ: whatever `lzma_stream_flags_compare()` returns.

## 2. `SEQ_STREAM_PADDING` (`stream_decode()`)

`coder->pos` is reused as the padding counter, modulo 4. It is 0 on entry because the footer copy resets it.

- **A `0x00` byte:** consumed; `pos = (pos + 1) & 3`.
- **Input runs out:**
  - action is not `LZMA_FINISH`: returns `LZMA_OK`, because more input may still come;
  - action is `LZMA_FINISH` and `pos == 0`: returns `LZMA_STREAM_END`. This covers valid padding and empty padding;
  - action is `LZMA_FINISH` and `pos != 0`: returns `LZMA_DATA_ERROR` (padding is not a multiple of 4).
- **A non-zero byte:** the loop stops.
  - If `pos != 0`: the bad byte is consumed (`++*in_pos`) and `LZMA_DATA_ERROR` is returned.
  - If `pos == 0`: the byte is not consumed. `stream_decoder_reset()` re-initializes the Index hash and sets `sequence = SEQ_STREAM_HEADER` and `pos = 0`. That byte becomes the first byte of the next Stream Header.

## 3. Next Stream or trailing garbage: `SEQ_STREAM_HEADER`

The decoder copies 12 bytes (`LZMA_STREAM_HEADER_SIZE`) and calls `lzma_stream_header_decode()` (`src/liblzma/common/stream_flags_decoder.c`). The checks run in this order:

1. Magic bytes mismatch: `LZMA_FORMAT_ERROR`.
2. CRC32 mismatch: `LZMA_DATA_ERROR`. This check is compiled out under `FUZZING_BUILD_MODE_UNSAFE_FOR_PRODUCTION`.
3. Reserved flag bits set (`in[0] != 0` or `in[1] & 0xF0`, in `stream_flags_decode()`): `LZMA_OPTIONS_ERROR`.

`stream_decode()` turns `LZMA_FORMAT_ERROR` into `LZMA_DATA_ERROR` when `!coder->first_stream`. `first_stream` is set to `true` only in `lzma_stream_decoder_init()`, set to `false` after the first header decodes, and never reset by `stream_decoder_reset()`. So:
- Garbage after a valid Stream gives `LZMA_DATA_ERROR`, never `LZMA_FORMAT_ERROR`.
- `LZMA_OPTIONS_ERROR` passes through unchanged. Garbage that happens to have the right magic and CRC but reserved bits set reports as "unsupported", not "corrupt".

The test-file notes in `tests/files/README` describe the same behaviour:
- `bad-0cat-header_magic.xz` gives `LZMA_DATA_ERROR`; `LZMA_FORMAT_ERROR` is used only for the first Stream.
- `bad-0cat-alone.xz` is an `.xz` file followed by an LZMA_Alone file.
- `bad-0pad-empty.xz` and `bad-0catpad-empty.xz` have 5-byte padding (corrupt).
- `good-0pad-empty.xz`, `good-0cat-empty.xz` and `good-0catpad-empty.xz` are valid.

History: `8e60c889` "Fixed Stream decoder to actually use the first_stream variable." The padding check took its current form in `80c4158f` "Stream decoder cleanups".

## 4. Edge cases that follow from this

- **Garbage made only of zeros, with length a multiple of 4:** accepted as valid padding. The format cannot tell it apart from real padding.
- **Garbage starting with zeros:** the zero run is counted as padding. At the first non-zero byte, either the length check fails (`LZMA_DATA_ERROR`) or header decoding fails (normally `LZMA_DATA_ERROR`).
- **Non-zero garbage shorter than 12 bytes, at end of input:** `SEQ_STREAM_HEADER` returns `LZMA_OK` whenever `pos < 12`, even with `LZMA_FINISH`. `lzma_code()` (`src/liblzma/common/common.c`) turns a second call that makes no progress (`in_pos == 0 && out_pos == 0` with `allow_buf_error` already set) into `LZMA_BUF_ERROR`. So a short tail, or a cut-off second Stream, ends as `LZMA_BUF_ERROR`, not `LZMA_DATA_ERROR`.
- **Multi-threaded decoder:** `stream_decoder_mt.c` (`stream_decode_mt()`) has the same `SEQ_STREAM_PADDING` logic and the same `first_stream` conversion. The only difference is that it also increments `coder->progress_in`.

## 5. What the `xz` command-line tool adds (`src/xz/coder.c`)

- `coder_init()`:
  - with `--single-stream`, it sets `allow_trailing_input = true` and does **not** pass `LZMA_CONCATENATED`;
  - otherwise it passes `LZMA_CONCATENATED`;
  - `.lz` input also sets `allow_trailing_input = true`.
- `coder_normal()`, on `LZMA_STREAM_END`:
  - if trailing input is allowed, it calls `io_fix_src_pos()` and succeeds, leaving the rest of the file unread;
  - otherwise, if `avail_in` is 0 and end of file has not been seen, it tries to read one more byte. Any input still left turns the result into `LZMA_DATA_ERROR`.
- The source comment says this check is needed for LZMA_Alone and raw streams. With `LZMA_CONCATENATED`, liblzma itself has already handled anything after the footer.
