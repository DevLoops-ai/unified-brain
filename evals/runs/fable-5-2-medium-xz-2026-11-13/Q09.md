# Q9 — End of Stream 1 to start of Stream 2 in the threaded .xz decoder (commit 7baf6835)

All paths are under `/tmp/xzfresh/xz`. The main file is `src/liblzma/common/stream_decoder_mt.c` (function `stream_decode_mt()`); "main thread" means the thread that calls `lzma_code()`.

## 0. How xz gets onto this path

- `src/xz/coder.c`, `coder_init()`: flags are `LZMA_TELL_UNSUPPORTED_CHECK` (or `LZMA_IGNORE_CHECK` with `--ignore-check`) plus `LZMA_CONCATENATED`, unless `--single-stream` (then `allow_trailing_input = true` and no `LZMA_CONCATENATED`). xz never sets `LZMA_FAIL_FAST`.
- With `MYTHREAD_ENABLED`, xz always calls `lzma_stream_decoder_mt()` with `threads = hardware_threads_get()`, `memlimit_stop = hardware_memlimit_get(MODE_DECOMPRESS)` (hard limit, `--memlimit-decompress`; `UINT64_MAX` if not set) and `memlimit_threading = hardware_memlimit_mtdec_get()` (soft limit, `--memlimit-mt-decompress`; default `total_ram / 4`, capped to 1400 MiB on 32-bit, capped to the hard limit). If `threads == 1` it passes `memlimit_threading = 0`. `timeout = 300` ms.
- `stream_decoder_mt_init()` clamps `memlimit_threading` to `memlimit_stop` and turns 0 into 1.
- `coder_normal()` calls `lzma_code()` with `LZMA_RUN`, and `LZMA_FINISH` once `pair->src_eof` is true.

## 1. The normal path

States of `coder->sequence`: `SEQ_STREAM_HEADER, SEQ_BLOCK_HEADER, SEQ_BLOCK_INIT, SEQ_BLOCK_THR_INIT, SEQ_BLOCK_THR_RUN, SEQ_BLOCK_DIRECT_INIT, SEQ_BLOCK_DIRECT_RUN, SEQ_INDEX_WAIT_OUTPUT, SEQ_INDEX_DECODE, SEQ_STREAM_FOOTER, SEQ_STREAM_PADDING, SEQ_ERROR`.

**a) Finishing the last Block (threaded mode).**
- Main thread, `SEQ_BLOCK_THR_RUN`: copies the Block's bytes into `thr->in`. The buffer size is `comp_blk_size()` = `vli_ceil4(compressed_size) + lzma_check_size(check)`, taken from the Block Header. When `in_filled == in_size` it sets `coder->thr = NULL` and goes to `SEQ_BLOCK_HEADER`. So the main thread moves past the Block before the Block is decoded.
- Worker, `worker_decoder()` → `block_decode()` in `block_decoder.c`:
  - `SEQ_CODE`: runs the filter chain; at the end `is_size_valid()` compares the real compressed and uncompressed sizes with the Block Header values (`LZMA_DATA_ERROR` on mismatch).
  - `SEQ_PADDING`: Block Padding bytes must be `0x00`.
  - `SEQ_CHECK`: copies the Check field into `block->raw_check` and `memcmp`s it with the calculated value. Skipped if `ignore_check`, if the Check type is unsupported, or if the type is `LZMA_CHECK_NONE`.
- The worker then stores the result under `coder->mutex`: `outbuf->finished = true`, `outbuf->finish_ret = ret`, `coder->thread_error = ret` if it is an error, adds progress, and calls `worker_stop()` (memory counters `mem_in_use` → `mem_cached`, thread pushed on `threads_free`, `coder->cond` signalled).

**b) Finding the Index.** `SEQ_BLOCK_HEADER` → `decode_block_header()`: if the next byte is `INDEX_INDICATOR` (0x00) it returns `LZMA_INDEX_DETECTED` without consuming the byte → `SEQ_INDEX_WAIT_OUTPUT`.

**c) Waiting for the workers.** `SEQ_INDEX_WAIT_OUTPUT` calls `read_output_and_wait(..., NULL, true, ...)` and returns `LZMA_OK` until `lzma_outq_is_empty()`. `lzma_outq_read()` (`outqueue.c`) returns each finished buffer's `finish_ret` in Block order, so a worker's Check or data error is returned here, after the output before it has been copied out. Only when the queue is empty does the state become `SEQ_INDEX_DECODE`.

**d) Index.** `lzma_index_hash_decode()` in `index_hash.c`, with its own states `SEQ_BLOCK, SEQ_COUNT, SEQ_UNPADDED, SEQ_UNCOMPRESSED, SEQ_PADDING_INIT, SEQ_PADDING, SEQ_CRC32`. On `LZMA_STREAM_END` → `SEQ_STREAM_FOOTER`.

**e) Footer.** `SEQ_STREAM_FOOTER` collects 12 bytes in `coder->buffer`, then:
1. `lzma_stream_footer_decode()` (`stream_flags_decoder.c`): magic `59 5A` (`LZMA_FORMAT_ERROR`, converted to `LZMA_DATA_ERROR`), CRC32 (`LZMA_DATA_ERROR`), reserved Stream Flags bits (`LZMA_OPTIONS_ERROR`), Backward Size = `(stored + 1) * 4`.
2. `lzma_index_hash_size(coder->index_hash) != footer_flags.backward_size` → `LZMA_DATA_ERROR`.
3. `lzma_stream_flags_compare(&coder->stream_flags, &footer_flags)`: Check type of Header vs Footer (`LZMA_DATA_ERROR`).
4. If `!coder->concatenated` → `LZMA_STREAM_END`. Otherwise → `SEQ_STREAM_PADDING`.

**f) Padding.** `SEQ_STREAM_PADDING` eats `0x00` bytes and keeps `coder->pos = (pos + 1) & 3`. A non-zero byte with `pos == 0` means "new Stream": `stream_decoder_reset()` re-initialises `index_hash` (`lzma_index_hash_init()`), sets `SEQ_STREAM_HEADER`, `pos = 0`.

**g) Next Stream Header.** `SEQ_STREAM_HEADER` collects 12 bytes, `lzma_stream_header_decode()` checks magic, CRC32, reserved bits. Then `first_stream = false`, `block_options.check = stream_flags.check`, state `SEQ_BLOCK_HEADER`. It may return `LZMA_UNSUPPORTED_CHECK` (xz prints a warning and continues).

**h) Back into Block decoding.** `SEQ_BLOCK_HEADER` (`lzma_block_header_decode()`, then `lzma_raw_decoder_memusage()` → `mem_next_filters`) → `SEQ_BLOCK_INIT` (memory decisions, section 4) → `SEQ_BLOCK_THR_INIT`/`SEQ_BLOCK_THR_RUN` or `SEQ_BLOCK_DIRECT_INIT`/`SEQ_BLOCK_DIRECT_RUN`.

## 2. The state that connects the stages

- **`coder->index_hash`** (`lzma_index_hash`) is the only link between Blocks and Index. It has two `lzma_index_hash_info` records, `blocks` and `records`, each with `blocks_size` (sum of `vli_ceil4(unpadded)`), `uncompressed_size`, `count`, `index_list_size` (sum of VLI byte lengths) and a `LZMA_CHECK_BEST` hash over the `(unpadded, uncompressed)` pairs (SHA-256, else CRC64, else CRC32, by build config, `check/check.h`).
  - Threaded Blocks: `lzma_index_hash_append()` is called in `SEQ_BLOCK_INIT`, **before** the Block is decoded, with `lzma_block_unpadded_size(&coder->block_options)` and the header's Uncompressed Size. The worker's Block decoder later proves those numbers true.
  - Direct-mode Blocks: the append happens in `SEQ_BLOCK_DIRECT_RUN` after the Block decoder returns `LZMA_STREAM_END` (the Block decoder writes the real sizes back into `coder->block_options`).
- **`coder->stream_flags`** (from the Stream Header) → gives the Check type to every Block and is compared with the Footer.
- **`lzma_index_hash_size()`** is computed from `blocks.count` and `blocks.index_list_size` (the Blocks, not the Index bytes) and is compared with Backward Size.
- **`coder->pos`** is reused: fill position of `coder->buffer` for headers/footer, and the mod-4 counter in padding.
- **`coder->first_stream`** changes the error code for a bad magic in later Streams.
- From the workers: `outbuf->finish_ret`, `coder->thread_error`, `coder->pending_error`, and the memory counters `mem_in_use`, `mem_cached`, `outq.mem_in_use`.

## 3. Failure cases

General rules that apply to all of them:
- Any return other than `LZMA_OK`, `LZMA_STREAM_END`, `LZMA_NO_CHECK`, `LZMA_UNSUPPORTED_CHECK`, `LZMA_GET_CHECK`, `LZMA_MEMLIMIT_ERROR`, `LZMA_TIMED_OUT` makes `lzma_code()` (`common.c`) set `ISEQ_ERROR`; later calls return `LZMA_PROG_ERROR`. So after `LZMA_DATA_ERROR` more input cannot change anything.
- "Needs more input" is `LZMA_OK`. If a call uses no input and gives no output twice in a row, `lzma_code()` returns `LZMA_BUF_ERROR` (xz: "Unexpected end of input"). `LZMA_DATA_ERROR` is "Compressed data is corrupt" (`message_strm()`).
- In all cases below the workers are already idle and the queue is empty (because of `SEQ_INDEX_WAIT_OUTPUT`), so the error is returned directly, not through `SEQ_ERROR`.

**3.1 Index Record with plausible but wrong sizes** — state `SEQ_INDEX_DECODE`, in `lzma_index_hash_decode()`. Not a CRC matter: the Index CRC32 is checked last (`SEQ_CRC32`), after all the cross-checks, so recomputing it does not help.
- Number of Records ≠ `blocks.count` → `LZMA_DATA_ERROR` at `SEQ_COUNT`.
- Unpadded Size outside `UNPADDED_SIZE_MIN (5)..UNPADDED_SIZE_MAX` → error at `SEQ_UNPADDED`.
- After each Record, `hash_append(&records, ...)`; if any running sum of `records` is larger than that of `blocks` → error immediately.
- After the last Record and the Index Padding (length derived from the Records, each byte must be 0): the three sums must be equal, then the two hashes are finished and `memcmp`'d. The hash catches changes that keep the sums equal (for example swapping sizes between two Blocks).
- Non-minimal VLI encodings are rejected in `lzma_vli_decode()` (`vli_decoder.c`).
- The final comparison runs when at least one more input byte is present (the loop is `while (*in_pos < in_size)`), but that byte's value does not matter.
- Result: `LZMA_DATA_ERROR`.
- Caught by CRC only: a changed Index with a stale CRC32 (`tests/files/bad-2-index-4.xz`).

**3.2 Index valid, Backward Size disagrees** — state `SEQ_STREAM_FOOTER`, detected only when all 12 Footer bytes are in `coder->buffer`. With a recomputed Footer CRC32 the CRC step passes; the check `lzma_index_hash_size() != footer_flags.backward_size` returns `LZMA_DATA_ERROR`. Same for a changed Check type in the Footer (`lzma_stream_flags_compare()`), a wrong footer magic (`LZMA_FORMAT_ERROR` → `LZMA_DATA_ERROR`), and reserved bits (`LZMA_OPTIONS_ERROR`). CRC only: stale Footer CRC.

**3.3 Stream Padding** — state `SEQ_STREAM_PADDING`, only with `LZMA_CONCATENATED`. No CRC exists here; all checks are structural.
- Non-zero byte when `pos != 0` (padding length not a multiple of 4 before the next Stream): the byte is consumed, `LZMA_DATA_ERROR`.
- Input ends: with `LZMA_RUN` → `LZMA_OK` (more input can still fix or break it). With `LZMA_FINISH` → `LZMA_STREAM_END` if `pos == 0`, else `LZMA_DATA_ERROR`.
- Non-zero byte when `pos == 0`: it is not judged here. It is taken as the first byte of a Stream Header (case 3.4).

**3.4 Partial or invalid next Stream Header** — state `SEQ_STREAM_HEADER`, `first_stream == false`.
- The magic is not checked byte by byte; the decoder waits for all 12 bytes. Fewer than 12 bytes before end of file: `LZMA_OK`, and then `lzma_code()` gives `LZMA_BUF_ERROR`. So short trailing garbage is reported as truncation, not corruption. Until `LZMA_BUF_ERROR` is returned, more input can change the result.
- 12 bytes, bad magic: `LZMA_FORMAT_ERROR` converted to `LZMA_DATA_ERROR` (only the first Stream gives `LZMA_FORMAT_ERROR`).
- Good magic, bad CRC32: `LZMA_DATA_ERROR` (CRC only). Reserved bits with recomputed CRC: `LZMA_OPTIONS_ERROR`.
- Valid header, then a bad Block Header: `decode_block_header()`; errors go to `pending_error` + `SEQ_ERROR`, which returns `pending_error` at once because the queue is empty.
- The first Stream's output has already been delivered and verified in all these cases.

**3.5 Without `LZMA_CONCATENATED` (`xz --single-stream`)**: `SEQ_STREAM_FOOTER` returns `LZMA_STREAM_END`; padding and the next Stream are never looked at by liblzma. xz then does `io_fix_src_pos()` and reports success (`allow_trailing_input`). Cases 3.3 and 3.4 are therefore not detected; 3.1 and 3.2 are detected the same way. Also, with `LZMA_CONCATENATED`, `LZMA_STREAM_END` only comes with `LZMA_FINISH` (API note in `src/liblzma/api/lzma/container.h`).

## 4. Threads and memory limits

**What must wait for workers.** Index, Footer, Padding and the next Stream Header are all processed only after `SEQ_INDEX_WAIT_OUTPUT` has seen an empty queue: every Block of Stream 1 is decoded, size-checked, Check-verified, and its output copied to the caller. This needs output space (it returns `LZMA_OK` while the caller's buffer is full). Blocks of Stream 2 never run in parallel with Blocks of Stream 1.

**What survives until Index verification.** Only `coder->index_hash` (main-thread state, O(1) memory) and `coder->stream_flags`. Workers pass back no sizes: `lzma_outq_read()` is called with `NULL, NULL` for the size outputs. What they pass back is `finish_ret`/`thread_error`. Because the hash is fed from the Block Header before decoding, the Index check is only meaningful after the worker has confirmed the header sizes — which is what the wait guarantees.

**Error order.** Without `LZMA_FAIL_FAST`, a worker error sets `pending_error = LZMA_PROG_ERROR` as a flag only; the real code comes from `lzma_outq_read()` at the right place in the output. With `LZMA_FAIL_FAST`, `thread_error` is returned at once. Any error return from `read_output_and_wait()` calls `threads_stop()`.

**Next Block is valid but memory is short** (`SEQ_BLOCK_INIT`), three different outcomes:
1. **Impossible under the hard limit**: `mem_next_filters > memlimit_stop`. The queue is flushed first, then `LZMA_MEMLIMIT_ERROR`. This is not fatal in `lzma_code()`; the state stays `SEQ_BLOCK_INIT` (before the hash append), so `lzma_memlimit_set()` + `lzma_code()` can resume. xz treats it as fatal: "Memory usage limit reached" plus `message_mem_needed(lzma_memusage())`. Note: `stream_decoder_mt_memconfig()` sums `mem_direct_mode + mem_in_use + mem_cached + outq.mem_allocated` and does not include `mem_next_filters`. Only the filter chain memory is compared with the hard limit, not the buffers.
2. **Cannot be threaded at all** (soft limit): `mem_next_block` (= filters + input buffer + output buffer) `> memlimit_threading`, or sizes missing in the Block Header, or size `> SIZE_MAX / 3` (`is_direct_mode_needed()`, matters on 32-bit), or the sum overflows. → `SEQ_BLOCK_DIRECT_INIT`: wait for an empty queue, `lzma_outq_clear_cache()`, `threads_end()` (all workers joined), Block decoder in the main thread, `mem_direct_mode = mem_next_filters`. No error; the soft limit may be exceeded. The Index hash is fed after decoding.
3. **Fits, but not right now**: `SEQ_BLOCK_THR_INIT` waits in `read_output_and_wait(&block_can_start, ...)` until `memlimit_threading - mem_in_use - outq.mem_in_use >= mem_next_block`, a queue slot is free and a thread is free or can be created. Then it trims caches (`lzma_outq_clear_cache2()`, freeing cached Block decoders of idle threads). This only delays the Block. For the first Block of a new Stream the queue is empty and no worker is running, so it can start immediately; the wait matters for later Blocks.

In all three, Stream 1 has already completed normally; the outcome only affects Stream 2. If Stream 2 then finishes, the same Index/Footer path runs again with the fresh `index_hash`.

## 6. Differences by build or mode

- No `MYTHREAD_ENABLED`: xz uses `lzma_stream_decoder()` (`stream_decoder.c`). Same Index/Footer/Padding/Header code, but no `SEQ_INDEX_WAIT_OUTPUT`, the hash is always fed after the Block, and there is one limit (`memusage > memlimit` → `LZMA_MEMLIMIT_ERROR`). `xzdec` always uses this decoder with `LZMA_CONCATENATED` and `UINT64_MAX`.
- `threads == 1` in xz: `memlimit_threading` becomes 1, so every Block goes through direct mode.
- Files without sizes in Block Headers (made by single-threaded xz, per the comment in `coder.c`): always direct mode.
- `FUZZING_BUILD_MODE_UNSAFE_FOR_PRODUCTION`: the CRC32 checks of Index, Stream Header, Stream Footer and Block Header are compiled out; the structural checks stay.
- `--ignore-check` or an unsupported Check type: the Block Check is not verified; everything else is unchanged.
- xz's 300 ms timeout: `LZMA_TIMED_OUT` from `read_output_and_wait()` becomes `LZMA_OK` in `lzma_code()`.
