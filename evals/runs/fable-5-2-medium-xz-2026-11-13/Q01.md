# When does the build emit the `.note.GNU-stack` section?

## Short answer

The section is written explicitly in only two places in the tree, both hand-written 32-bit x86 assembly files:

- `src/liblzma/check/crc32_x86.S` (line 307)
- `src/liblzma/check/crc64_x86.S` (line 290)

Each file ends with the same guarded directive:

```
#if defined(__ELF__) && (defined(__FreeBSD__) || defined(__linux__))
	.section	.note.GNU-stack,"",@progbits
#endif
```

So two layers of conditions must both hold: (1) the preprocessor guard inside the file, and (2) the build system must actually compile that `.S` file.

## Layer 1: preprocessor guard in the `.S` files

All of these must be true when the file is preprocessed:

- `__ELF__` is defined (ELF object format), and
- `__FreeBSD__` or `__linux__` is defined.

The comment above the guard says the note is needed to support a non-executable stack, and that testing `__FreeBSD__` / `__linux__` is an "ugly" stand-in because the author knows no way to detect GNU assembler directly. The section is emitted with empty flags (`""`, so not executable) and type `@progbits`.

Consequence: on other targets where the files are still built (NetBSD, OpenBSD, MirBSD, GNU/Hurd, MinGW, Cygwin, MSYS, DJGPP, Darwin) the directive is not emitted, even on the ELF ones.

## Layer 2: the `.S` files must be part of the build

### Autotools (`configure.ac` lines 342-374, `src/liblzma/check/Makefile.inc`)

- `--enable-assembler` defaults to `yes`. With `yes`, it is first reset to `no`, then set to `x86` only if `$host_os` matches `linux* | *bsd* | mingw* | cygwin | msys | *djgpp*` AND `$host_cpu` matches `i?86`.
- Passing `--enable-assembler=x86` forces it on regardless of the host triplet; `--disable-assembler` turns it off. Any other value is a configure error.
- `x86` defines `HAVE_CRC_X86_ASM` and sets the Automake conditional `COND_ASM_X86`.
- In `Makefile.inc`:
  - `crc32_x86.S` is added only if `COND_SMALL` is false (no `--enable-small`) and `COND_ASM_X86` is true.
  - `crc64_x86.S` is added only if `COND_CHECK_CRC64` is true (crc64 check enabled), `COND_SMALL` is false, and `COND_ASM_X86` is true.

`INSTALL` (section 5.3) confirms the decision is made from the configure triplet only; there is no test that the assembly actually builds.

### CMake (`CMakeLists.txt` lines 233-256, 718-720, 736-737)

- The whole block is skipped for `MSVC`.
- Option `XZ_ASM_I386`. Its default comes from `check_symbol_exists("__i386__" ...)` when `MINGW OR CYGWIN OR CMAKE_SYSTEM_NAME` matches `^FreeBSD$|^GNU$|^Linux$|^MirBSD$|^NetBSD$|^OpenBSD$`; otherwise the default is `OFF`. The user can override it.
- When `XZ_ASM_I386` is on, `enable_language(ASM)` runs, and:
  - `crc32_x86.S` is added if `XZ_SMALL` is off (also defines `HAVE_CRC_X86_ASM`).
  - `crc64_x86.S` is added if `"crc64"` is in `XZ_CHECKS` and `XZ_SMALL` is off.

### DOS build (`dos/Makefile`, `dos/config.h`)

`SRCS_ASM` always lists both `.S` files and `dos/config.h` defines `HAVE_CRC_X86_ASM`, but DJGPP is not ELF/Linux/FreeBSD, so the guard is false and no note is emitted there.

## Combined condition

The explicit `.note.GNU-stack` section is emitted only when all hold:

1. Target is 32-bit x86 with assembler enabled (`enable_assembler=x86` / `COND_ASM_X86`, or `XZ_ASM_I386=ON`); by default that means an `i?86` CPU on a listed OS.
2. Not a small build (`--enable-small` / `XZ_SMALL` off). For `crc64_x86.S`, the CRC64 check must also be enabled.
3. The object format is ELF (`__ELF__`).
4. The OS is Linux or FreeBSD (`__linux__` or `__FreeBSD__`).

In practice with default settings: 32-bit x86 Linux or FreeBSD, non-small build. It is never emitted by these sources on x86-64 or any non-x86 architecture, because the files are not compiled there (`INSTALL` says the option "currently does nothing on other architectures (not even on x86-64)").

## What is not in the code

- No other file in the checkout mentions `.note.GNU-stack`, `GNU_STACK`, `noexecstack` or `execstack` (searched the whole tree outside `.git`, excluding `ChangeLog`, `po`). Neither `configure.ac` nor `CMakeLists.txt` passes `-Wa,--noexecstack` or `-z noexecstack`.
- The only assembly source files in the tree are these two `.S` files.
- For C sources, any `.note.GNU-stack` section in the objects comes from the compiler itself, not from anything in this repository. That is outside what the source controls and I did not build to check it.
- There is no check for the GNU assembler itself; the `__linux__` / `__FreeBSD__` test is the stand-in, as the source comment says.
