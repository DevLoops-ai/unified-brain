# How sandboxing is enforced in XZ Utils, and on which platforms

## Short answer

Sandboxing exists only in two command line tools, `xz` and `xzdec` (which is also built as `lzmadec`). The library `liblzma`, `lzmainfo` and the shell scripts have no sandbox code. Three operating-system mechanisms are supported, and exactly one is chosen at build time:

| Method | Platform | Build macro | Minimum version (per `INSTALL` / `CMakeLists.txt` comments) |
|---|---|---|---|
| `pledge(2)` | OpenBSD | `HAVE_PLEDGE` | OpenBSD >= 5.9 |
| Landlock | Linux | `HAVE_LINUX_LANDLOCK` | Linux >= 5.13 |
| Capsicum | FreeBSD | `HAVE_CAP_RIGHTS_LIMIT` | FreeBSD >= 10.2 |

On every other platform (Windows, macOS, etc.) none of the macros is defined, `ENABLE_SANDBOX` is not defined, and there is no sandbox at all. `src/xz/sandbox.c` then compiles to just `typedef int dummy;`.

## Build-time selection

- Autotools: `--enable-sandbox=METHOD` in `configure.ac` (lines 548-572 and 1149-1216). CMake: the `XZ_SANDBOX` cache variable in `CMakeLists.txt` (lines 1740-1841). Accepted values in both: `auto` (default), `no`, `capsicum`, `pledge`, `landlock`.
- Detection order in both build systems: Capsicum (`cap_rights_limit`), then `pledge`, then Landlock. The first one found wins.
- Landlock is detected with a compile/link test, not just a header check, because some systems have `linux/landlock.h` without the syscalls. The test uses `prctl(PR_SET_NO_NEW_PRIVS, ...)`, `SYS_landlock_create_ruleset`, `SYS_landlock_restrict_self` and `LANDLOCK_CREATE_RULESET_VERSION`.
- If Landlock is found and the C flags contain `-fsanitize=`, the build stops with an error (`AC_MSG_ERROR` / `message(SEND_ERROR ...)`): Landlock is incompatible with sanitizers. The CI (`.github/workflows/ci.yml`) therefore disables the sandbox for the sanitizer and valgrind jobs.
- If a specific method is requested and not found, the build fails. With `auto` and nothing found, the tools are built without a sandbox.
- In autotools, if both `--disable-xz` and `--disable-xzdec` are used, the sandbox is forced to `no`.
- `ENABLE_SANDBOX` is defined in `src/xz/sandbox.h` (lines 12-15) and separately in `src/xzdec/xzdec.c` (lines 38-41) when any of the three macros is defined. CMake adds the macro to both the `xz` and the `xzdec`/`lzmadec` targets.

## `xz`: three levels (`src/xz/sandbox.c`, `src/xz/sandbox.h`)

The API is four functions: `sandbox_init()`, `sandbox_enable_read_only()`, `sandbox_allow_strict()`, `sandbox_enable_strict_if_allowed(src_fd, pipe_event_fd, pipe_write_fd)`.

### Where they are called

1. `sandbox_init()` — in `main()` (`src/xz/main.c` line 169), right after `tuklib_progname_init()` and `io_init()`, before locale/gettext setup. This is the level that can always be on.
2. `sandbox_enable_read_only()` — in `main()` (line 252) after argument parsing, when `to_stdout_only` is true: `opt_stdout` is set (`--stdout`, and `--test` implies it), or `opt_mode == MODE_LIST`, or `--files`/`--files0` is not used (`args.files_name == NULL`) and every filename argument is `"-"` (no arguments counts as one `"-"`).
3. `sandbox_allow_strict()` — same place (line 259), only if `to_stdout_only` is true and `args.files_name == NULL && args.arg_count == 1`. It only sets the static flag `strict_sandbox_allowed`.
4. `sandbox_enable_strict_if_allowed()` — in `io_open_src()` (`src/xz/file_io.c` lines 723-727), after `io_open_src_real()` has opened the input successfully. It gets `pair.src_fd`, `user_abort_pipe[0]` and `user_abort_pipe[1]`. It first calls `prepare_for_strict_sandbox()`, which returns false if the flag is not set; otherwise it tries to force locale and iconv data to be loaded before files can no longer be opened (`snprintf(NULL, 0, "%s%s", _(dummy_str), strerror(EINVAL))` and `tuklib_mbstr_width(dummy_str, NULL)`). The source comments call this a hack that may not be good enough.

So the strict level applies only when exactly one file goes to standard output (including single-file `--test` and `--list`) without `--files`/`--files0`. When xz creates or deletes files (normal `xz file`), only the `sandbox_init()` level is active.

### What each method does at each level

**pledge (OpenBSD)**
- `sandbox_init()`: `pledge("stdio rpath wpath cpath fattr", "")`.
- `sandbox_enable_read_only()`: `pledge("stdio rpath", "")`.
- strict: `pledge("stdio", "")`.
- Any failure: `message_fatal("Failed to enable the sandbox")`.

**Landlock (Linux)**
- `sandbox_init()`: calls `prctl(PR_SET_NO_NEW_PRIVS, 1, 0, 0, 0)` with the return value ignored (a failure would show up later because `landlock_restrict_self` fails without it). Then it asks the kernel for its Landlock ABI version with `syscall(SYS_landlock_create_ruleset, NULL, 0, LANDLOCK_CREATE_RULESET_VERSION)`, stores it in the static `landlock_abi`, and clamps it to `LANDLOCK_ABI_MAX` (4 if the header defines `LANDLOCK_ACCESS_NET_BIND_TCP`, otherwise 3). Then it calls `enable_landlock()` keeping these rights: `LANDLOCK_ACCESS_FS_WRITE_FILE | READ_FILE | READ_DIR | REMOVE_FILE | MAKE_REG`. (`READ_DIR` is kept only to get the "Is a directory, skipping" message; truncate is not needed because files are created with `O_EXCL` and without `O_TRUNC`.)
- `sandbox_enable_read_only()`: `enable_landlock(LANDLOCK_ACCESS_FS_READ_FILE | LANDLOCK_ACCESS_FS_READ_DIR)`.
- strict: `enable_landlock(0)` — every filesystem action the ABI knows is denied.
- `enable_landlock(required_rights)`: returns silently if `landlock_abi <= 0` (kernel without Landlock, so xz runs unsandboxed). Otherwise it builds a `struct landlock_ruleset_attr` with `handled_access_fs = ~required_rights & ((1ULL << (12 + my_min(3, landlock_abi))) - 1)` (ABI v1 flags end at `MAKE_SYM` bit 12, v2 adds `REFER` bit 13, v3 adds `TRUNCATE` bit 14), and, when ABI >= 4, `handled_access_net = LANDLOCK_ACCESS_NET_BIND_TCP | LANDLOCK_ACCESS_NET_CONNECT_TCP` (TCP bind and connect denied). It creates the ruleset with `SYS_landlock_create_ruleset` and applies it with `SYS_landlock_restrict_self`. No `landlock_add_rule` is ever called, so there are no path exceptions: everything in the handled set is denied, and already-open descriptors keep working. Failure of either syscall is `message_fatal`.

**Capsicum (FreeBSD)**
- `sandbox_init()` and `sandbox_enable_read_only()` do nothing. Only the strict level exists.
- strict: `cap_enter()`, then `cap_rights_limit()` per descriptor:
  - `src_fd`: `CAP_EVENT, CAP_FCNTL, CAP_LOOKUP, CAP_READ, CAP_SEEK`
  - `STDIN_FILENO` (if it is not the source): all rights cleared (`cap_rights_clear`)
  - `STDOUT_FILENO`: `CAP_EVENT, CAP_FCNTL, CAP_FSTAT, CAP_LOOKUP, CAP_WRITE, CAP_SEEK`
  - `STDERR_FILENO`: `CAP_WRITE`
  - `pipe_event_fd` (`user_abort_pipe[0]`): `CAP_EVENT`
  - `pipe_write_fd` (`user_abort_pipe[1]`): `CAP_WRITE`
- On error: if `errno == ENOSYS` (kernel without capability mode, or an emulator) xz continues silently without the sandbox; any other error is `message_fatal`.

## `xzdec` / `lzmadec` (`src/xzdec/xzdec.c`)

xzdec has its own copy of the logic and does not use `sandbox.c`.

- Start of `main()`:
  - pledge: `pledge("stdio rpath", "")`, so the looser sandbox already covers argument parsing and all files; failure prints "Failed to enable the sandbox" and exits with `EXIT_FAILURE`.
  - Landlock: only `prctl(PR_SET_NO_NEW_PRIVS, 1, 0, 0, 0)` (return value ignored). No Landlock ruleset yet.
  - Capsicum: nothing yet.
- `sandbox_enter(int src_fd)` (lines 302-388) is the strict step. It is called with `STDIN_FILENO` when no filenames are given, otherwise only for the last file (`optind == argc - 1`), after that file has been opened with `fopen`. With several files, the earlier files are decompressed without the strict sandbox.
  - Capsicum: `cap_enter()`; `src_fd` limited to `CAP_READ`; stdin cleared if it is not the source; stdout `CAP_WRITE`; stderr `CAP_WRITE`. `ENOSYS` is ignored silently, as in xz.
  - pledge: `pledge("stdio", "")`.
  - Landlock: queries the ABI, and if it is > 0, clamps to `LANDLOCK_ABI_MAX`, sets `handled_access_fs = (1ULL << (12 + my_min(3, landlock_abi))) - 1` (all filesystem actions denied) plus the two TCP flags on ABI >= 4, then `SYS_landlock_create_ruleset` and `SYS_landlock_restrict_self`, with no rules added. If the ABI is <= 0 nothing is done.
  - Any other failure: `my_errorf("Failed to enable the sandbox")` and `exit(EXIT_FAILURE)`.
  - If `ENABLE_SANDBOX` is defined but no method matches, there is a compile-time `#error`.

## Things that are not enforced / limits

- No seccomp or other syscall filtering on Linux. Landlock here restricts only filesystem actions and (ABI 4) TCP bind/connect. On Linux kernels without Landlock the tools run with no sandbox and no warning.
- On FreeBSD, `xz` has no sandbox unless the strict single-file-to-stdout case applies; `ENOSYS` disables it silently.
- Normal file-to-file `xz` runs get only the first level (pledge with file create/attribute promises, or Landlock still allowing read, write, create and remove of regular files; nothing on FreeBSD).
- `xz` with several files to stdout gets only the read-only level, not strict.
- No sandbox on platforms other than OpenBSD, Linux and FreeBSD, and none inside `liblzma` or the other tools.
- `INSTALL` itself describes this as "limited sandboxing support".
