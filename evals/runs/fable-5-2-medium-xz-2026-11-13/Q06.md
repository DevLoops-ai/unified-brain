# Q6: Memory limit enforcement in the multithreaded decoder

All of this is in `src/liblzma/common/stream_decoder_mt.c` (function `stream_decode_mt()` and helpers), with the output-queue counters in `src/liblzma/common/outqueue.c` / `outqueue.h`.

## Short answer

There are two limits, not one:

- `memlimit_threading` - a **soft** limit. It never causes an error. It only decides whether a block is decoded by a worker thread, how long the main thread waits before starting the next block, and when caches are freed.
- `memlimit_stop` - a **hard** limit. If the filter chain of a block alone needs more than this, `lzma_code()` returns `LZMA_MEMLIMIT_ERROR`.

When a block does not fit:

- Over `memlimit_threading` but within `memlimit_stop`: the decoder drops to single-threaded "direct mode" for that block (`SEQ_BLOCK_DIRECT_INIT` / `SEQ_BLOCK_DIRECT_RUN`). No error.
- Fits `memlimit_threading` on its own, but not together with what is running right now: the main thread waits in `SEQ_BLOCK_THR_INIT` until enough running blocks finish, then frees caches if needed.
- Filter chain over `memlimit_stop`: pending output is flushed first, then `LZMA_MEMLIMIT_ERROR`. This is resumable after `lzma_memlimit_set()`.

## Setup

`stream_decoder_mt_init()` copies the limits from `lzma_mt`:

```c
coder->memlimit_threading = my_max(1, options->memlimit_threading);
coder->memlimit_stop = my_max(1, options->memlimit_stop);
if (coder->memlimit_threading > coder->memlimit_stop)
	coder->memlimit_threading = coder->memlimit_stop;
```

So 0 becomes 1, and the soft limit is clamped to the hard limit. All counters start at 0.

## Counters used

In `struct lzma_stream_coder`:

- `mem_in_use` - input buffers + filter chains of running worker threads (mutex protected). Does not include output buffers.
- `mem_cached` - filter chains kept by idle threads on the `threads_free` stack (mutex protected).
- `mem_direct_mode` - filter chain memory of the direct-mode decoder `coder->block_decoder`; 0 in threaded mode.
- `mem_next_filters`, `mem_next_in`, `mem_next_block` - needs of the block about to start.
- `outq.mem_in_use` / `outq.mem_allocated` - output buffers in use / allocated including cached ones (maintained in `outqueue.c`).

Per worker thread: `thr->mem_filters` and `thr->in_size`.

## Step by step per block

### 1. `SEQ_BLOCK_HEADER`

After the Block Header is decoded, `mem_next_filters = lzma_raw_decoder_memusage(coder->filters)`. If that is `UINT64_MAX` (unknown filter ID), `pending_error = LZMA_OPTIONS_ERROR` and the state becomes `SEQ_ERROR`.

### 2. `SEQ_BLOCK_INIT` - the decisions

In this order:

1. **Hard limit.** `if (coder->mem_next_filters > coder->memlimit_stop)`: call `read_output_and_wait()` with waiting allowed to flush pending output; return `LZMA_OK` while the output queue is not empty; once it is empty return `LZMA_MEMLIMIT_ERROR`. The state stays `SEQ_BLOCK_INIT`, and the comment says the check is first on purpose so decoding can restart after the limit is raised with `lzma_memlimit_set()`.
   Note what is compared: only the filter chain memory. That is exactly the cost of single-threaded decoding of this block (no per-thread in/out buffers).
2. **Sizes unusable.** `is_direct_mode_needed()` returns true if compressed or uncompressed size is `LZMA_VLI_UNKNOWN` or `> SIZE_MAX / 3` -> `SEQ_BLOCK_DIRECT_INIT`.
3. **Compute threaded cost.**
   - `mem_next_in = comp_blk_size(coder)` = `vli_ceil4(compressed_size) + lzma_check_size(check)`
   - `mem_buffers = mem_next_in + lzma_outq_outbuf_memusage(uncompressed_size)` (= `sizeof(lzma_outbuf) + uncompressed_size`)
   - If `UINT64_MAX - mem_buffers < mem_next_filters` (overflow) -> `SEQ_BLOCK_DIRECT_INIT`.
   - `mem_next_block = mem_next_filters + mem_buffers`
4. **Soft limit.** `if (coder->mem_next_block > coder->memlimit_threading)` -> `SEQ_BLOCK_DIRECT_INIT`.
5. Otherwise threaded mode: free the direct decoder (`lzma_next_end(&coder->block_decoder)`), `mem_direct_mode = 0`, append sizes to the index hash, go to `SEQ_BLOCK_THR_INIT`.

### 3. `SEQ_BLOCK_THR_INIT` - wait, then free caches

`read_output_and_wait()` is called with `&block_can_start`. Under `coder->mutex` it sets `*input_is_possible = true` only when all three hold:

```c
coder->memlimit_threading - coder->mem_in_use - coder->outq.mem_in_use
		>= coder->mem_next_block
&& lzma_outq_has_buf(&coder->outq)
&& (coder->threads_initialized < coder->threads_max
		|| coder->threads_free != NULL)
```

Otherwise it keeps copying output and waits on `coder->cond`. `worker_stop()` signals that condition when a thread finishes a block, after doing `mem_in_use -= in_size`, `mem_in_use -= mem_filters`, `mem_cached += mem_filters` and pushing the thread onto `threads_free`. If the caller's output buffer fills first, `stream_decode_mt()` returns `LZMA_OK` and stays in the same state.

So the effective number of parallel blocks is throttled by memory: this is how "reduce the number of threads" from the API doc (`src/liblzma/api/lzma/container.h`, `lzma_mt.memlimit_threading`) is actually done.

Note that this check ignores cached memory. Cached memory is handled next, with `mem_max = memlimit_threading - mem_next_block`:

- If `mem_in_use + mem_cached + outq.mem_allocated > mem_max`: `lzma_outq_clear_cache2(&coder->outq, allocator, uncompressed_size)` frees all cached output buffers except one of exactly the needed size.
- If there is a cached thread and `mem_in_use + mem_cached + outq.mem_in_use > mem_max`: free the block decoders of cached threads (`lzma_next_end(&thr->block_decoder)`, `thr->mem_filters = 0`), summing `mem_freed`. The first cached thread is skipped if `thr->mem_filters <= coder->mem_next_filters`, so its allocation can be reused.

Then under the mutex: `mem_cached -= mem_freed; mem_in_use += mem_next_in + mem_next_filters;`. After that come `lzma_outq_prealloc_buf()`, `get_thread()` (which subtracts the reused thread's `mem_filters` from `mem_cached`), `lzma_block_decoder_init()`, and allocation of `thr->in`. A real allocation failure here gives `LZMA_MEM_ERROR` after `threads_stop()`, which is a different thing from the limit.

### 4. `SEQ_BLOCK_DIRECT_INIT` / `SEQ_BLOCK_DIRECT_RUN` - the fallback

- Wait via `read_output_and_wait()` until the output queue is empty (returns `LZMA_OK` in between).
- `lzma_outq_clear_cache()` frees all cached output buffers.
- `threads_end()` destroys all worker threads and the `coder->threads` array.
- `lzma_block_decoder_init(&coder->block_decoder, ...)`, then `mem_direct_mode = mem_next_filters`.
- `SEQ_BLOCK_DIRECT_RUN` decodes straight from the caller's `in` to the caller's `out`, with no per-block buffers. On `LZMA_STREAM_END` it appends to the index hash and returns to `SEQ_BLOCK_HEADER`.

The decision is made again for every block, so a later smaller block can go back to threads (which are then created again).

## Changing the limit at run time

`stream_decoder_mt_memconfig()` (behind `lzma_memusage()`, `lzma_memlimit_get()`, `lzma_memlimit_set()`):

- usage reported = `mem_direct_mode + mem_in_use + mem_cached + outq.mem_allocated`, at least `LZMA_MEMUSAGE_BASE`.
- It gets/sets **`memlimit_stop` only**. The comment says `memlimit_threading` cannot be changed after init.
- A new limit below current usage (cached memory included) is rejected with `LZMA_MEMLIMIT_ERROR`. `lzma_memlimit_set()` in `common.c` turns 0 into 1.

## What is not checked

- `memlimit_stop` is compared only with `mem_next_filters`. It is not compared with the running total. In threaded mode the total is bounded only by `memlimit_threading` (which is clamped to `memlimit_stop` at init).
- The wait condition in `read_output_and_wait()` does not count `mem_cached` or cached output buffers; those are handled by the cache-freeing step, whose math the source calls worst-case.
- `memlimit_threading` can be exceeded "even by a large amount" in direct mode (comment on the struct field and in the API doc). It never produces `LZMA_MEMLIMIT_ERROR`.
- After the limit steps, a comment notes `mem_in_use + mem_cached` may briefly count the same thing twice until `get_thread()` corrects it.

## How the `xz` tool sets the limits

`src/xz/coder.c` (`FORMAT_XZ` case):

- `mt_options.memlimit_stop = hardware_memlimit_get(MODE_DECOMPRESS)` - `UINT64_MAX` when the user set no limit.
- `mt_options.memlimit_threading = threads == 1 ? 0 : hardware_memlimit_mtdec_get()` - 0 forces direct mode for every block, matching `lzma_stream_decoder()`.
- `hardware_memlimit_mtdec_get()` in `src/xz/hardware.c` returns `memlimit_mtdec` if set, else `memlimit_mt_default` (total RAM / 4, capped by `mem_ceiling`), capped to `memlimit_decompress` if that is set.
- On `LZMA_MEMLIMIT_ERROR`, `xz` prints the message and calls `message_mem_needed(V_ERROR, lzma_memusage(&strm))`.
