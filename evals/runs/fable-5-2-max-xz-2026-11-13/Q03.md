# Decompression path in XZ Utils (commit 7baf6835)

Everything below comes from reading the source under `/tmp/xzmax/xz`. Nothing was built or run, and nothing comes from memory or the web.

## The path in one picture

Default case `xz -d file.xz`, shown as one thread:

```
input file
  -> io_read()          read() into in_buf
  -> lzma_code()        public entry of liblzma
  -> stream_decode()    .xz container: Stream Header, Blocks, Index, Stream Footer
  -> block_decode()     one Block: data, padding, integrity check
  -> filter chain       BCJ / Delta (optional), LZMA2 always last
  -> lz_decode()        dictionary (window of recent output bytes)
  -> lzma2_decode()     LZMA2 chunks
  -> lzma_decode()      LZMA symbols, read through the range decoder
  <- bytes go into the dictionary, are copied to the output buffer,
     are un-filtered by BCJ/Delta on the way back up, and are hashed by the Block check
  -> io_write()         write() from out_buf
```

- The container, Block and filter layers share one call shape, `lzma_code_function`: `(coder, allocator, in, in_pos, in_size, out, out_pos, out_size, action)`.
- Each layer holds a `lzma_next_coder next` that points to the layer below.
- The two LZ-level decoders use `lzma_lz_decoder.code(coder, dict, in, in_pos, in_size)` and write into the dictionary, not into `out`.
- Each layer is a state machine with a `sequence` field, so it can stop when input or output runs out and continue on the next call.

## Stage by stage

### 0. Start-up
- `main()` runs `io_init()`, `hardware_init()`, `args_parse()`, `signals_init()`, then calls `coder_run()` once per file name.
- `opt_mode = MODE_DECOMPRESS` comes from `-d` or from the program name (`unxz`, `xzcat`, `lzcat`, `unlzma`).
- `-t` gives `MODE_TEST`: the same path, but the output is thrown away.
- `hardware_init()` calls `hardware_threads_set(0)`, so the thread count is `lzma_cputhreads()`.

### 1. Open the input and read the first chunk
- `coder_run()` calls `io_open_src()`, which opens the file with `O_RDONLY | O_NONBLOCK` and runs `fstat()`.
- It skips directories. When writing to disk it also skips non-regular files, and (unless `--force` or `--keep`) setuid/setgid/sticky files and files with more than one hard link.
- Then `strm.next_in = in_buf.u8; strm.avail_in = io_read(pair, &in_buf, IO_BUFFER_SIZE)`.
- `IO_BUFFER_SIZE` is 8192 when `BUFSIZ <= 1024`, else `BUFSIZ & ~7U`. `in_buf` and `out_buf` are static buffers of that size.
- `io_read()` loops on `read()` until the buffer is full or the file ends (then `pair->src_eof = true`).

### 2. Detect the format and create the decoder: `coder_init()`
- Flags: `LZMA_IGNORE_CHECK` with `--ignore-check`, otherwise `LZMA_TELL_UNSUPPORTED_CHECK`; `LZMA_CONCATENATED` unless `--single-stream`.
- Detection on the first chunk:
  - `is_format_xz()`: magic bytes `FD 37 7A 58 5A 00`.
  - `is_format_lzip()`: magic bytes `4C 5A 49 50`.
  - `is_format_lzma()`: no magic. The 13-byte header must decode with `lzma_properties_decode()`, the dictionary size must be 2^n or 2^n + 2^(n-1) or `UINT32_MAX`, and a known size must be at most 2^38.
- Decoder chosen:
  - `.xz`: `lzma_stream_decoder_mt()` when built with threads (`MYTHREAD_ENABLED`), otherwise `lzma_stream_decoder()`.
  - `.lzma`: `lzma_alone_decoder()`.
  - `.lz`: `lzma_lzip_decoder()`.
  - `--format=raw`: `lzma_raw_decoder()` with the filter chain from the command line.
  - Unknown format: `LZMA_FORMAT_ERROR`. The exception is `--decompress --stdout --force`, where `coder_passthru()` copies the input unchanged.
- Thread options for `.xz`: `threads = hardware_threads_get()`, `memlimit_stop = hardware_memlimit_get(MODE_DECOMPRESS)`, `timeout = 300` ms. `memlimit_threading` is 0 with one thread (this forces single-thread behaviour), otherwise `hardware_memlimit_mtdec_get()`.
- Every init goes through the `lzma_next_strm_init` macro: `lzma_strm_init()` allocates `strm->internal`, the format's init fills `strm->internal->next`, and `LZMA_RUN` and `LZMA_FINISH` are enabled in `supported_actions`.
- `coder_init()` then calls `lzma_code(&strm, LZMA_RUN)` once with no output buffer. This decodes the first headers, so a too-low memory limit or an unsupported check type shows up before the output file is created.

### 3. Open the output: `io_open_dest()`
- It is not called in `MODE_TEST`.
- The output is stdout, or a new file opened with `O_WRONLY | O_CREAT | O_EXCL`.
- The name comes from `suffix_get_dest_name()`: it strips `.xz`, `.lzma`, `.lz`, and turns `.txz` / `.tlz` into `.tar`.
- `dest_try_sparse` is set in `MODE_DECOMPRESS` unless `--no-sparse` was given or stdout is not suitable.

### 4. The main loop: `coder_normal()`
- Setup: `action = pair->src_eof ? LZMA_FINISH : LZMA_RUN`; `strm.next_out = out_buf.u8; strm.avail_out = IO_BUFFER_SIZE`.
- Repeat while `!user_abort`:
  1. If `strm.avail_in == 0 && action == LZMA_RUN`, call `io_read()` again. At end of file, `action = LZMA_FINISH`.
  2. `ret = lzma_code(&strm, action)`.
  3. If `strm.avail_out == 0`, call `coder_write_output()`.
  4. If `ret != LZMA_OK`:
     - `LZMA_UNSUPPORTED_CHECK` is only a warning and the loop continues.
     - Any other code first writes out the remaining output.
     - `LZMA_STREAM_END` means success after the trailing-data check in stage 13.
     - Other codes print `message_strm(ret)`; `LZMA_MEMLIMIT_ERROR` also prints `lzma_memusage(&strm)`.

### 5. Library entry: `lzma_code()`
- It checks the arguments and tracks `strm->internal->sequence` (`ISEQ_RUN`, `ISEQ_FINISH`, `ISEQ_END`, `ISEQ_ERROR`; the flush states are for encoding).
- It calls `strm->internal->next.code(...)`, then moves `next_in`, `avail_in`, `total_in`, `next_out`, `avail_out`, `total_out` by the amounts used.
- Return-code rules:
  - `LZMA_OK` with no progress twice in a row becomes `LZMA_BUF_ERROR` (`allow_buf_error`).
  - The internal `LZMA_TIMED_OUT` becomes `LZMA_OK`.
  - `LZMA_STREAM_END` sets `ISEQ_END`.
  - Fatal errors set `ISEQ_ERROR`.

### 6. Container: `stream_decode()` (single thread)
States, in order:
- **`SEQ_STREAM_HEADER`**
  - Collects 12 bytes (`LZMA_STREAM_HEADER_SIZE`) in `coder->buffer`.
  - `lzma_stream_header_decode()` checks the magic (`LZMA_FORMAT_ERROR`), the CRC32 (`LZMA_DATA_ERROR`) and the reserved bits (`LZMA_OPTIONS_ERROR`), and reads the check type.
  - It can return `LZMA_NO_CHECK`, `LZMA_UNSUPPORTED_CHECK` or `LZMA_GET_CHECK` if the flags ask for it.
- **`SEQ_BLOCK_HEADER`**
  - A first byte of `0x00` (`INDEX_INDICATOR`) means the Index starts: go to `SEQ_INDEX`.
  - Otherwise the header size is `(byte + 1) * 4` (`lzma_block_header_size_decode`, max `LZMA_BLOCK_HEADER_SIZE_MAX` = 1024), and the header is collected in `coder->buffer`.
- **`SEQ_BLOCK_INIT`**
  - `lzma_block_header_decode()` reads the CRC32, the flags, the optional Compressed Size and Uncompressed Size (`lzma_vli_decode()`), and 1 to 4 filters (`lzma_filter_flags_decode()` then `lzma_properties_decode()`).
  - Memory check with `lzma_raw_decoder_memusage(filters)`: unknown filter gives `LZMA_OPTIONS_ERROR`; above `coder->memlimit` gives `LZMA_MEMLIMIT_ERROR`.
  - Otherwise `lzma_block_decoder_init()`.
- **`SEQ_BLOCK_RUN`**
  - Calls `coder->block_decoder.code(...)`.
  - When the Block ends, `lzma_index_hash_append()` records its unpadded size and uncompressed size, and the state returns to `SEQ_BLOCK_HEADER`.
- **`SEQ_INDEX`**
  - `lzma_index_hash_decode()` reads the Index and compares it with what the Blocks really were: record count, sizes, a hash of all size pairs (`LZMA_CHECK_BEST`), and the Index CRC32.
- **`SEQ_STREAM_FOOTER`**
  - Collects 12 bytes; `lzma_stream_footer_decode()` checks magic `59 5A` and the CRC32.
  - `lzma_index_hash_size()` must equal the footer's `backward_size`.
  - `lzma_stream_flags_compare()` compares header and footer.
  - Without `LZMA_CONCATENATED` it returns `LZMA_STREAM_END` here.
- **`SEQ_STREAM_PADDING`** (only with `LZMA_CONCATENATED`)
  - Skips zero bytes; their count must be a multiple of 4.
  - A non-zero byte starts the next Stream (`stream_decoder_reset()`).
  - End of input with `LZMA_FINISH` gives `LZMA_STREAM_END`.

### 7. Block: `block_decode()`
- **`SEQ_CODE`**
  - Limits input and output to `compressed_limit` / `uncompressed_limit`.
  - Calls `coder->next.code` (the filter chain) and counts `compressed_size` / `uncompressed_size`.
  - Passes the new output bytes to `lzma_check_update()` (skipped with `ignore_check`).
  - Sizes that do not match the Block Header give `LZMA_DATA_ERROR`.
- **`SEQ_PADDING`**: zero bytes until the compressed size is a multiple of 4.
- **`SEQ_CHECK`**
  - `lzma_check_finish()`, then reads `lzma_check_size()` bytes into `block->raw_check`.
  - `memcmp()` against `coder->check.buffer.u8`; a mismatch gives `LZMA_DATA_ERROR`.
  - The compare is skipped if the check type is unsupported or ignored.
- Check types: `LZMA_CHECK_NONE` (0), `LZMA_CHECK_CRC32` (1, 4 bytes), `LZMA_CHECK_CRC64` (4, 8 bytes), `LZMA_CHECK_SHA256` (10, 32 bytes). They use `lzma_crc32()`, `lzma_crc64()` and `lzma_sha256_update()`.

### 8. Filter chain
- It is built by `lzma_block_decoder_init()` → `lzma_raw_decoder_init()` → `lzma_raw_coder_init()`.
- `lzma_validate_chain()` allows 1 to `LZMA_FILTERS_MAX` (4) filters. The last must be LZMA1 or LZMA2; BCJ and Delta may only be non-last.
- The `decoders[]` table maps Filter ID to an init function:
  - `LZMA_FILTER_LZMA2` (0x21) → `lzma_lzma2_decoder_init`.
  - `LZMA_FILTER_LZMA1` / `LZMA_FILTER_LZMA1EXT` → `lzma_lzma_decoder_init`.
  - `LZMA_FILTER_X86`, `POWERPC`, `IA64`, `ARM`, `ARMTHUMB`, `SPARC`, `ARM64`, `RISCV` (0x04 to 0x0B) → `lzma_simple_*_decoder_init`.
  - `LZMA_FILTER_DELTA` (0x03) → `lzma_delta_decoder_init`.
- For decoding, the order from the header is kept. `lzma_next_filter_init()` sets up filter 0, and each filter's init sets up the next one. So the first filter is the outer layer and LZMA2 is the innermost.
- Data is pulled: the outer filter asks the next one for bytes, then undoes its own transform on those bytes in the output buffer.
  - Delta: `delta_decode()` calls `next.code`, then `decode_buffer()` adds back the byte `distance` positions earlier, using a 256-byte `history`.
  - BCJ: in `simple_code()`, `copy_or_code()` gets bytes from `next.code`, and `call_filter()` runs the architecture function in place (for example `x86_code()` with `is_encoder = false`). Bytes that cannot be converted yet wait in `coder->buffer`.

### 9. Dictionary layer: `lz_decode()` and `decode_buffer()`
- `lzma_lz_decoder_init()` creates the `lzma_dict` (`buf`, `pos`, `full`, `limit`, `size`, `has_wrapped`, `need_reset`).
- Its size is at least 4096, rounded up to a multiple of 16, plus `2 * LZ_DICT_REPEAT_MAX` (2 × 288) spare bytes.
- The `decode_buffer()` loop:
  1. If `dict.pos == dict.size`, wrap: copy the last 288 bytes to the start and set `has_wrapped = true`.
  2. Set `dict.limit` so no more is decoded than fits in the output.
  3. Call `coder->lz.code()` (for `.xz` this is `lzma2_decode`).
  4. `memcpy()` the new bytes from `dict.buf + dict_start` to `out`.
  5. If `dict.need_reset`, call `lz_decoder_reset()`.
- A temp-buffer path (`coder->temp.buffer[LZMA_BUFFER_SIZE]`, 4096 bytes) exists for an LZ filter that is not last. LZMA1 and LZMA2 must be last, so it is not used for them.

### 10. LZMA2 chunks: `lzma2_decode()`
States: `SEQ_CONTROL`, `SEQ_UNCOMPRESSED_1`, `SEQ_UNCOMPRESSED_2`, `SEQ_COMPRESSED_0`, `SEQ_COMPRESSED_1`, `SEQ_PROPERTIES`, `SEQ_LZMA`, `SEQ_COPY`.
- Control byte:
  - `0x00`: end of the LZMA2 data, returns `LZMA_STREAM_END`.
  - `>= 0x80`: LZMA chunk; the low 5 bits are the top bits of the uncompressed size.
  - `>= 0xA0`: also resets the LZMA state.
  - `>= 0xC0`: also reads a new properties byte.
  - `>= 0xE0`: also resets the dictionary.
  - `0x01`: uncompressed chunk with dictionary reset. `0x02`: uncompressed chunk without reset.
  - `0x03` to `0x7F`: `LZMA_DATA_ERROR`.
- Sizes: uncompressed is 5 bits plus 2 bytes, plus 1; compressed is 2 bytes, plus 1.
- `SEQ_PROPERTIES`: `lzma_lzma_lclppb_decode()` reads lc/lp/pb, then `coder->lzma.reset()`.
- `SEQ_LZMA`: calls `coder->lzma.code()`, which is `lzma_decode()`. The input used must match the chunk's compressed size exactly at the end.
- `SEQ_COPY`: `dict_write()` copies raw bytes into the dictionary.
- The dictionary size comes from the 1-byte filter property in the Block Header (`lzma_lzma2_props_decode()`).

### 11. LZMA symbols and range decoder: `lzma_decode()`
- `rc_read_init()` reads 5 start bytes; the first must be `0x00`.
- There are two loops over the same logic:
  - A fast one, used while at least `LZMA_IN_REQUIRED` (20) input bytes remain and the dictionary is not at its limit.
  - A slow one that can stop anywhere and saves its place in `coder->sequence` (`SEQ_IS_MATCH`, `SEQ_LITERAL`, `SEQ_IS_REP`, `SEQ_DIST_SLOT`, `SEQ_DIRECT`, `SEQ_ALIGN`, `SEQ_EOPM`, `SEQ_SHORTREP`, `SEQ_COPY` and others).
  - With `HAVE_SMALL` only the slow loop is compiled.
- One symbol:
  - Bit `is_match` = 0 is a literal: `literal_subcoder()` picks the probability set, 8 bits are decoded, and `dict_put()` writes the byte.
  - `is_match` = 1 and `is_rep` = 0 is a new match: length from `match_len_decoder` (2 to 273), distance from `dist_slot`, then `pos_special` bits, or direct bits (`rc_direct`) plus 4 `pos_align` bits.
  - `is_rep` = 1 repeats one of the last four distances `rep0..rep3` (`is_rep0`, `is_rep0_long`, `is_rep1`, `is_rep2`); the length comes from `rep_len_decoder`.
  - Distance `UINT32_MAX` is the end marker. It is not allowed in LZMA2.
  - `dict_is_distance_valid()` rejects a distance beyond the data produced so far; `dict_repeat()` copies the bytes inside the dictionary.
- Range decoder macros:
  - `rc_normalize` pulls in one input byte when `range < RC_TOP_VALUE` (2^24).
  - `rc_if_0`, `rc_update_0`, `rc_update_1` decode one bit with an 11-bit adaptive probability (`RC_MOVE_BITS` = 5).
  - On x86-64 with GCC or Clang, inline-assembly versions are used (`LZMA_RANGE_DECODER_CONFIG` = `0x1F0`).
- A chunk ends when the dictionary limit set from the chunk's uncompressed size is reached and `rc_is_finished()` is true (`rc.code == 0`). This returns `LZMA_STREAM_END`.

### 12. Output
- When the call returns, the bytes are already in the caller's buffer: dictionary to `out` (stage 9), filters applied in place (stage 8), check updated (stage 7). `lzma_code()` then moves `strm.next_out`.
- `coder_write_output()` calls `io_write()`, which calls `io_write_buf()` and `write()`.
- With `dest_try_sparse`, a full all-zero buffer (`is_sparse()`) is not written. It is added to `dest_pending_sparse` and skipped later with `lseek()`.
- In `MODE_TEST` nothing is written.

### 13. End
- On `LZMA_STREAM_END`:
  - With `--single-stream` or `.lz` (`allow_trailing_input`), `io_fix_src_pos()` seeks back over unused input.
  - Otherwise one more byte is read to confirm end of file; leftover input gives `LZMA_DATA_ERROR`.
- `io_close(pair, success)`:
  - Finishes a trailing sparse hole (seek, then write one zero byte).
  - Copies file attributes (`io_copy_attrs()`).
  - Closes the output, and removes it on failure.
  - Closes the input, and removes it on success unless `--keep` or stdout.

## Multi-threaded .xz decoder (what `xz` uses in a threaded build)

`stream_decode_mt()` has the same container states as stage 6, with these changes:
- **Mode choice in `SEQ_BLOCK_INIT`**
  - `LZMA_MEMLIMIT_ERROR` if the filters need more than `memlimit_stop`.
  - Direct mode (`SEQ_BLOCK_DIRECT_INIT`, `SEQ_BLOCK_DIRECT_RUN`): the main thread runs the Block decoder as in stage 6.
  - Direct mode is used when the Block Header lacks Compressed Size or Uncompressed Size, when a size is above `SIZE_MAX / 3` (`is_direct_mode_needed()`), or when the Block needs more than `memlimit_threading`.
- **`SEQ_BLOCK_THR_INIT`**
  - `read_output_and_wait()` waits for memory, a free output-queue slot and a free thread.
  - Then `lzma_outq_prealloc_buf()`, `get_thread()`, and `lzma_block_decoder_init()` for that thread.
  - It allocates `thr->in` for the whole Block except its header (`comp_blk_size()`), and sets `thr->state = THR_RUN`.
- **`SEQ_BLOCK_THR_RUN`**: the main thread copies input into `thr->in`, signals the worker, and reads output.
- **Worker `worker_decoder()`** (states `THR_IDLE`, `THR_RUN`, `THR_STOP`, `THR_EXIT`)
  - It calls its own `block_decoder.code` on at most 16384 input bytes at a time and writes straight into `thr->outbuf->buf`.
  - At the end it sets `outbuf->finished` and `finish_ret`.
- **Output order**
  - The queue (`lzma_outq`, at most 2 × threads buffers) keeps the order: `lzma_outq_read()` copies only from the head buffer to the caller's `out`.
  - The worker of the head buffer reports partial progress (`lzma_outq_enable_partial_output()`).
- **Index**
  - The Index hash entry is added before decoding, from the header sizes; the Block decoder verifies them.
  - `SEQ_INDEX_WAIT_OUTPUT` empties the queue before `SEQ_INDEX_DECODE`.
- **Errors**
  - They go through `thread_error` / `pending_error` to `SEQ_ERROR`.
  - Output before the error is delivered first, unless `LZMA_FAIL_FAST` is set; `xz` does not set it.
- Stages 7 to 11 are unchanged; they run inside the worker.
