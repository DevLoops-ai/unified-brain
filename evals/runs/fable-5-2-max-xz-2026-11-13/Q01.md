# Answer

# When the build emits `.note.GNU-stack`

## Short answer

The source emits it in exactly two places: the last lines of the two hand-written 32-bit x86 assembly files. Both use the same guard:

```c
#if defined(__ELF__) && (defined(__FreeBSD__) || defined(__linux__))
	.section	.note.GNU-stack,"",@progbits
#endif
```

- `/tmp/xzmax/xz/src/liblzma/check/crc32_x86.S`, lines 306-308 (comment at 301-305)
- `/tmp/xzmax/xz/src/liblzma/check/crc64_x86.S`, lines 289-291 (comment at 284-288)

So the section is emitted only when both of these hold:

1. The build system actually compiles the `.S` file.
2. The preprocessor sees `__ELF__` and also `__FreeBSD__` or `__linux__`. These are compiler-predefined macros; nothing in the repo defines them.

In practice this means a 32-bit x86 ELF build of liblzma for Linux or FreeBSD, with the assembly code enabled and "small" mode off.

## Condition 1: the guard inside the `.S` files

- **Reason given in the source:** "This is needed to support non-executable stack. It's ugly to use `__FreeBSD__` and `__linux__` here, but I don't know a way to detect when we are using GNU assembler."
- **What the OS macros stand for:** they are a stand-in for "the assembler is GNU as". The assembler itself is never checked.
- **The directive:** section `.note.GNU-stack`, empty flags `""`, type `@progbits`. It is the last statement in the file, so the section is empty.
- **Independent of other `#if`s:** `PIC`/`__PIC__`, `__CET__`, `__APPLE__`, `_WIN32`, `__CYGWIN__` and `__MSDOS__` do not change this guard. `__CET__` only pulls in `<cet.h>` / `_CET_ENDBR`.
- **No `config.h`:** the `.S` files do not include it, so no `HAVE_*` macro (including `HAVE_CRC_X86_ASM`) affects the guard.

## Condition 2: when the two `.S` files are compiled

### Autotools

Files: `/tmp/xzmax/xz/configure.ac` and `/tmp/xzmax/xz/src/liblzma/check/Makefile.inc`.

- **Option** (`configure.ac` 343-374): `--enable-assembler`, default `yes`. Accepted values are `yes`, `no`, `x86`; anything else is an error.
- **Auto-detect with `yes`:** the value becomes `x86` only if `$host_os` matches `linux* | *bsd* | mingw* | cygwin | msys | *djgpp*` and `$host_cpu` matches `i?86`. Otherwise it becomes `no`.
- **Forcing:** an explicit `--enable-assembler=x86` skips the host check.
- **Result of `x86`:** defines `HAVE_CRC_X86_ASM` and sets `AM_CONDITIONAL(COND_ASM_X86, ...)`.
- **Detection uses the configure triplet only** (`AC_CANONICAL_HOST`, line 32), not the compiler. `INSTALL` 887-889 says there is no check that the assembly can actually be built. The CI script passes `--build=i686-pc-linux-gnu` for `gcc -m32` because of this (`build-aux/ci_build.bash` 212-219).
- **`crc32_x86.S`** (`Makefile.inc` 20-30): added only if `COND_SMALL` is false and `COND_ASM_X86` is true.
- **`crc64_x86.S`** (`Makefile.inc` 32-44): added only if `COND_CHECK_CRC64` is true, `COND_SMALL` is false and `COND_ASM_X86` is true.
- **`COND_SMALL`** is `--enable-small` (`configure.ac` 411-423).
- **`COND_CHECK_CRC64`** is crc64 in `--enable-checks`, default all (`configure.ac` 240-279). CRC32 cannot be disabled (273-275).
- **Trap:** with `--enable-small`, configure still reports `x86` and defines `HAVE_CRC_X86_ASM`, but the `.S` files are not built, so no note comes from them.

### CMake

File: `/tmp/xzmax/xz/CMakeLists.txt`.

- **Option** (233-256): `XZ_ASM_I386` exists only under `if(NOT MSVC)`. If it is on, `enable_language(ASM)` is called.
- **Default:** the result of `check_symbol_exists("__i386__" "" ASM_I386_DEFAULT)` when `MINGW OR CYGWIN OR CMAKE_SYSTEM_NAME MATCHES "^FreeBSD$|^GNU$|^Linux$|^MirBSD$|^NetBSD$|^OpenBSD$"`. Otherwise `OFF`. Here the compiler is asked, unlike Autotools.
- **`crc32_x86.S`** (709-722): added if `XZ_SMALL` is off and `XZ_ASM_I386` is on. This also defines `HAVE_CRC_X86_ASM`.
- **`crc64_x86.S`** (724-742): added if `"crc64" IN_LIST XZ_CHECKS`, `XZ_SMALL` is off and `XZ_ASM_I386` is on.

### DOS / DJGPP

File: `/tmp/xzmax/xz/dos/Makefile`.

- It always compiles both `.S` files (`SRCS_ASM` at 122-124, rule at 138-139 runs `$(CC) ... -c`).
- `dos/config.h` line 16 defines `HAVE_CRC_X86_ASM`.
- The guard is false there, so no note. The `.S` files themselves treat `__MSDOS__` as a non-ELF case (`crc32_x86.S` 89-92, 296-299).

## Result by case

The "note emitted" column assumes compilers define `__linux__`, `__FreeBSD__` and `__ELF__` only on those targets. That is a toolchain fact and is not in the repo.

| Case | `.S` files built? | Note emitted? |
|---|---|---|
| i?86 Linux, ELF, defaults | yes | yes |
| i?86 FreeBSD, ELF, defaults | yes | yes |
| i?86 NetBSD / OpenBSD (both build systems), MirBSD / GNU (CMake list only) | yes by default | no: guard names only `__FreeBSD__` / `__linux__` |
| MinGW / Cygwin / MSYS i?86 | yes by default | no: guard needs `__ELF__` |
| DJGPP (`dos/Makefile`) | always | no |
| Darwin, Solaris x86 | only if forced (`--enable-assembler=x86` or `-DXZ_ASM_I386=ON`) | no |
| x86-64 and every non-x86 CPU | no (`INSTALL` 413-415) | no |
| `--disable-assembler` / `XZ_ASM_I386=OFF` | no | no |
| `--enable-small` / `XZ_SMALL=ON` | no | no |
| MSVC | no | no |

Without crc64 in `--enable-checks` / `XZ_CHECKS`, only `crc32_x86.S` is built and it alone carries the note.
