# When xz deletes the original input file (commit 7baf6835)

## Short answer

The input file is deleted in exactly one place: `io_close_src()` in `/tmp/xzmax/xz/src/xz/file_io.c` (lines 738-774), which calls `io_unlink()` (lines 230-285). This is from reading the source only; nothing was built or run.

```c
if (pair->src_fd != STDIN_FILENO && pair->src_fd != -1) {
	(void)close(pair->src_fd);

	if (success && !opt_keep_original)
		io_unlink(pair->src_name, &pair->src_st);
}
```

So the input is deleted only when all three hold:
- it is a real named file, not stdin;
- the whole operation succeeded, including closing the output file;
- `opt_keep_original` is false.

Even then, `io_unlink()` first checks that the name still points to the same file.

Call chain: `main()` → `coder_run()` (`/tmp/xzmax/xz/src/xz/coder.c:1379`) → `io_close(pair, success)` (`file_io.c:1028`) → `io_close_dest()` → `io_close_src()` → `io_unlink()` → `unlink()`.

## Conditions that must all be true

1. **Mode is compress or decompress.** `opt_mode` is `MODE_COMPRESS` (the default, `coder.c:25`) or `MODE_DECOMPRESS`.
   - `MODE_TEST` forces keep (`args.c:822-825`).
   - `MODE_LIST` runs `list_file()`, which always calls `io_close(pair, false)` (`list.c:1344`).
2. **Output goes to a file, not stdout.** `opt_stdout` is set by `-c/--stdout/--to-stdout` (`args.c:383-385`) or by a program name containing `xzcat` or `lzcat` (`args.c:773-781`). `args_parse()` then forces keep:
   ```c
   if (opt_stdout || opt_mode == MODE_TEST) {
   	opt_keep_original = true;
   	opt_stdout = true;
   }
   ```
3. **`-k/--keep` was not given** (`args.c:422-425`). It can also come from the `XZ_DEFAULTS` or `XZ_OPT` environment variables (`args.c:791-792`). Nothing in the code sets `opt_keep_original` back to false.
4. **The input is a named file.** For `-` on the command line, or no file arguments, `src_fd = STDIN_FILENO` (`file_io.c:453-454`), which `io_close_src()` excludes. A `-` read through `--files`/`--files0` is treated as a real file name (`main.c:308-310`).
5. **The source passed the open-time checks** in `io_open_src_real()` (see next section).
6. **`coder_run()` ended with `success == true`.** It starts as false (`coder.c:1391`) and becomes true only if:
   - the first read did not fail (`strm.avail_in != SIZE_MAX`, line 1403);
   - `coder_init()` did not return `CODER_INIT_ERROR` and `user_abort` is not set (line 1412);
   - `io_open_dest()` succeeded (line 1415);
   - `coder_normal()` returned true (lines 1285, 1310).
7. **`coder_normal()` returns true only on a clean finish.** That means `lzma_code()` returned `LZMA_STREAM_END`, the remaining output was written without error, and there was no trailing input. Trailing input is allowed only with `--single-stream` or `.lz` files (`allow_trailing_input`).
8. **`io_close()` kept `success` true** (`file_io.c:1028-1074`):
   - the sparse-file tail (`lseek` plus a 1-byte write) worked, if one was pending (lines 1032-1052);
   - `io_close_dest()` returned false, meaning `close(dest_fd)` succeeded. The code comment says: "Close the destination first. If it fails, we must not remove the source file!" (lines 1061-1064).
9. **`io_unlink()` identity check passed** and `unlink()` itself succeeded.

## Checks that prevent deletion

### Source skipped at open (`io_open_src()` / `io_open_src_real()`, `file_io.c:449-730`)

| Check | Message | Bypassed by |
|---|---|---|
| Empty name (692-695) | "Empty filename, skipping" | nothing |
| Symlink, via `O_NOFOLLOW` or an `lstat()` fallback (488-531, 541-588) | "Is a symbolic link, skipping" | `opt_stdout`, `opt_force` or `opt_keep_original` |
| `open()` or `fstat()` fails (535-596, 605-611) | error with `strerror` | nothing |
| Directory (613-617) | "Is a directory, skipping" | nothing |
| Not a regular file when `!opt_stdout` (619-623) | "Not a regular file, skipping" | nothing; `--force` does not override |
| `S_ISUID` or `S_ISGID` bit (627-641) | "File has setuid or setgid bit set, skipping" | `--force` or `--keep` |
| `S_ISVTX` bit (643-648) | "File has sticky bit set, skipping" | `--force` or `--keep` |
| `st_nlink > 1` (650-655) | "Input file has more than one hard link, skipping" | `--force` or `--keep` |

- The last three rows run only when `reg_files_only && !opt_force && !opt_keep_original`, and only on non-DOS-like systems (`#ifndef TUKLIB_DOSLIKE`).
- `--force` is the one option that turns these checks off while leaving deletion on. `xz -f` on a symlink or a multi-link file will process it and then unlink that name.

### Destination cannot be opened (`io_open_dest_real()`, `file_io.c:777-964`)

If any of these fail, no coding happens, `success` stays false and the source stays.

- `suffix_get_dest_name()` returns NULL (`/tmp/xzmax/xz/src/xz/suffix.c`):
  - compress: "File already has '%s' suffix, skipping" (lines 237-260);
  - decompress: "Filename has an unknown suffix, skipping" (lines 164-168).
- With `--force`, the existing target cannot be unlinked and `errno != ENOENT`: "Cannot remove" (837-842).
- `open(dest, O_WRONLY|O_CREAT|O_EXCL…)` fails, for example because the target exists and `--force` was not given (845-858).
- DJGPP only: the target is a DOS special file, or "Output file is the same as the input file" by `st_dev`/`st_ino` (812-834).
- Windows only: "Destination is not a regular file", for names like `con` or `nul` (872-893).
- `--format=raw` without `--suffix` and without stdout is a fatal error before any file is processed (`args.c:846-863`).

### Failure or abort during coding

- `coder_init()` returns `CODER_INIT_ERROR`: unknown format, bad header, memory limit, or encoder init failure (`coder.c:1021-1027`).
- `user_abort` is set by the signal handler (`/tmp/xzmax/xz/src/xz/signals.c:38-49`).
  - The signals are SIGINT, SIGTERM, SIGHUP, SIGPIPE, SIGXCPU and SIGXFSZ; on Windows it is the console Ctrl handler.
  - It is checked at `coder.c:1412`, in the `while (!user_abort)` loop (line 1192), and in `io_read()`, `io_wait()` and `io_write_buf()`.
- `io_read()` returns `SIZE_MAX` on a read error (`file_io.c:1143-1146`).
- `io_write()` fails on a write error or a sparse seek error.
- `lzma_code()` returns any error other than `LZMA_UNSUPPORTED_CHECK` (`coder.c:1270`).
- Trailing garbage after the stream end becomes `LZMA_DATA_ERROR` (`coder.c:1294-1315`).
- Fatal exits (`message_fatal()`, `message_bug()`, `xrealloc()` failure) call `tuklib_exit()` → `exit()` without `io_close()`, so nothing is unlinked.

When `success` is false, `io_close_dest()` deletes the destination instead (`file_io.c:1019-1020`).

### Destination close fails (`io_close_dest()`, `file_io.c:1006-1015`)

`close(dest_fd)` fails → "Closing the file failed", the destination is unlinked, the function returns true, `io_close()` sets `success = false`, and the source is kept.

### Last check before `unlink()` (`io_unlink()`, `file_io.c:230-285`)

- On POSIX-like systems it calls `lstat(name)`, or `stat(name)` if `--force` was used (249-250).
- The result must match the `st_dev` and `st_ino` saved in `pair->src_st` by `fstat(src_fd)` at open time (line 609).
- If the stat fails or the numbers differ: warning "File seems to have been moved, not removing", and no unlink.
- On VMS only `st_ino` is compared.
- If `unlink(name)` fails: warning "Cannot remove: …", and the file stays.
- Both are warnings, so the exit status is `E_WARNING` (2), or 0 with `--no-warn` (`main.c:363-364`).

### OS-level backstop (`/tmp/xzmax/xz/src/xz/sandbox.c`, `main.c:225-261`)

- If output is stdout only (`opt_stdout`, `--list`, or all arguments are `-`), `sandbox_enable_read_only()` drops the right to remove files.
- With pledge the promises become `"stdio rpath"`; with Landlock only `READ_FILE` and `READ_DIR` remain.
- This covers only cases where xz would not delete anyway.
- The Capsicum version of this function does nothing.

## Not checked or not present in the code

- **No dev/inode check on DOS-like systems** (Windows non-Cygwin, OS/2, MSDOS): `io_unlink()` calls `unlink()` directly (233-236).
- **With `--force`, `stat()` replaces `lstat()`**, so a file renamed and replaced by a symlink to it is not detected. The code comment at 240-248 says so.
- **A small race between `lstat()` and `unlink()`** is acknowledged in comments (226-229, 278-279).
- **The return value of `close(src_fd)` is ignored** (`(void)close(...)`, line 767), although the function comment says "if closing succeeds".
- **Attribute-copy failures do not block deletion.** `fchown`/`fchmod` failures in `io_copy_attrs()` only warn, and timestamp calls are cast to `(void)`.
- **No `fsync`/`fdatasync` exists in `src/xz`.** Only `close()` returning 0 is required before the source is removed.
- **The output is never re-read or verified** before the unlink.
- **`user_abort` is not re-checked inside `io_close()`** once coding has succeeded.
- **Integrity is not a condition.** `LZMA_UNSUPPORTED_CHECK` is only a warning (`coder.c:1004-1007`, 1270), and `--ignore-check` skips verification. Decoding can still succeed and the source is removed.
- **With `--single-stream` or `.lz` input**, trailing bytes are not decoded but `success` is still true (`coder.c:1283-1287`).
- **The "never delete when writing to stdout" rule is not tested at the unlink site.** It works only because `args_parse()` forces `opt_keep_original = true`.

## Other unlink calls

- `io_close_dest()` removes the destination on failure (`file_io.c:1012`, 1020).
- `io_open_dest_real()` removes an existing target with `--force` (`file_io.c:837`).
- A search of `/tmp/xzmax/xz/src` found no other deletion of input files. The only other match is a temp-directory `rm -rf` in `src/scripts/xzdiff.in`.
