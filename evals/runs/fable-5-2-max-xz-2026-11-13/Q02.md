# Sandboxing in XZ Utils (checkout 7baf6835, 5.7.0alpha development tree)

## Short answer

Only the command-line tools sandbox themselves: `xz` (and its symlink names `unxz`, `xzcat`, `lzma`, `unlzma`, `lzcat`) and `xzdec` / `lzmadec`. The process asks the kernel to take away its own rights, using one OS facility chosen at build time.

| Platform | Facility | Build macro | Minimum version named in the tree |
|---|---|---|---|
| OpenBSD | `pledge(2)` | `HAVE_PLEDGE` | OpenBSD 5.9 |
| Linux | Landlock, plus `PR_SET_NO_NEW_PRIVS` | `HAVE_LINUX_LANDLOCK` | Linux 5.13; Landlock ABI versions 1 to 4 |
| FreeBSD | Capsicum (`cap_enter`, `cap_rights_limit`) | `HAVE_CAP_RIGHTS_LIMIT` | FreeBSD 10.2 |

- **Other systems:** the tree has no sandbox code for anything else (Windows, DOS, macOS, NetBSD, Solaris and so on). There `ENABLE_SANDBOX` stays undefined and `sandbox.c` compiles to `typedef int dummy;`.
- **Detection is by feature, not by OS name:** the build looks for the function or header, so the OS names above are the ones the documentation gives.
- **Not sandboxed:** liblzma, `lzmainfo` and the shell scripts have no sandbox code.

## Where the code is

- `/tmp/xzmax/xz/src/xz/sandbox.h` defines `ENABLE_SANDBOX` when any of the three macros is set. It declares `sandbox_init()`, `sandbox_enable_read_only()`, `sandbox_allow_strict()` and `sandbox_enable_strict_if_allowed(src_fd, pipe_event_fd, pipe_write_fd)`.
- `/tmp/xzmax/xz/src/xz/sandbox.c` holds the three implementations, selected by `#if defined(HAVE_PLEDGE)` / `#elif defined(HAVE_LINUX_LANDLOCK)` / `#elif defined(HAVE_CAP_RIGHTS_LIMIT)`.
- `/tmp/xzmax/xz/src/xz/main.c` (lines 158-170 and 225-261) and `/tmp/xzmax/xz/src/xz/file_io.c` (`io_open_src()`, lines 723-727) are the call sites in xz.
- `/tmp/xzmax/xz/src/xzdec/xzdec.c` has its own separate copy: `sandbox_enter(int src_fd)` plus early setup in `main()`. `lzmadec` is the same file built with `-DLZMADEC`.
- Build logic is in `/tmp/xzmax/xz/configure.ac` (lines 547-573, 1149-1216) and `/tmp/xzmax/xz/CMakeLists.txt` (lines 1739-1841, 1890-1893, 2048-2050).
- User documentation is in `/tmp/xzmax/xz/INSTALL` (lines 593-627).

## Build time: which method is compiled in

- **Options:** Autotools uses `--enable-sandbox=METHOD`; CMake uses the cache variable `XZ_SANDBOX`. Both accept `auto` (default), `no`, `capsicum`, `pledge`, `landlock`.
- **Probe order with `auto`:** Capsicum, then pledge, then Landlock. The first hit wins (`enable_sandbox=found` in configure, `SANDBOX_FOUND` in CMake), so exactly one macro is defined.
- **Capsicum and pledge probes:** a check for the function `cap_rights_limit` (CMake looks in `sys/capsicum.h`) and for `pledge` (CMake looks in `unistd.h`).
- **Landlock probe:** a test program including `<linux/landlock.h>`, `<sys/syscall.h>`, `<sys/prctl.h>` that uses `prctl(PR_SET_NO_NEW_PRIVS, ...)`, `SYS_landlock_create_ruleset`, `SYS_landlock_restrict_self` and `LANDLOCK_CREATE_RULESET_VERSION`. The header alone is not enough.
- **Explicit method not found:** configure stops with "`$enable_sandbox support not found`"; CMake raises `SEND_ERROR`.
- **Landlock with `-fsanitize=` in CFLAGS:** both build systems refuse to configure. The CI comment says the sandbox blocks `/proc`, which the sanitizer needs.
- **Both `--disable-xz` and `--disable-xzdec`:** configure forces `enable_sandbox=no`. `lzmadec` is not part of that test, so a lzmadec-only Autotools build gets no sandbox.
- **CMake targets:** `SANDBOX_COMPILE_DEFINITION` is added to `xz`, `xzdec` and `lzmadec`.
- **No run-time switch:** there is no command-line option or environment variable to turn the sandbox off.

## Run time in xz: three levels

| Level | Function | pledge (OpenBSD) | Landlock (Linux) | Capsicum (FreeBSD) |
|---|---|---|---|---|
| 1. Initial | `sandbox_init()` | `pledge("stdio rpath wpath cpath fattr", "")` | set no-new-privs, read the kernel ABI, then deny all filesystem rights except five | nothing ("Nothing to do") |
| 2. Read-only | `sandbox_enable_read_only()` | `pledge("stdio rpath", "")` | deny all except `LANDLOCK_ACCESS_FS_READ_FILE` and `LANDLOCK_ACCESS_FS_READ_DIR` | nothing |
| 3. Strict | `sandbox_enable_strict_if_allowed()` | `pledge("stdio", "")` | `enable_landlock(0)`: deny everything | `cap_enter()` plus `cap_rights_limit()` on each open descriptor |

**Level 1** always runs. `main()` calls it right after `tuklib_progname_init(argv)` and `io_init()`, before gettext, `hardware_init()` and `args_parse()`. The five rights Landlock keeps here are `LANDLOCK_ACCESS_FS_WRITE_FILE`, `_READ_FILE`, `_READ_DIR`, `_REMOVE_FILE` and `_MAKE_REG`.

**Level 2** runs after `args_parse()` when the local `to_stdout_only` is true, meaning no file will be created or deleted:
- `opt_stdout` is set (by `-c`, by the names `xzcat` / `lzcat`, or forced for `MODE_TEST` in `args_parse()`), or `opt_mode == MODE_LIST`; or
- `--files` / `--files0` was not used (`args.files_name == NULL`) and every file name is `-` (no names counts as one `-`).

**Level 3** needs level 2 plus `args.files_name == NULL && args.arg_count == 1`. Then `main()` calls `sandbox_allow_strict()`, which sets the static flag `strict_sandbox_allowed`.
- It is applied in `io_open_src()` right after `io_open_src_real()` succeeds, as `sandbox_enable_strict_if_allowed(pair.src_fd, user_abort_pipe[0], user_abort_pipe[1])`.
- So the single input is already open, and no input byte has been read yet by `coder_run()` or `list_file()`.
- `prepare_for_strict_sandbox()` runs first and forces files to load while that is still allowed. `snprintf(NULL, 0, "%s%s", _(dummy_str), strerror(EINVAL))` loads libc and xz translations; `tuklib_mbstr_width(dummy_str, NULL)` loads iconv data.

**Landlock details** (`enable_landlock(uint64_t required_rights)`):
- `sandbox_init()` calls `prctl(PR_SET_NO_NEW_PRIVS, 1, 0, 0, 0)` and stores the kernel ABI from `syscall(SYS_landlock_create_ruleset, NULL, 0, LANDLOCK_CREATE_RULESET_VERSION)` in the static `landlock_abi`.
- The ABI is capped to `LANDLOCK_ABI_MAX`: 4 if the build headers define `LANDLOCK_ACCESS_NET_BIND_TCP`, otherwise 3.
- The denied set is `handled_access_fs = ~required_rights & ((1ULL << (12 + my_min(3, landlock_abi))) - 1)`.
  - ABI 1 covers bits 0-12 (`LANDLOCK_ACCESS_FS_EXECUTE` to `LANDLOCK_ACCESS_FS_MAKE_SYM`).
  - ABI 2 adds `LANDLOCK_ACCESS_FS_REFER`.
  - ABI 3 adds `LANDLOCK_ACCESS_FS_TRUNCATE`.
- On ABI 4, `handled_access_net = LANDLOCK_ACCESS_NET_BIND_TCP | LANDLOCK_ACCESS_NET_CONNECT_TCP`.
- It then calls `SYS_landlock_create_ruleset` and `SYS_landlock_restrict_self`. `landlock_add_rule` is never called, so no path is exempt; the design relies on needed files being open already.

**Capsicum rights at level 3:**
- `src_fd`: `CAP_EVENT, CAP_FCNTL, CAP_LOOKUP, CAP_READ, CAP_SEEK`
- `STDIN_FILENO`, when it is not the source: all rights removed (`cap_rights_clear`)
- `STDOUT_FILENO`: `CAP_EVENT, CAP_FCNTL, CAP_FSTAT, CAP_LOOKUP, CAP_WRITE, CAP_SEEK`
- `STDERR_FILENO`: `CAP_WRITE`
- `user_abort_pipe[0]`: `CAP_EVENT`; `user_abort_pipe[1]`: `CAP_WRITE`

**What typical commands get:**
- `xz file` (creates `file.xz`, removes `file`), or `--files` without `-c`: level 1 only.
- `xz -c a b`, `xz -t a b`, `xz -l a b`: levels 1 and 2.
- `xz < in > out`, `xz -dc one.xz`, `xzcat one.xz`, `xz -t one.xz`, `xz -l one.xz`: all three levels.
- On FreeBSD only the last group is sandboxed at all, because levels 1 and 2 are empty for Capsicum.

## Run time in xzdec and lzmadec

- **Start of `main()`:**
  - OpenBSD: `pledge("stdio rpath", "")` as the first statement.
  - Linux: only `prctl(PR_SET_NO_NEW_PRIVS, 1, 0, 0, 0)`, no ruleset yet.
  - FreeBSD: nothing.
- **`sandbox_enter(src_fd)` is called before `uncompress()`:**
  - with `STDIN_FILENO` when no file names are given;
  - otherwise only for the last file name (`optind == argc - 1`), after `fopen`.
- **What it does:**
  - Capsicum: `cap_enter()`, then `CAP_READ` on the source, all rights cleared on stdin if unused, `CAP_WRITE` on stdout and stderr.
  - pledge: `pledge("stdio", "")`.
  - Landlock: the same ABI query and cap, then a ruleset denying all filesystem rights (`(1ULL << (12 + my_min(3, landlock_abi))) - 1`) plus TCP on ABI 4.
- **Several files:** the earlier ones are decoded with only `stdio rpath` (OpenBSD), only no-new-privs (Linux), or nothing (FreeBSD).

## When enabling fails

- **xz:** `message_fatal(_("Failed to enable the sandbox"))`, which exits with `E_ERROR` (1).
- **xzdec:** `my_errorf("Failed to enable the sandbox"); exit(EXIT_FAILURE);`.
- **Silent run without a sandbox, by design:**
  - Landlock: the kernel reports ABI <= 0 (`enable_landlock()` returns; xzdec skips the block).
  - Capsicum: `errno == ENOSYS` (kernel without capability mode, or an emulator).
- **`prctl()` result is ignored on purpose:** the comment says `landlock_restrict_self` fails later if no-new-privs is not set, and that failure is fatal.
- **pledge:** no silent path.

## Limits and things that are not there

- **No other isolation:** I searched the tree for seccomp, chroot, unveil, rlimits, uid dropping and fork-based separation and found none.
- **No sandbox tests:** `/tmp/xzmax/xz/tests` contains no test that mentions the sandbox.
- **CI:** default builds leave it on `auto`. The Linux ASan/UBSan and Valgrind jobs pass `-d sandbox`, which becomes `--enable-sandbox=no`. That switch only exists in the Autotools branch of `/tmp/xzmax/xz/build-aux/ci_build.bash`.
- **Documentation:** the man pages do not mention sandboxing. `INSTALL` describes only the single-file case for xz; the three levels are in the code and in `NEWS` for 5.6.0.
- **Admitted weakness:** a comment in `sandbox.c` calls `prepare_for_strict_sandbox()` a hack that may not be enough, and says a Landlock rule for `/usr` might then be needed.
- **Unclosed descriptor:** `ruleset_fd` is never closed, in `sandbox.c` and in `xzdec.c`.
- **Untranslated error:** `src/xz/sandbox.c` is not in `/tmp/xzmax/xz/po/POTFILES.in`. The 22 `.po` files that contain the string have it only as an obsolete `#~` entry.
- **Earlier sabotage, now fixed:** `NEWS` for 5.6.2 and commit f9cf4c05 say the CMake Landlock check had been sabotaged (a stray `.` made it never enable). I checked the test program at this commit and it is clean.
