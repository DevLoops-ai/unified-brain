# xz @ 7baf6835: from the last Block of Stream 1 to the first Block of Stream 2

**Method.** Everything is read from the checkout only (no web, no memory). Nothing was built or run. I hex-dumped the test files and recomputed their CRC32 fields with a read-only script. Short file names refer to the absolute paths listed at the end.

## Short version

- Index, Footer, Padding and the next Stream Header are all checked in the main thread, and only after the output queue is empty (`SEQ_INDEX_WAIT_OUTPUT`). So they always wait for every worker's result.
- The link between Blocks and Index is one small object, `coder->index_hash`. It holds totals plus a running hash (SHA-256 by default) of each Block's (Unpadded Size, Uncompressed Size).
- Recomputing CRC32 does not help an attacker in the Index or the Footer. Every content byte there is fixed by something already decoded.
- Only one memory condition is an error: `mem_next_filters > memlimit_stop` gives `LZMA_MEMLIMIT_ERROR`. Not fitting the threading limit only makes the Block wait, or be decoded in the main thread.

## 1. Which decoder runs

- `coder_run()` calls `coder_init()` (coder.c:810). A build with threads (`MYTHREAD_ENABLED`) always uses `lzma_stream_decoder_mt()` for .xz (coder.c:939-959).
- Flags (coder.c:867-879): `LZMA_CONCATENATED` unless `--single-stream`; `LZMA_TELL_UNSUPPORTED_CHECK` unless `--ignore-check`. `LZMA_FAIL_FAST` is not used in src/xz.
- Hard limit `memlimit_stop` comes from `--memlimit-decompress` / `-M`, and is unlimited if unset (hardware.c:174-186).
- Soft limit `memlimit_threading` comes from `--memlimit-mt-decompress`, default RAM/4, never above the hard limit (hardware.c:205-219, 322; stream_decoder_mt.c:1982-1985).
- `timeout` is 300 ms (coder.c:83-86).
- `coder_normal()` loops over `lzma_code()`. `action` becomes `LZMA_FINISH` when the input file hits EOF (coder.c:1135, 1208-1210).
- A Block runs in a worker only if its header has both size fields and it fits the soft limit. Otherwise the main thread decodes it ("direct mode").

## 2. Normal path (stream_decoder_mt.c unless noted)

1. **Block finish and Check, in the worker.** `worker_decoder()` (370-517) feeds `block_decode()` (block_decoder.c:63) in chunks of up to 16384 bytes.
   - `SEQ_CODE`: at end of data, the counted sizes must equal the Block Header sizes (137-141).
   - `SEQ_PADDING`: Block Padding must be zero bytes (153-167).
   - `SEQ_CHECK`: the stored Check is compared with the computed one (179-197). This is skipped with `ignore_check` or an unsupported Check type.
   - The worker then sets `outbuf->finished` and `outbuf->finish_ret`, sets `coder->thread_error` on error, and calls `worker_stop()` (351-367, 474-516).
2. **Main thread reaches the Index.** After copying the Block's bytes to the worker, `SEQ_BLOCK_THR_RUN` returns to `SEQ_BLOCK_HEADER` without waiting (1569-1573). `decode_block_header()` sees byte 0x00, returns `LZMA_INDEX_DETECTED` and does not consume it (887-890).
3. **`SEQ_INDEX_WAIT_OUTPUT`** (1644-1654). `read_output_and_wait()` runs until `lzma_outq_is_empty()`.
   - `lzma_outq_read()` (outqueue.c:229-270) returns each Block's `finish_ret` after its last byte, in Block order.
   - A Block error is returned here, after `threads_stop()`.
   - A full output buffer or a timeout returns `LZMA_OK` to the caller.
4. **`SEQ_INDEX_DECODE`** (1658-1675) calls `lzma_index_hash_decode()` (index_hash.c:172). Its checks run in this order:
   - Number of Records equals `blocks.count` (204-206).
   - Per Record: Unpadded Size is at least 5 (232-235), and the running totals do not exceed the Block totals (250-256).
   - Index Padding is 0-3 zero bytes; the count is computed, not read (266-281).
   - Totals are equal (284-290), then the two hashes are equal (293-298).
   - Only then is the stored CRC32 compared (308-322).
5. **`SEQ_STREAM_FOOTER`** (1679-1717).
   - `lzma_stream_footer_decode()` checks magic, then CRC32, then reserved bits (stream_flags_decoder.c:61-87).
   - `lzma_index_hash_size()` must equal Backward Size (1704-1706).
   - `lzma_stream_flags_compare()` checks the footer flags against the header's (1710-1711).
   - Without `LZMA_CONCATENATED` it returns `LZMA_STREAM_END` here (1713-1714).
6. **`SEQ_STREAM_PADDING`** (1721-1759). It eats zero bytes; `coder->pos` is the count mod 4.
   - Input empty: `LZMA_OK`, unless `LZMA_FINISH`. With `LZMA_FINISH`: `LZMA_STREAM_END` if `pos == 0`, else `LZMA_DATA_ERROR`.
   - First non-zero byte with `pos != 0`: `LZMA_DATA_ERROR`.
   - First non-zero byte with `pos == 0`: `stream_decoder_reset()` (951-965) re-initialises the index hash and goes to `SEQ_STREAM_HEADER`. The byte is not consumed.
7. **`SEQ_STREAM_HEADER`** (1034-1080). It buffers 12 bytes and calls `lzma_stream_header_decode()`. It stores `coder->stream_flags`, sets `SEQ_BLOCK_HEADER`, and may first return `LZMA_UNSUPPORTED_CHECK` (a warning).
8. **Back into Blocks.** `SEQ_BLOCK_HEADER` → `lzma_block_header_decode()` → `SEQ_BLOCK_INIT` (memory decisions, section 5.3). Then either `SEQ_BLOCK_THR_INIT` / `SEQ_BLOCK_THR_RUN` (worker) or `SEQ_BLOCK_DIRECT_INIT` / `SEQ_BLOCK_DIRECT_RUN` (main thread).

Direct-mode variant of steps 1-3: `SEQ_BLOCK_DIRECT_RUN` (1620-1642) decodes in the main thread and returns a Check error at once. The queue is already empty, so step 3 passes straight through.

## 3. State that links the stages

| State | Set by | Used by |
|---|---|---|
| `coder->stream_flags` (Check type) | Stream Header | Check size of each Block (`comp_blk_size()`, `lzma_block_unpadded_size()`); footer flags compare |
| `coder->block_options` | Block Header | memory decision, worker buffer size, Index-hash record |
| `coder->index_hash->blocks` (`blocks_size`, `uncompressed_size`, `count`, `index_list_size`, running hash) | `lzma_index_hash_append()` | Index compare; `lzma_index_hash_size()` for Backward Size |
| `lzma_outbuf.finished` / `finish_ret`; `thread_error`, `pending_error` | workers / main thread | error order |
| `coder->pos`, `coder->buffer` | header/footer buffering | padding count mod 4 |
| `first_stream` | first Stream Header | bad magic gives `LZMA_FORMAT_ERROR` vs `LZMA_DATA_ERROR` |

How Block sizes get into the hash:
- **Worker mode:** appended at `SEQ_BLOCK_INIT` (1295-1298) from the Block Header's claimed sizes, before the Block is decoded. This is safe because the Block decoder enforces those sizes, and step 3 reports any failure before the Index is read.
- **Direct mode:** appended after decoding (1635-1638), from the sizes the Block decoder counted and wrote back (block_decoder.c:145-146).

## 4. Failures

### 4.1 CRC alone vs other checks

| Where | Change | What catches it | Result |
|---|---|---|---|
| Index CRC32 field | damaged | CRC compare (index_hash.c:308-322) | `LZMA_DATA_ERROR` (CRC alone) |
| Index: count, Records, padding | any, CRC fixed or not | count / range / totals / hash / zero-padding checks; all run before the CRC | `LZMA_DATA_ERROR` |
| Footer fields | CRC not fixed | CRC (stream_flags_decoder.c:70-76) | `LZMA_DATA_ERROR` (CRC alone) |
| Footer magic | any | magic compare (65-67); no CRC covers it | `LZMA_FORMAT_ERROR`, turned into `LZMA_DATA_ERROR` |
| Footer Backward Size | CRC fixed | compare with `lzma_index_hash_size()` | `LZMA_DATA_ERROR` |
| Footer Check type | CRC fixed | `lzma_stream_flags_compare()` | `LZMA_DATA_ERROR` |
| Footer or next-header reserved bits | CRC fixed | `stream_flags_decode()` (15-26) | `LZMA_OPTIONS_ERROR` |
| Stream Padding | any | no CRC exists; zero-byte and multiple-of-4 rules only | see (c) |
| Next Stream Header magic | any | magic compare | `LZMA_DATA_ERROR` |
| Next Stream Header flags | CRC not fixed | CRC (38-45) | `LZMA_DATA_ERROR` (CRC alone) |
| Next Stream Header Check type | CRC fixed | accepted at the header | caught later, see below |

- In the Index, the CRC decides only when the CRC field itself is wrong. Every other byte must match what the Blocks imply, and non-minimal integer encodings are rejected (vli_decoder.c:62-63).
- A changed Check type in the next Stream Header is caught later by a Block Check or size error, or by that Stream's footer compare.
- If the new ID has the same size but is unsupported (for example 0x04 changed to 0x05), Blocks are decoded without Check verification. xz prints a warning, and the mismatch is reported only at that Stream's footer, after its output is out. (Traced by reading, not run.)

### 4.2 The four cases

**(a) Record with plausible but wrong sizes**
- **Detected:** in `lzma_index_hash_decode()`. A running total above the real one fails right after that Record. Otherwise it fails only after the last Record and padding, at the totals or hash compare.
- **Example:** `bad-2-index-1.xz` swaps two Unpadded Sizes. All totals still match and its Index CRC32 is valid, so only the hash compare rejects it. `bad-2-index-2.xz` is the same kind of case.
- **State:** `SEQ_INDEX_DECODE`; the queue is empty, so all data of Stream 1 has already gone to the caller.
- **More input:** cannot rescue it. If the file ends before the end of the Index, the result is `LZMA_BUF_ERROR` instead.
- **Caller:** `LZMA_DATA_ERROR` straight from `stream_decode_mt()` (1671-1672).

**(b) Index size vs Backward Size**
- Step 4 accepts only the exact Index the Blocks imply, including its length. So this can only be a wrong Backward Size in a footer with good magic and CRC.
- **Detected:** `SEQ_STREAM_FOOTER`, 1704-1706. The size comes from `blocks.count` and `blocks.index_list_size` (index_hash.c:112-120).
- **State:** all 12 footer bytes consumed, `coder->pos` is 0.
- **More input:** no.
- **Caller:** `LZMA_DATA_ERROR`. Test: `bad-0-backward_size.xz` (valid footer CRC; says 4, real Index is 8).

**(c) Stream Padding** (only with `LZMA_CONCATENATED`)
- **Length not a multiple of 4, then EOF:** `LZMA_DATA_ERROR` once `LZMA_FINISH` is given (1734-1736). Before that it returns `LZMA_OK` and more zero bytes could still fix it. Test: `bad-0pad-empty.xz`.
- **Non-zero byte while `pos != 0`:** `LZMA_DATA_ERROR` at once (1751-1755), fatal. Test: `bad-0catpad-empty.xz`.
- **Non-zero byte at a multiple of 4:** not a padding error. Padding ends and the byte is read as the start of a Stream Header, so case (d) applies.

**(d) Partial or invalid next Stream Header**
- **State:** `SEQ_STREAM_HEADER`; index hash already reset; `first_stream` is false.
- **Partial (under 12 bytes, then EOF):** the bytes are kept and it returns `LZMA_OK` even with `LZMA_FINISH` (1042-1043). `lzma_code()` turns the second call without progress into `LZMA_BUF_ERROR` (common.c:311-324).
  - More input would continue normally, but after `LZMA_FINISH` the API forbids new input (common.c:263-268).
  - xz prints "Unexpected end of input".
  - A complete valid header followed by EOF ends the same way from `SEQ_BLOCK_HEADER`.
- **Bad magic:** `LZMA_FORMAT_ERROR` turned into `LZMA_DATA_ERROR` (1050-1052). Tests: `bad-0cat-header_magic.xz`, `bad-0cat-alone.xz`.
- **Bad CRC:** `LZMA_DATA_ERROR`. **Reserved bits with fixed CRC:** `LZMA_OPTIONS_ERROR`. All fatal.

**Propagation in xz, all cases**
- `lzma_code()` marks fatal codes `ISEQ_ERROR` (common.c:362-366).
- `coder_normal()` flushes output and prints the `message_strm()` text (coder.c:1266-1343): "Compressed data is corrupt", "Unexpected end of input", "Unsupported options".
- `io_close(pair, false)` deletes the output file unless it is stdout (file_io.c:1017-1020). Exit status is 1.
- With `-c`, the earlier Stream's data has already been written.
- If the problem is reachable in the first input chunk without output space, the same message comes from the probe call in `coder_init()` (coder.c:1001-1027).

### 4.3 Concatenated vs single-stream

- **`--single-stream` (no `LZMA_CONCATENATED`):** steps 1-5 are the same. `LZMA_STREAM_END` comes right after the footer checks, without `LZMA_FINISH`. Padding and later bytes are never read, so (c) and (d) cannot happen. xz rewinds the unread bytes and reports success (coder.c:876-877, 1282-1287).
- **Concatenated:** `LZMA_STREAM_END` comes only from `SEQ_STREAM_PADDING`, with `LZMA_FINISH`, empty input, and padding a multiple of 4.

## 5. Threads and memory limits

### 5.1 What waits for workers

- Check, Block Padding and size checks happen inside the worker. The main thread sees only the result, in Block order.
- Index, Footer, Padding, next Stream Header and the next Stream's first Block are all behind step 3. That needs every worker finished and all output taken by the caller. Streams are done one at a time (container.h:757-758).
- The main thread does read ahead: it parses later Block Headers and appends their sizes to the hash while workers still run.

### 5.2 What must survive until the Index check

- Only `coder->index_hash` (fixed size), `coder->stream_flags`, and the error flags. There is no per-Block list.
- In worker mode a finished Block passes back only pass/fail (`finish_ret`). The size fields of `lzma_outbuf` are set to 0 and never read by the decoder (outqueue.c:209-210; stream_decoder_mt.c:677-679).
- Memory after a Block finishes: the worker's filter memory moves from `mem_in_use` to `mem_cached`. Its output buffer stays in `outq.mem_in_use` until the main thread has copied it all out.

### 5.3 Next Block needs more memory than is free

`SEQ_BLOCK_INIT` (1221-1306) computes `mem_next_block` = `mem_next_filters` + padded Compressed Size + Check size + `sizeof(lzma_outbuf)` + Uncompressed Size.

| Condition | Meaning | What happens |
|---|---|---|
| `mem_next_filters > memlimit_stop` (1228) | impossible under the hard limit | Flush the queue, then `LZMA_MEMLIMIT_ERROR`. State stays `SEQ_BLOCK_INIT`; decoding resumes after `lzma_memlimit_set()`. xz prints "Memory usage limit reached" and stops. No record is appended, so the Stream never completes. |
| Sizes missing, size above `SIZE_MAX/3`, or `mem_next_block > memlimit_threading` (1248-1285) | can never run in a worker | `SEQ_BLOCK_DIRECT_INIT`: wait for an empty queue, free caches, `threads_end()`, decode in the main thread. No error. The record is appended after decoding. |
| Fits the soft limit but not now: `memlimit_threading - mem_in_use - outq.mem_in_use < mem_next_block`, or no free queue slot, or no free thread (751-763) | only delayed | Wait in `SEQ_BLOCK_THR_INIT` inside `read_output_and_wait()`. It returns `LZMA_OK` on a full output buffer or timeout. The record was already appended. Caches are trimmed before start (1385-1424). |

- **First Block of a new Stream:** the queue is empty after step 3, so nothing is in use and row 3 cannot occur (comment at 749-750). Only rows 1 and 2, or an immediate threaded start, are possible.
- **After raising the hard limit:** `memlimit_threading` is not changed (1824-1825), so that Block is decoded in direct mode.
- **Memory figure xz prints:** `stream_decoder_mt_memconfig()` reports only memory already allocated (1843-1852) and does not add `mem_next_filters`. So the "MiB of memory is required" line from `lzma_memusage()` (coder.c:1334-1339) is not the need of the refused Block. The single-threaded decoder stores the needed amount first (stream_decoder.c:229-233). This is from reading, not run.

### 5.4 Error order

- **Worker errors** come out through `finish_ret`, in stream order, after earlier output.
- **Main-thread errors found ahead** (bad Block Header, hash append, decoder init) are held in `pending_error` and returned from `SEQ_ERROR` (1761-1784) after the queue is flushed. An earlier worker error wins.
- **Index, Footer, Padding and Stream Header errors** return directly; the queue is empty by then.
- **`LZMA_MEM_ERROR`** (allocation failure) returns at once, not in order (FIXME at 1767-1770).

## 7. Differences by platform, build, mode

- **No thread support in the build:** xz uses `lzma_stream_decoder()` (stream_decoder.c). Same Index/Footer/Padding logic, no queue, hard limit only.
- **`-T1` or one CPU:** `memlimit_threading` is 0, so every Block uses direct mode (coder.c:955-957).
- **Files without size fields in Block Headers** (single-threaded xz output): always direct mode.
- **32-bit:** sizes above `SIZE_MAX/3` force direct mode; the soft-limit default is capped at 1400 MiB.
- **`LZMA_CHECK_BEST`:** SHA-256, else CRC64, else CRC32, depending on enabled checks (check.h:65-73). A weaker hash weakens the Index compare.
- **`FUZZING_BUILD_MODE_UNSAFE_FOR_PRODUCTION`:** header, footer and Index CRC32 failures are ignored; the other checks stay.
- **`--ignore-check` or unsupported Check ID:** the Block Check is not verified.
- **`LZMA_FAIL_FAST`** (not used by xz): worker errors return at once.
- **`xz -l`:** a different path (`lzma_file_info_decoder`); no Blocks are decoded.
- **xzdec:** single-threaded decoder, no memory limit.

## 8. Not checked / not present in the code

- Stream Padding has no check beyond zero bytes and length.
- Nothing after the footer is examined in single-stream mode.
- There are no whole-file limits; the index hash is reset per Stream.
- The Check type is not compared across Streams.
