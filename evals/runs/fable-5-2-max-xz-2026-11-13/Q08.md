# Detecting a modified Index in XZ Utils (commit 7baf6835)

**Basis.** Everything here is read from the source. I did not build or run xz (no-write rule). I parsed the repo's `tests/files/bad-*index*.xz` files in memory, recomputed their CRC32s, and replayed the check order below with a small model of my own. So "accepted by `xz -l`" means "traced through the code", not "observed".

## 1. Starting facts

1. **The Index has only one valid encoding.** Layout (`doc/xz-file-format.txt` §4): `0x00`, Number of Records, then {Unpadded Size, Uncompressed Size} per Block, 0-3 zero bytes, CRC32. `lzma_vli_decode()` rejects non-minimal and longer-than-9-byte integers (`vli_decoder.c:62`, `:79`), and the padding length is computed, not read. Any byte change therefore breaks the format or changes the count or sizes.
2. **Nothing outside the Index protects its content.** Its CRC32 has no key, so an attacker recomputes it. The Stream Footer CRC32 covers only Backward Size and Stream Flags (`stream_flags_decoder.c:70`).
3. **There are two consumers.** A full decode compares the Index with the Blocks it just decoded. `xz --list` reads only the Index and trusts it.

## 2. Path A: full decode

Used by `lzma_stream_decoder` (`stream_decoder.c`), `lzma_stream_decoder_mt` (`stream_decoder_mt.c`), `lzma_stream_buffer_decode` and `lzma_auto_decoder`, so by `xz -d`, `xz -t` and `xzdec`.

**Reference values.** After each Block the decoder calls `lzma_index_hash_append()` with the real Unpadded Size and Uncompressed Size (`stream_decoder.c:270`; MT: `:1295` in `SEQ_BLOCK_INIT`, `:1635` in `SEQ_BLOCK_DIRECT_RUN`). `hash_append()` (`index_hash.c:124`) keeps these in `index_hash->blocks`:
- `count`
- `blocks_size`: sum of sizes rounded up to 4 with `vli_ceil4()`
- `uncompressed_size`
- `index_list_size`: sum of VLI byte lengths
- `check`: a running `LZMA_CHECK_BEST` hash over each raw 16-byte size pair

`lzma_index_hash_decode()` then parses the Index into `index_hash->records` and checks in this order. Every failure is `LZMA_DATA_ERROR` unless noted.

| # | State | What must hold |
|---|---|---|
| A1 | stream decoder `SEQ_BLOCK_HEADER` (MT: `decode_block_header()` returns `LZMA_INDEX_DETECTED`), then hash `SEQ_BLOCK` | First byte is `INDEX_INDICATOR` (0x00). If not, the bytes are parsed as a Block Header instead. |
| A2 | `SEQ_COUNT` | Number of Records equals `blocks.count`. |
| A3 | `SEQ_UNPADDED` | `UNPADDED_SIZE_MIN` (5) ≤ Unpadded Size ≤ `UNPADDED_SIZE_MAX` (`LZMA_VLI_MAX & ~3`). |
| A4 | `SEQ_UNCOMPRESSED` | After each Record, the running `records.blocks_size`, `.uncompressed_size` and `.index_list_size` must not exceed the `blocks.*` totals. |
| A5 | `SEQ_PADDING` | The computed number of padding bytes are all 0x00. |
| A6 | `SEQ_PADDING`, `pos == 0` | The three totals are equal. |
| A7 | same | `lzma_check_finish()` on both hashes, then `memcmp()` over `lzma_check_size(LZMA_CHECK_BEST)` bytes. |
| A8 | `SEQ_CRC32` | Stored CRC32 equals the CRC32 of Indicator through Padding. |
| A9 | stream decoder `SEQ_STREAM_FOOTER` | Footer decodes; `lzma_index_hash_size(index_hash) == footer_flags.backward_size`; `lzma_stream_flags_compare()` passes. |

Notes:
- **A7 is the only check that sees each Record and their order.** A4 and A6 see only sums, and the size sum uses rounded sizes.
- `LZMA_CHECK_BEST` is SHA-256 when `HAVE_CHECK_SHA256` is defined (`check.h:67`), which is the default in configure and CMake. Otherwise it is CRC64, then CRC32.
- I found no decoder flag that skips A1-A9. `LZMA_IGNORE_CHECK` only skips the Block Check.
- A9's Backward Size test uses sizes from the real Blocks, so it adds nothing for an Index-only change.
- **All output is produced before A1 runs.** A changed Index cannot change the decompressed bytes; it only makes the run fail at the end. xz then deletes the output file (`io_close_dest()`, `file_io.c:1019`), but with `-c` or `xzdec` the data is already written.

## 3. Path B: Index-only decode (`xz --list`)

`parse_indexes()` in `list.c` runs `lzma_file_info_decoder` (`file_info.c`), which uses `index_decode()` (`index_decoder.c`) and `lzma_index_append()` (`index.c`). It reads backwards: footer, Index, Stream Header. No Block is decoded.

| # | State | What must hold |
|---|---|---|
| B1 | file_info `SEQ_MAGIC_BYTES` | File size ≤ `LZMA_VLI_MAX` and a multiple of 4. |
| B2 | `SEQ_FOOTER` | Footer decodes; `backward_size + LZMA_STREAM_HEADER_SIZE` fits before it. The Index is taken to be the `backward_size` bytes before the footer. |
| B3 | index_decoder `SEQ_INDICATOR` | First byte is 0x00. |
| B4 | `SEQ_COUNT`, `SEQ_MEMUSAGE` | `lzma_index_memusage(1, count) <= memlimit`, else `LZMA_MEMLIMIT_ERROR`. xz passes `hardware_memlimit_get(MODE_LIST)`, which is `UINT64_MAX` unless a limit was set. |
| B5 | `SEQ_UNPADDED` | Same range as A3. |
| B6 | `SEQ_UNCOMPRESSED`, `lzma_index_append()` | Limits only: Uncompressed sum ≤ `LZMA_VLI_MAX` (`index.c:660`), Unpadded sum ≤ `UNPADDED_SIZE_MAX`, `index_file_size()` in range, `index_size()` ≤ `LZMA_BACKWARD_SIZE_MAX`. |
| B7 | `SEQ_PADDING` | Padding bytes are zero. |
| B8 | `SEQ_CRC32` | CRC32 matches. |
| B9 | file_info `SEQ_INDEX_DECODE` | The Index uses exactly Backward Size bytes (`index_remaining` tests, `file_info.c:475-502`). |
| B10 | same, then `SEQ_HEADER_DECODE` | `lzma_index_total_size() + LZMA_STREAM_HEADER_SIZE` must lead back to offset 0 or to a valid Stream Header (`reverse_seek()`, `lzma_stream_header_decode()`). |
| B11 | `SEQ_HEADER_COMPARE` | `lzma_stream_flags_compare(header, footer)` passes. |

- **What B pins down:** format, CRC32, byte length, and the rounded total of the Unpadded Sizes.
- **What B does not check:**
  - the Record count against the real Blocks
  - how the total is split between Records
  - an Unpadded Size changed without crossing a multiple of 4
  - any Uncompressed Size, apart from the overflow limit
- `lzma_index_decoder()` and `lzma_index_buffer_decode()` on their own do only B3-B8.

## 4. Path C: per-Block cross-checks

Only `xz -lvv` (`V_DEBUG`) does this: `parse_details()` calls `parse_block_header()` at each offset taken from the Index.

| # | `list.c` | Check |
|---|---|---|
| C1 | `:456` | First byte at the Block offset is not 0x00. |
| C2 | `:467` | Block Header size fits inside the Record's size. |
| C3 | `:471` | `lzma_block_header_decode()` passes, including the Block Header CRC32. |
| C4 | `:507` | `lzma_block_compressed_size(&block, unpadded_size)`: Unpadded Size must exceed header plus Check size, and must match the header's Compressed Size if that field exists. |
| C5 | `:516` | Index Uncompressed Size must match the header's, if that field exists. |

- The matching halves of C4 and C5 only work when the Block Header carries the size fields. The single-threaded encoder writes neither (`stream_encoder.c:68-69`); the threaded encoder writes both (`stream_encoder_mt.c:307`).
- `parse_check_value()` prints the Check field and does not verify it.

## 6. Bottom line

- **Full decode, default build:** no Index change survives. Which check fires depends on the change:
  - net increase of a sum: A4
  - net decrease: A6
  - sum-neutral change: A7
  - CRC-only change: A8
- **`xz -l` alone is not an integrity check of Index content.** With the CRC32 fixed it accepts any Uncompressed Size values, any split with the same rounded total, and a changed Record count if the byte length still fits. Those are exactly the changes that later fail `xz -t` or `xz -d`.
- `xz -lvv` adds per-Block checks, but they are only strong when Block Headers carry size fields.
- I found no change that passes Path A and then fails B or C. This follows from the one-valid-encoding fact.

## 7. Not checked, not present, not run

- **No keyed protection:** the Index bytes have only the CRC32.
- **Weaker hash without SHA-256:** A7 then falls back to CRC64 or CRC32, which is not collision-resistant. The spec (§4.3) warns about this. I did not try to build a collision.
- **Fuzzing builds:** `FUZZING_BUILD_MODE_UNSAFE_FOR_PRODUCTION` turns off the CRC32 failures (A8, B8, and the header, footer and Block Header CRC32s).
- **No random-access Block reader in the tree.** The spec rule for such readers (§4.3) is left to applications. The API hooks are `lzma_block_compressed_size()` and the Block decoder's size checks (`compressed_limit`, `uncompressed_limit`, `is_size_valid()` in `block_decoder.c`). They only act if the application copies the Index sizes into `lzma_block` (see the comment at `list.c:510-515`).
- **Early stop:** an application that stops calling `lzma_code()` after the last Block's output never reaches A1-A9.
- **Tests:** `tests/test_files.sh` runs bad files through `xz -dc` and `xzdec`, and `xz -l` only on `bad-3-index-uncomp-overflow.xz`. `tests/test_index.c:8` has a todo for `lzma_file_info_decoder` tests.
- **Assert only:** the final size test in `file_info.c:637` is an `assert`, not a runtime check.
