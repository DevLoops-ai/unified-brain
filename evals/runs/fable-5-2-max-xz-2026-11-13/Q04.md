# How XZ Utils (commit 7baf6835) verifies or constrains its test fixture files

**Short answer.** There is no checksum list, signature or manifest for the fixtures. The 95 fixtures in `/tmp/xzmax/xz/tests/files/` (the only binary files tracked in the repo) are checked indirectly, in nine ways:

1. A naming contract and per-file notes in a README.
2. A script that decodes every fixture and checks pass/fail against its name.
3. The check fields stored inside the file formats, verified by the decoders.
4. C tests that load named fixtures under size limits and compare a few pinned values.
5. One golden-output script test.
6. Provenance rules (recreate recipes, generated inputs, removal of files that could not be reproduced).
7. Build isolation (the build never reads fixtures).
8. A release-time file-name whitelist.
9. CI and platform guards.

Sources: only files under `/tmp/xzmax/xz` (its `.git` history where marked). No web, no memory.

## 1. Naming contract and README
`/tmp/xzmax/xz/tests/files/README`
- Lines 15-26 define the three classes:
  - `good-*` must decode "without requiring a lot of CPU time or RAM".
  - `unsupported-*` are valid files using features the format spec does not define.
  - `bad-*` must give an error, also cheaply.
- Sections 2-4 describe each file. I compared names: the README lists exactly the 95 files present. No test enforces this match.
- Lines 9-10: many files were made by hand with a hex editor, so "there is no better 'source code' than the files themselves".

## 2. `test_files.sh`: every fixture must behave as its name says
`/tmp/xzmax/xz/tests/test_files.sh` loops over globs in `$srcdir/files`:

| Files | Command | Required result (lines) |
|---|---|---|
| `good-*.xz` | `xz -dc`, `xzdec` | exit 0 (61-108) |
| `bad-*.xz` | `xz -dc`, `xzdec` | must fail (110-124) |
| `bad-3-index-uncomp-overflow.xz` | `xz -l` | must fail (127-131) |
| `unsupported-*.xz` | `xz -dc` only | must fail (133-142) |
| `unsupported-check.xz` | `xz -dcqQ`, `xzdec -qQ` | exit 0 (145-158) |
| `good-*.lzma` / `bad-*.lzma` | `xz -dc` | exit 0 / must fail (165-181) |
| `good-*.lz` / `bad-*.lz`, `unsupported-*.lz` | `xz -dc` | exit 0 / must fail, only if `HAVE_LZIP_DECODER` (188-206) |

- The eight globs cover all 95 files. Output goes to `/dev/null`; only the exit status counts.
- `have_feature()` (39-46) skips files whose decoder is missing in `../config.h` and sets `EXIT_STATUS=77`, so a partial run reports SKIP, not PASS.
- `NO_WARN=-qQ` (55-59) applies when CRC64 or SHA-256 is not built. Good files then pass without their check being verified, and the xzdec test of bad files is skipped (117-120).
- Automake always runs it (`TESTS` in `/tmp/xzmax/xz/tests/Makefile.am`). CMake runs it only `if(UNIX AND HAVE_ALL_DECODERS AND HAVE_ALL_CHECKS AND XZ_LZIP_DECODER)` (`/tmp/xzmax/xz/tests/tests.cmake:180`).

## 3. Checks stored inside the formats (what makes step 2 meaningful)

| Format | Code | What is verified |
|---|---|---|
| `.xz` headers | `lzma_stream_header_decode()`, `lzma_stream_footer_decode()` in `/tmp/xzmax/xz/src/liblzma/common/stream_flags_decoder.c` | Magic bytes (`LZMA_FORMAT_ERROR`), CRC32 of Stream Flags (`LZMA_DATA_ERROR`), reserved bits (`LZMA_OPTIONS_ERROR`) |
| `.xz` Block Header | `lzma_block_header_decode()` in `block_header_decoder.c` | Header CRC32, size sanity, unknown flags, non-zero padding |
| `.xz` payload | `block_decode()` in `block_decoder.c`, states `SEQ_CODE`, `SEQ_PADDING`, `SEQ_CHECK` | Sizes against the header (`is_size_valid()`), zero padding, then `lzma_check_update()`/`lzma_check_finish()` and a `memcmp` with the stored Check (lines 179-197) |
| `.xz` Index | `lzma_index_hash_append()`/`lzma_index_hash_decode()` in `index_hash.c`, states `SEQ_BLOCK` to `SEQ_CRC32` | Record count and sizes must match the decoded Blocks; hash of size pairs with `LZMA_CHECK_BEST` (`check/check.h:67-73`); Index CRC32 |
| `.xz` end | `stream_decode()` in `stream_decoder.c`, states `SEQ_STREAM_FOOTER`, `SEQ_STREAM_PADDING` | Backward Size equals `lzma_index_hash_size()`; `lzma_stream_flags_compare()`; padding is a multiple of 4 |
| `xz -l` | `parse_indexes()` in `/tmp/xzmax/xz/src/xz/list.c`, then `index_decode()`, then `lzma_index_append()` | Uncompressed-size overflow check (`index.c:659-661`), needed by `bad-3-index-uncomp-overflow.xz` |
| `.lz` | `lzip_decode()` in `lzip_decoder.c`, states `SEQ_ID_STRING` to `SEQ_MEMBER_FOOTER` | Magic, version > 1 (`LZMA_OPTIONS_ERROR`), dictionary size range, footer CRC32, data size, member size |
| `.lzma` | `alone_decode()` in `alone_decoder.c` | No checksum in this format. Only header sanity and the size / end-marker rules in `lzma/lzma_decoder.c` |

- The payload check is skipped for `LZMA_CHECK_NONE`, for a check type not built in (`lzma_check_is_supported()`), or with `LZMA_IGNORE_CHECK`.
- `xz` uses `lzma_stream_decoder_mt()` when threads are built in; it calls the same helpers.
- `coder_init()` in `/tmp/xzmax/xz/src/xz/coder.c` sets `LZMA_TELL_UNSUPPORTED_CHECK`. An unsupported check becomes `message_warning()`, exit status `E_WARNING` (2), which `-Q` turns into 0.
- `xzdec` calls `lzma_stream_decoder(strm, UINT64_MAX, LZMA_CONCATENATED)` (`/tmp/xzmax/xz/src/xzdec/xzdec.c:182`): no memory limit and no unsupported-check warning.
- The macro `FUZZING_BUILD_MODE_UNSAFE_FOR_PRODUCTION` turns off the five header/Index CRC32 rejections. No build file in the repo defines it.

## 4. C tests: loader limits and pinned values
Loader: `tuktest_file_from_srcdir()` calls `tuktest_file_from_x()` (`/tmp/xzmax/xz/tests/tuktest.h:642-770`).
- It prefixes the name with the env variable `srcdir` and opens the file in `"rb"` mode.
- It rejects a NULL or empty name, an open failure, an empty file, a short read, and read/close errors.
- It rejects a size above `TUKTEST_FILE_SIZE_MAX` (`64L << 20`, 64 MiB, never overridden).
- Any failure is a hard error through `tuktest_error_impl()`: exit status 99 (`TUKTEST_EXIT_ERROR`), and the remaining tests in that program do not run.

| Test | Fixtures | What is pinned |
|---|---|---|
| `test_lzip_decoder.c` (`basic_lzip_decode`, `trailing_helper`, `test_concatenated`, `test_invalid_memlimit`) | 8 `good-*.lz` | CRC32 of output equals `hello_world_crc = 0x15A2A343`; trailing bytes equal `trailing_garbage_crc = 0x87081A60`; `total_in` against file size; `MEMLIMIT (1U << 20)` |
| `test_lzip_decoder.c` (`decode_expect_error`, `test_crc`) | 7 `bad-*.lz`, `unsupported-1-v234.lz` | Exact error: `LZMA_DATA_ERROR`, `LZMA_OPTIONS_ERROR` (v234), `LZMA_BUF_ERROR` (trailing-magic) |
| `test_check.c` (`test_lzma_get_check_st`, `_mt`) | `good-1-check-{none,crc32,crc64,sha256}.xz`, `unsupported-check.xz` | `LZMA_NO_CHECK` / `LZMA_UNSUPPORTED_CHECK` / `LZMA_GET_CHECK`, the check ID from `lzma_get_check()`, output fits 128 bytes |
| `test_bcj_exact_size.c` (`test_empty_block`) | `good-1-empty-bcj-lzma2.xz` | Decodes with zero output space; `in_pos == in_size`, `out_pos == 0` |
| `test_memlimit.c` | `good-1-check-crc32.xz`, `good-unknown_size-with_eopm.lzma` | Fails at 1234 bytes, passes at 2 MiB |

26 of the 95 fixtures are named in tests. The other 69 are covered only by the loops in step 2.

## 7. Build isolation

## Not present, or weak
- **No hashes, signatures or manifest.** Deleting a fixture is not noticed unless a test names it. A `bad-*` glob that matches nothing still "fails".
- **Content is mostly unpinned.** `test_files.sh` discards the output and the error reason. The README says the rejection reason matters for `bad-1-vli-1/2`, `bad-1-block_header-4` and `bad-2-index-5`; nothing checks it.
- **Some payloads have no check.** The `.lzma` format has none. Four `.xz` fixtures declare check None; `good-1-check-none.xz` is the only good one.
- **The CPU/RAM rule is not enforced.** `test_files.sh` passes no `--memlimit`, and neither it nor `tests.cmake` sets a timeout.
