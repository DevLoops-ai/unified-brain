# How long GitHub keeps workflow logs and artifacts

## Default

By default, the artifacts and log files generated by workflows are kept for 90 days and are then deleted automatically. The same default applies to checks, workflow runs and commit statuses. (data/reusables/actions/about-artifact-log-retention.md, included in content/organizations/managing-organization-settings/configuring-the-retention-period-for-github-actions-artifacts-and-logs-in-your-organization.md and in content/repositories/managing-your-repositorys-settings-and-features/enabling-features-for-your-repository/managing-github-actions-settings-for-a-repository.md)

## How far you can change it — and the public/private difference

Yes, public and private repositories are different on GitHub Free/Pro/Team and GitHub Enterprise Cloud:

| Product | Repository type | Allowed retention period |
|---|---|---|
| GitHub Free/Pro/Team, GitHub Enterprise Cloud | Public | 1 to 90 days |
| GitHub Free/Pro/Team | Private | 1 to 400 days |
| GitHub Enterprise Cloud | Private and internal | 1 to 400 days |
| GitHub Enterprise Server | Any (no public/private split is stated) | 1 to 400 days |

(data/reusables/actions/about-artifact-log-retention.md; the enterprise policy article gives the same ranges: content/admin/enforcing-policies/enforcing-policies-for-your-enterprise/enforcing-policies-for-github-actions-in-your-enterprise.md)

So for a public repository you can only shorten the period (90 days is both the default and the maximum); for a private repository you can shorten it or extend it up to 400 days.

## Rules that apply to a change

- A new retention period only applies to new checks, workflow runs, commit statuses, artifacts and log files. It is not applied to objects that already exist. (data/reusables/actions/about-artifact-log-retention.md)
- For managed repositories and organizations, the maximum retention period cannot be higher than the limit set by the managing organization or enterprise. (data/reusables/actions/about-artifact-log-retention.md)
- The retention policies cover checks data (check suites and check runs) and commit statuses too, including those created by third-party integrations, not only data created by GitHub Actions. (data/reusables/actions/checks-and-statuses-retention-scope.md)
- GitHub Free/Pro/Team and GitHub Enterprise Cloud only: the documentation states that from October 1, 2026 these policies apply to checks, workflow runs and commit statuses in addition to artifacts and logs; until that date checks, workflow runs and commit statuses were kept for 400+ days regardless of the configured period. (data/reusables/actions/about-artifact-log-retention.md)

## Where to change it

Retention can be set at repository, organization and enterprise level. (content/actions/how-tos/manage-workflow-runs/remove-workflow-artifacts.md)

- Repository: repository **Settings** > Actions > General, under **Check, workflow run, status, artifact and log retention**, enter a new value and click **Save**. (content/repositories/managing-your-repositorys-settings-and-features/enabling-features-for-your-repository/managing-github-actions-settings-for-a-repository.md; data/reusables/actions/change-retention-period-for-artifacts-logs.md)
- Organization: organization settings > Actions > General, same field. (content/organizations/managing-organization-settings/configuring-the-retention-period-for-github-actions-artifacts-and-logs-in-your-organization.md)
- Enterprise (GitHub Enterprise Cloud and GitHub Enterprise Server only): as an enterprise policy. (content/admin/enforcing-policies/enforcing-policies-for-your-enterprise/enforcing-policies-for-github-actions-in-your-enterprise.md)

## A single artifact

You can give one artifact its own retention period with `retention-days` in the `actions/upload-artifact` step, for example `retention-days: 5`. The value cannot exceed the retention limit set by the repository, organization or enterprise. (content/actions/tutorials/store-and-share-data.md)

## Other useful facts

- Inside a workflow, the current value is available as the variable `GITHUB_RETENTION_DAYS` and as `github.retention_days` (the number of days that workflow run logs and artifacts are kept, for example `90`). (content/actions/reference/workflows-and-actions/variables.md; content/actions/reference/workflows-and-actions/contexts.md)
- You can check when an artifact is scheduled to be deleted with the `expires_at` value returned by the REST API. (content/actions/how-tos/manage-workflow-runs/remove-workflow-artifacts.md)
- When a workflow run is deleted, all artifacts of that run are also deleted from storage. (data/reusables/actions/artifacts/artifacts-from-deleted-workflow-runs.md)
- Caches are a separate setting, not part of this retention period: by default caches are kept 7 days; this can be raised up to 90 days for public repositories or 365 days for private and internal repositories. (content/repositories/managing-your-repositorys-settings-and-features/enabling-features-for-your-repository/managing-github-actions-settings-for-a-repository.md)
