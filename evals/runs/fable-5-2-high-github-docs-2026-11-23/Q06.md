# Text-message codes and a backup phone number on GitHub Enterprise Server (Nigeria)

## Short answer

- **Codes by text message: no.** On GitHub Enterprise Server the documentation does not offer text messages (SMS) as a two-factor method at all. This is because of the product, not only because of the country.
- **Second phone number as backup: no.** A fallback SMS number is no longer supported, and that feature was documented only for GitHub Free/Pro/Team and GitHub Enterprise Cloud anyway.
- Use an authenticator (TOTP) app, and add a security key or passkey plus your recovery codes as backup.

## Why text messages are not available to you

1. **Product.** In the documentation, every mention of text messages is marked as applying only to GitHub Free/Pro/Team and GitHub Enterprise Cloud:
   - "You can configure two-factor authentication using a TOTP app on mobile or desktop" — the words "or via text message" appear only for GitHub Free/Pro/Team and GitHub Enterprise Cloud. The whole section "Configuring two-factor authentication using text messages" is also limited to those products. (content/authentication/securing-your-account-with-two-factor-authentication-2fa/configuring-two-factor-authentication.md)
   - For GitHub Enterprise Server the second factor is described as "a code that's generated by an application on your mobile device"; "or sent as a text message (SMS)" is added only for GitHub Free/Pro/Team and GitHub Enterprise Cloud. (content/authentication/securing-your-account-with-two-factor-authentication-2fa/about-two-factor-authentication.md)
   - The sections "Changing the SMS number" and "Adding an SMS number" are also limited to GitHub Free/Pro/Team and GitHub Enterprise Cloud. (content/authentication/securing-your-account-with-two-factor-authentication-2fa/changing-your-two-factor-authentication-method.md)
   - The article "Countries where SMS authentication is supported" itself is published only for GitHub Free/Pro/Team and GitHub Enterprise Cloud (front matter `versions: fpt, ghec`; no GitHub Enterprise Server). (content/authentication/securing-your-account-with-two-factor-authentication-2fa/countries-where-sms-authentication-is-supported.md)
2. **Country.** Even on GitHub.com, Nigeria is not in the list of supported countries and regions for SMS authentication. The article says: if your country is not on the list, GitHub cannot currently deliver text messages reliably to your country, and you can set up authentication with a TOTP mobile application instead. The list is updated periodically. (content/authentication/securing-your-account-with-two-factor-authentication-2fa/countries-where-sms-authentication-is-supported.md)

## Why you cannot add a second phone number

- "Configuring a fallback SMS number in addition to your primary SMS number is no longer supported. Instead, we strongly recommend registering multiple authentication methods." (content/authentication/securing-your-account-with-two-factor-authentication-2fa/recovering-your-account-if-you-lose-your-2fa-credentials.md)
- The section "Authenticating with a fallback number" that contains this note is shown only for GitHub Free/Pro/Team and GitHub Enterprise Cloud, not for GitHub Enterprise Server. (same file)

## What you can use instead on GitHub Enterprise Server

- **Authenticator (TOTP) app** on your phone or desktop. This is the method GitHub strongly recommends; many TOTP apps can back up your codes to the cloud so you can restore them if you lose the device. (content/authentication/securing-your-account-with-two-factor-authentication-2fa/configuring-two-factor-authentication.md)
- **Security key** as an extra method, after you have set up the TOTP app. If you lose the security key you can still sign in with the code from your phone. (content/authentication/securing-your-account-with-two-factor-authentication-2fa/configuring-two-factor-authentication.md; data/reusables/two_fa/after-2fa-add-security-key.md)
- **Passkey**, optional; the passkey article applies to GitHub Enterprise Server too. (content/authentication/authenticating-with-a-passkey/about-passkeys.md, front matter `versions`)
- **Recovery codes**: download and store them when you set up two-factor authentication; you can use them if you lose access to your phone. (data/reusables/two_fa/about-recovery-codes.md; content/authentication/securing-your-account-with-two-factor-authentication-2fa/configuring-two-factor-authentication-recovery-methods.md)
- GitHub recommends more than one two-factor method and several recovery methods (recovery codes file, SSH keys, personal access tokens, verified devices). (content/authentication/securing-your-account-with-two-factor-authentication-2fa/changing-your-two-factor-authentication-method.md; content/authentication/securing-your-account-with-two-factor-authentication-2fa/configuring-two-factor-authentication-recovery-methods.md)
- GitHub Mobile as a second factor is documented only for GitHub Free/Pro/Team and GitHub Enterprise Cloud, so not for GitHub Enterprise Server. (content/authentication/securing-your-account-with-two-factor-authentication-2fa/configuring-two-factor-authentication.md)

## One thing to check with your site administrator

On GitHub Enterprise Server, whether two-factor authentication is handled by the server at all depends on how your company's instance signs users in (data/reusables/two_fa/auth_methods_2fa.md; data/reusables/two_fa/2fa_not_supported_with_saml_and_cas.md):

| Sign-in method of the instance | Two-factor authentication |
|---|---|
| Built-in authentication | Supported and managed on the GitHub Enterprise Server appliance |
| LDAP | Supported and managed on the GitHub Enterprise Server appliance |
| Built-in authentication with an identity provider | Depends on the identity provider |
| SAML or CAS | Not supported or managed on the appliance; may be supported by the external authentication provider |

If your company uses SAML, CAS or an identity provider, the second factor (and whether it can be a text message) is decided by that provider, not by GitHub Enterprise Server. The GitHub documentation does not say what such a provider offers.
