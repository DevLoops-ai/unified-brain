# What happens to forks

## 1. You delete a private repository that people have forked

- All forks of the private repository are deleted with it. (content/pull-requests/reference/forks.md: "A private repository is deleted — Its private forks are also deleted"; content/repositories/creating-and-managing-repositories/deleting-a-repository.md: "Deleting a private repository will delete all forks of the repository". On GitHub Enterprise Cloud and GitHub Enterprise Server the same applies to internal repositories.)
- This is different from a public repository: deleting a public repository does not delete its forks, and an active public fork becomes the new upstream repository of the network. (content/repositories/creating-and-managing-repositories/deleting-a-repository.md; content/pull-requests/reference/forks.md)
- Deleting a repository also permanently deletes its team permissions; this cannot be undone. (content/repositories/creating-and-managing-repositories/deleting-a-repository.md)
- Some deleted repositories can be restored within 90 days of deletion. On GitHub Enterprise Server a site administrator may be able to restore it for you. (content/repositories/creating-and-managing-repositories/deleting-a-repository.md)
- The documentation does not say whether the deleted forks come back when the deleted private repository is restored.
- Local clones are not touched by GitHub; the documentation says, in the access-removal context, that local clones of a private repository are retained. (data/reusables/repositories/deleted_forks_from_private_repositories_warning.md)

## 2. You make a public repository private

- The public forks are not made private. They stay public. (content/pull-requests/reference/forks.md; content/repositories/managing-your-repositorys-settings-and-features/managing-repository-settings/setting-repository-visibility.md)
- GitHub detaches the public forks from your repository and puts them into a new, separate network. (content/repositories/managing-your-repositorys-settings-and-features/managing-repository-settings/setting-repository-visibility.md; content/pull-requests/reference/forks.md)
- The reason given: visibility changes can separate forks into new repository networks so that existing fork owners can keep working without unexpected loss of access. (content/pull-requests/reference/forks.md)
- Practical meaning: the code that was already forked remains publicly available in those forks. Making your repository private does not pull it back.
- Other effects of going from public to private that the documentation lists: stars and watchers of the repository are erased; dependency graph, Dependabot alerts and code scanning availability can be affected. (content/pull-requests/reference/forks.md; content/repositories/managing-your-repositorys-settings-and-features/managing-repository-settings/setting-repository-visibility.md)
- GitHub Enterprise Server only: if the public repository had anonymous Git read access enabled, all its forks lose anonymous Git read access when the repository is made private. (content/pull-requests/reference/forks.md)
- GitHub Free only: a published GitHub Pages site of the repository is automatically unpublished when the repository becomes private. (content/repositories/managing-your-repositorys-settings-and-features/managing-repository-settings/setting-repository-visibility.md)

## 3. You remove a person's access to a private repository

- Any forks that person has of that private repository are deleted. Their local clones are retained. (data/reusables/repositories/deleted_forks_from_private_repositories_warning.md, included in content/pull-requests/reference/forks.md)
- The same is stated for removing a collaborator from a personal-account repository ("If the repository is private and the person has created a fork, then that fork is also deleted") and for removing an outside collaborator from an organization repository. (content/repositories/managing-your-repositorys-settings-and-features/repository-access-and-collaboration/permission-levels-for-a-personal-account-repository.md; content/organizations/managing-user-access-to-your-organizations-repositories/managing-outside-collaborators/removing-an-outside-collaborator-from-an-organization-repository.md)
- Access through teams: if a team's access to the private repository is revoked, or a team with access is deleted, and the team members have no access through another team, their private forks are deleted. (data/reusables/repositories/deleted_forks_from_private_repositories_warning.md)
- You are responsible for making sure that people who lost access delete any confidential information or intellectual property (for example in their local clones). (data/reusables/repositories/deleted_forks_from_private_repositories_warning.md)

Exceptions and special cases the documentation names:

- Forks created in another organization are not deleted when an individual's access to the upstream repository is removed. (content/pull-requests/reference/forks.md, "Important security considerations") When private repositories are forked to other organizations, those organizations control access to the fork network, so a user may keep access to such forks. (content/organizations/managing-membership-in-your-organization/removing-a-member-from-your-organization.md, text for GitHub Free/Pro/Team and GitHub Enterprise Cloud)
- Removing a member from the organization: the removed member loses access to private forks of the organization's private repositories. The member's data is kept for three months; you can restore the private forks they owned of your organization's repositories if the person rejoins (is reinstated) within that time. (content/organizations/managing-membership-in-your-organization/removing-a-member-from-your-organization.md)
- GitHub Enterprise Server with LDAP Sync enabled: if you remove a person from a repository they lose access, but their forks are not deleted. If the person is added to a team with access to the original organization repository within three months, access to the forks is restored on the next sync. (data/reusables/repositories/deleted_forks_from_private_repositories_warning.md)
- Git data from any repository in a network may be accessed from any repository in the same network, even after a fork is deleted. (content/pull-requests/reference/forks.md)

To prevent the problem in future: people with admin permissions to a private repository can disallow forking of it, and organization owners can disallow forking of any private repository in the organization. (data/reusables/repositories/deleted_forks_from_private_repositories_warning.md)
