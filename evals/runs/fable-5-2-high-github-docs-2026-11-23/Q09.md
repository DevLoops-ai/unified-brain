# Running an online shop on GitHub Pages

## Can I run my shop on it?

No. GitHub Pages "is not intended for or allowed to be used as a free web-hosting service to run your online business, e-commerce site, or any other website that is primarily directed at either facilitating commercial transactions or providing commercial software as a service (SaaS)". (content/pages/getting-started-with-github-pages/github-pages-limits.md)

Two more points that matter for a shop:

- GitHub Pages sites should not be used for sensitive transactions such as sending passwords or credit card numbers. (data/reusables/pages/no_sensitive_data_pages.md, included in content/pages/getting-started-with-github-pages/github-pages-limits.md)
- GitHub Pages is a static site hosting service: it takes HTML, CSS and JavaScript files from a repository, optionally runs a build, and publishes the result. (content/pages/getting-started-with-github-pages/what-is-github-pages.md) The documentation describes no server-side part (for example for orders or payments).

What it is meant for: a website about yourself, your organization, or your project. (content/pages/getting-started-with-github-pages/what-is-github-pages.md, intro)

The use of GitHub Pages is also subject to the GitHub Terms of Service. (content/pages/getting-started-with-github-pages/github-pages-limits.md)

## Limits

All from content/pages/getting-started-with-github-pages/github-pages-limits.md, except where noted.

| Limit | Value | Applies to |
|---|---|---|
| Size of the published site | No larger than 1 GB | All products |
| Size of the source repository | Recommended limit of 1 GB | All products |
| Deployment time | A deployment times out if it takes longer than 10 minutes | All products |
| Traffic (bandwidth) | Soft limit of 100 GB per month | GitHub Free/Pro/Team, GitHub Enterprise Cloud |
| Builds | Soft limit of 10 builds per hour | GitHub Free/Pro/Team, GitHub Enterprise Cloud |
| Request rate | Rate limits may apply; a rate-limited request gets HTTP status `429` with an explanatory HTML page | GitHub Free/Pro/Team, GitHub Enterprise Cloud |
| Number of sites | One user or organization site per account; one project site per repository | All products (project-site limit: content/pages/getting-started-with-github-pages/what-is-github-pages.md) |

Notes:

- The limit of 10 builds per hour does not apply if you build and publish the site with a custom GitHub Actions workflow.
- "Soft" limits: if the site goes over these quotas, GitHub may not be able to serve the site, or you may get an email from GitHub Support suggesting ways to reduce the load — putting a third-party content distribution network (CDN) in front of the site, using other GitHub features such as releases, or moving to a different hosting service.
- The documentation gives the bandwidth, build and rate limits only for GitHub.com (GitHub Free/Pro/Team and GitHub Enterprise Cloud); it states no such numbers for GitHub Enterprise Server.

## Publishing from a private repository on the Free plan

No.

- GitHub Pages is available in public repositories with GitHub Free (personal accounts) and GitHub Free for organizations. It is available in public and private repositories with GitHub Pro, GitHub Team, GitHub Enterprise Cloud and GitHub Enterprise Server. (data/reusables/gated-features/pages.md, the `product:` line of content/pages/getting-started-with-github-pages/github-pages-limits.md)
- The plans article says the same: GitHub Free includes "GitHub Pages in public repositories"; GitHub Pages in private repositories is listed under GitHub Pro and GitHub Team. (content/get-started/learning-about-github/githubs-plans.md)
- If you have a Pages site and make its repository private while on GitHub Free, the published site is automatically unpublished. If the site had a custom domain, remove or update the DNS records before you make the repository private, to avoid the risk of a domain takeover. (content/repositories/managing-your-repositorys-settings-and-features/managing-repository-settings/setting-repository-visibility.md)

Also good to know if you move to a paid plan for this:

- A private repository does not make the site private. GitHub Pages sites are publicly available on the internet even if the repository is private (if your plan or organization allows it). (data/reusables/pages/private_pages_are_public_warning.md)
- To publish a site privately (with access control) you need an organization account, and the organization must use GitHub Enterprise Cloud. (data/reusables/pages/privately-publish-ghec-only.md; content/get-started/learning-about-github/githubs-plans.md)
