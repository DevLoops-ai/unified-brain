# REST API requests per hour, by way of authentication

These numbers are the "primary rate limit" on GitHub.com (GitHub Free/Pro/Team and GitHub Enterprise Cloud). For GitHub Enterprise Server see the last section.

| How the script authenticates | Requests per hour | Counted per |
|---|---|---|
| No token | 60 | IP address the request comes from |
| Personal access token | 5,000 | User (your personal limit) |
| `GITHUB_TOKEN` in a workflow | 1,000; or 15,000 for resources that belong to a GitHub Enterprise Cloud account | Repository |
| GitHub App installation (installation access token) | 5,000 minimum, scaling up to 12,500; or 15,000 if installed on a GitHub Enterprise Cloud organization | Installation |

## Details

**No token**

- 60 requests per hour. (data/reusables/rest-api/primary-rate-limit-unauthenticated-users.md, included in content/rest/using-the-rest-api/rate-limits-for-the-rest-api.md)
- Unauthenticated requests are only possible for public data. They are tied to the originating IP address, not to a user or application. (same file) For CI this means the 60 are shared by everything that calls from the same IP address.

**Personal access token**

- 5,000 requests per hour. This is your personal rate limit. (data/reusables/rest-api/primary-rate-limit-authenticated-users.md)
- The limit is shared: requests with your personal access token and requests that a GitHub App or OAuth app makes on your behalf all count towards the same 5,000. (same file)
- If a GitHub App owned by a GitHub Enterprise Cloud organization (or an OAuth app owned or approved by such an organization, of which you are a member) acts on your behalf, those requests have a higher limit of 15,000 per hour. But they also use up the budget of the lower-limit methods: if such an app makes 10,000 requests for you, the 5,000 budget of your personal access tokens is exhausted. (same file)

**`GITHUB_TOKEN` inside a workflow**

- 1,000 requests per hour per repository. (data/reusables/rest-api/primary-rate-limit-github-token-in-actions.md)
- For requests to resources that belong to a GitHub Enterprise Cloud account, the limit is 15,000 requests per hour per repository. (same file)

**GitHub App installation**

- An app that authenticates with an installation access token gets the installation's minimum of 5,000 requests per hour. (data/reusables/rest-api/primary-rate-limit-github-app-installations.md)
- If the installation is on a GitHub Enterprise Cloud organization (the GitHub Enterprise Cloud version of the text adds "or enterprise"), the limit is 15,000 requests per hour. (same file)
- For installations that are not on GitHub Enterprise Cloud the limit scales (same file):
  - more than 20 repositories: another 50 requests per hour for each repository;
  - on an organization with more than 20 users: another 50 requests per hour for each user;
  - the limit cannot go above 12,500 requests per hour.
- This is for installation access tokens. If the app uses a user access token instead, the limit of that user applies (the 5,000 shared personal limit above). (same file)

## Other limits your script can hit

- Some endpoints, such as the search endpoints, have stricter limits. (content/rest/using-the-rest-api/rate-limits-for-the-rest-api.md)
- Secondary rate limits apply on top, for example: no more than 100 concurrent requests; no more than 900 points per minute for REST API endpoints (most `GET`/`HEAD`/`OPTIONS` requests cost 1 point, most `POST`/`PATCH`/`PUT`/`DELETE` requests cost 5); in general no more than 80 content-creating requests per minute and 500 per hour. These can change without notice. (data/reusables/rest-api/secondary-rate-limit-rest-graphql.md)
- Git LFS has a separate bucket: 300 requests per minute unauthenticated, 3,000 per minute authenticated. (content/rest/using-the-rest-api/rate-limits-for-the-rest-api.md)

## Checking and handling the limit in the script

- Every response carries the headers `x-ratelimit-limit`, `x-ratelimit-remaining`, `x-ratelimit-used` and `x-ratelimit-reset` (reset time in UTC epoch seconds). `GET /rate_limit` gives an overview and does not count against the primary limit. If the headers and `GET /rate_limit` disagree, rely on the headers. (content/rest/using-the-rest-api/rate-limits-for-the-rest-api.md)
- When you exceed the primary limit you get a `403` or `429` response and `x-ratelimit-remaining` is `0`. Do not retry before the time in `x-ratelimit-reset`. Continuing to send requests while rate limited may get your integration banned. (same file)
- To get a higher limit: authenticate instead of calling without a token; and for automation in an organization consider a GitHub App instead of a personal access token. (same file)

## GitHub Enterprise Server

The numbers above do not apply by default. Rate limits are disabled by default on GitHub Enterprise Server; your site administrator can set them, so ask the administrator which limits your instance uses. (content/rest/using-the-rest-api/rate-limits-for-the-rest-api.md)
