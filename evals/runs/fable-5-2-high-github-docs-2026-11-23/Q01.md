# Time limits in GitHub Actions

## Short answer

| What | GitHub-hosted runners | Self-hosted runners | Can GitHub Support raise it? |
|---|---|---|---|
| One job (execution time) | 6 hours | 5 days | No |
| Whole workflow run | 35 days | 35 days | No |
| Waiting for a runner | 45 minutes (see below) | 24 hours | No (24-hour limit); not stated for the 45 minutes |

## Details

**How long one job can run**

- On GitHub-hosted runners a job can run for up to 6 hours of execution time. When it reaches the limit, the job is terminated and fails. (content/actions/reference/limits.md)
- On self-hosted runners a job can run for up to 5 days of execution time. When it reaches the limit, the job is terminated and fails. (content/actions/reference/limits.md)
- You can set a shorter limit yourself with `jobs.<job_id>.timeout-minutes`. The default is 360 minutes. If you set a value above the runner's job execution limit, the job is cancelled when the execution limit is reached. (content/actions/reference/workflows-and-actions/workflow-syntax.md)

**How long a whole workflow run can last**

- 35 days per workflow run. When a run reaches this limit, it is cancelled. The 35 days include execution time and also time spent waiting and waiting for approval. (content/actions/reference/limits.md)
- The table does not give a different value for self-hosted runners; the 35-day limit is listed as a general "workflow execution limit". (content/actions/reference/limits.md)
- Related: a workflow can wait up to 30 days for an environment approval. (content/actions/reference/limits.md)

**How long a job can wait for a runner**

- Self-hosted runners: a job can stay in the queue for 24 hours, then it is automatically cancelled. (content/actions/reference/limits.md) The self-hosted runner reference says the same thing in other words: if no online, idle runner matches the job's `runs-on` labels and groups, the job stays queued until a runner comes online, and if it stays queued for more than 24 hours the job fails. (content/actions/reference/runners/self-hosted-runners.md)
- GitHub-hosted runners: the limits table has no "job queue time" row for GitHub-hosted runners. The only statement is in the GitHub-hosted runners article: if a workflow run was queued successfully but has not been processed by a GitHub-hosted runner within 45 minutes, the queued workflow run is discarded. (content/actions/concepts/runners/github-hosted-runners.md)
- Also, if GitHub Actions services are temporarily unavailable, a workflow run is discarded if it has not been queued within 30 minutes of being triggered. (data/reusables/actions/runner-workflow-continuity.md, included in content/actions/concepts/runners/github-hosted-runners.md)

**Is it different on self-hosted runners?**

Yes, for jobs: 5 days instead of 6 hours of execution time, and a 24-hour queue limit. (content/actions/reference/limits.md)

One thing to watch on self-hosted runners: the `GITHUB_TOKEN` expires when the job finishes or after at most 24 hours. A self-hosted job may run for 5 days, but the token can only be refreshed for up to 24 hours. For jobs longer than 24 hours, use a personal access token or another authentication method. On GitHub-hosted runners the token lives at most 6 hours, the same as the job. (content/actions/concepts/security/github_token.md; data/reusables/actions/github-token-expiration.md; content/actions/reference/workflows-and-actions/workflow-syntax.md)

**Can GitHub Support raise these limits?**

No. In the limits table the column "Can GitHub Support increase?" says "No" for all four: workflow run time (35 days), GitHub-hosted job execution time (6 hours), self-hosted job execution time (5 days) and self-hosted job queue time (24 hours). (content/actions/reference/limits.md)

Limits that Support can raise by support ticket are other ones, for example job concurrency on GitHub-hosted runners, the number of re-runs (50), and the workflow trigger event rate limit. (content/actions/reference/limits.md)

The documentation does not say whether the 45-minute discard time for GitHub-hosted runners can be changed.

Note: the article states that these limits are subject to change. (content/actions/reference/limits.md)
